## 1. What I implemented

**Normalization** (`web-crawler-connector.ts:604-641`): `normalizeCrawlUrl` now lowercases the host, strips the seven tracking params, and removes a trailing slash on non-root paths, on top of the existing hash and default-port stripping.

One non-obvious choice: tracking params are dropped by filtering the raw query string rather than via `URLSearchParams`, which re-serializes and would rewrite `[expr]` to `[expr]` on surviving params — changing URLs the task didn't ask to change.

**A required companion fix** (`web-crawler-connector.ts:465-478`): `buildAllowedPathPrefixes` derived the crawl scope from the *normalized* start URL. Once trailing slashes are stripped, a `https://host/docs/` start URL becomes `/docs`, which falls into the `lastIndexOf(…)` branch and yields prefix `/` — silently widening the crawl from one directory to the entire origin. It now reads `config.startUrl`, where the trailing slash still carries its meaning. Behavior is identical to today for every config shape (directory, file, root).

## 2. The already-indexed-documents requirement

`buildDocument` derives the document id as `sha256(…)` (`:449`), and that value is persisted as `kb_documents.source_id` (`connector-sync.ts:504`), which is unique per connector (`kb-document.ts:44`). Sync finds an existing document only by `[expr]` (`connector-sync.ts:419-421`) and has **no prune step** — so a changed derivation inserts a second row and kb search returns the page twice, from the new row and the stale one.

Identity change is unavoidable here: it's a pure function of the normalized URL. So I added a data migration, `0313_rekey_web_crawler_source_ids.sql`, following the `0131_fix_agent_tool_trailing_underscores` precedent. It works because `source_url` stores the same URL in plain text (`connector-sync.ts:509`), and the new rules are a superset of the old ones acting on independent URL components — so `new(…)`. I verified that property explicitly. `kb_documents.id` is untouched, so chunks and embeddings are kept and each document keeps serving continuously; no deletes, no re-embedding.

The migration is deliberately non-destructive: it re-keys only rows that can move without colliding, leaving anything ambiguous exactly as it behaves today.
