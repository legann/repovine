## Files changed

| File | Why |
|---|---|
| `web-crawler-connector.ts` | The normalization itself |
| `0313_renormalize_web_crawler_source_ids.sql` (new) | Re-keys already-indexed documents onto the new derivation |
| `meta/_journal.json`, `meta/0313_snapshot.json` (new) | Drizzle migration registration (hand-authored — see risk 2) |

**Connector.** `normalizeCrawlUrl` (`web-crawler-connector.ts:608`) now lowercases the host, strips the seven tracking params, and keeps the existing hash/default-port handling. Trailing-slash folding lives in a new `normalizeDocumentUrl` (`:630`) that `normalizeCanonicalUrl` calls (`:595-604`), so it reaches document identity via `buildDocument` (`:456`, `:460`) without touching what the crawler fetches.

That split is deliberate. `normalizeCrawlUrl` also normalizes request targets and crawl scope: `createCrawler` feeds its output straight to `buildAllowedPathPrefixes` (`:193-194`, also `:359`), which branches on `path.endsWith(…)` at `:480`. Folding the slash there turns a `/docs/` start URL into `/docs`, and the default allowed prefix silently widens from `/docs/` to `/`. It would also request `/docs` from servers that only serve `/docs/`. Tracking-param stripping is safe at that layer and dedupes the crawl frontier too.

**Migration.** `kb_documents.source_id` is `sha256(…)`, written once at ingest and never re-derived, and connector-sync has no prune (`connector-sync.ts:419-421`, `:504`). Without a re-key, the first sync after this change inserts a second row per moved page and search returns it twice. Statement 1 deletes rows the new normalization collapses onto a survivor (chunks cascade via `kb-chunk.ts:44`); statement 2 re-keys the rest. It mirrors the TS textually — including rewriting the query string only when a tracking param is present, since `URLSearchParams` would rewrite `[expr]` to `[expr]` in surviving params and diverge from the connector. Only rows where `[expr]` are touched.
