## One deliberate deviation, and why

The strengthened rules govern **page identity/dedup**; they do not rewrite the URL that gets requested and stored. Two independent reasons:

1. **`/a` and `/a/` are distinct HTTP resources.** Rewriting the request would 404 on any site that serves only the slashed form. The existing test server is exactly such a site (`web-crawler-connector.test.ts:722-739` routes are keyed `/docs/`), so stripping the slash inside `normalizeCrawlUrl` would break the fetch path itself — it feeds `crawler.run()` at line 120/161.
2. **The stored URL *is* the document's primary key.** `buildDocument` hashes it into `id` (`web-crawler-connector.ts:465-467`), which becomes `kb_documents.source_id` (`connector-sync.ts:504`) — the sole sync dedup key (`connector-sync.ts:419-421`, unique on `[expr]` per `database/schemas/kb-document.ts:44`). Repointing it would strand every already-indexed row: the sync path has **no** stale-row pruning (only whole-connector/whole-org deletes exist — `[expr]`; `deleteByConnectorAndSourceId:332` has zero callers). Stranded rows keep being retrieved (`query.ts:265` serves `sourceUrl` off the row) while never being refreshed again — permanent stale duplicates.

Because `sourceUrl`, `metadata.url`, and `id` are byte-identical to before, `contentHash` is unchanged too (`connector-sync.ts:405-416`) — the first sync after deploy re-ingests nothing and re-embeds nothing. The existing suite corroborates this boundary: `web-crawler-connector.test.ts:178-179` pins `[expr]`, and `:163-166`, `:271`, `:317-318`, `:667-668` pin trailing-slash document URLs.

If you'd rather have the tracking params also stripped from stored URLs, that's a one-line swap (use `canonicalPageKey` where `normalizeCrawlUrl` feeds `buildDocument`) **plus** a `source_id` backfill — note `UpdateKbDocumentSchema` deliberately omits `sourceId` (`types/kb-document.ts:64-73`), so the rename isn't currently expressible through the model.
