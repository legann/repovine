## What changed and why

**`platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts`**

1. `TRACKING_QUERY_PARAMS` (new constant) — the seven named parameters; `isTrackingQueryParam` also matches any `utm_`-prefixed key.
2. `crawlPageIdentity(…)` (new) — builds a page-identity string on top of `normalizeCrawlUrl`: strips tracking parameters, sorts the remaining ones, lowercases the host, drops a trailing slash on non-root paths, and inherits the existing fragment + default-port stripping.
3. `buildStartRequest(…)` (new) — replaces the bare start-URL string at both `crawler.run(…)` call sites (`testConnection`, `sync`) with `[expr]`, so a link back to the start page shares its identity.
4. `enqueueAllowedLinks` — adds `transformRequestFunction` setting each discovered request's `uniqueKey` to its page identity.

The stronger rules are applied to the request **unique key**, not to the URL that gets fetched or stored. Crawlee's request queue de-duplicates on `uniqueKey` (verified in `@crawlee/core` `storages/request_provider.js:303` and `@crawlee/memory-storage` `resource-clients/request-queue.js:526`), so variants collapse to one visit and therefore one document, while each request still fetches the URL as authored.

**`docs/pages/platform-knowledge-connectors.md`** — two sentences in the Web Crawler section stating the de-duplication rules, plus a `lastUpdated` bump (matching the convention in the page's last four commits).

## Behavior, and residual risk

Trivially-different links to one page — tracking tags, reordered parameters, host case, non-root trailing slash — now produce a single fetch and a single document. Previously only the `utm_`-prefixed subset collapsed, via Crawlee's default key; `gclid`/`fbclid` did not. I verified the new key against the extracted `@apify/utilities` `normalizeUrl` over a probe matrix: every pair the default key collapsed still collapses (no de-dup regression), plus the tracker cases that leaked before.

Residual risk:

- **`sourceUrl` is not canonicalized.** If a page is first reached through a tracking URL, that URL remains its `sourceUrl` and its id, and pages already indexed that way keep it. Making `sourceUrl` canonical re-keys `source_id`, which the invariant rules out; doing it safely needs an adoption path in the ingest layer (match the stored `source_url`, re-key the row) — a cross-cutting change to all 16 connectors, so I left it out.
- **Which variant wins is link-order dependent** — the first URL enqueued for an identity is the one fetched. Order is stable for a stable site; a site that reorders its links could shift a document's `sourceUrl`/id and create one duplicate row.
- **Unverified by execution.** `pnpm` is shimmed to refuse installs in this worktree, so I could not run the 24 existing tests or `type-check`. I compensated by executing the extracted key function under plain Node, and by checking every Crawlee contract against the published 3.14.1 tarballs: `RequestOptions.uniqueKey`, `[expr]` (so `run(…)` typechecks), `[expr]`, `transformRequestFunction` in the `ow` shape and applied before `[expr]`, and the default-strategy pattern objects carrying only `glob` (so the merge in `createRequests` cannot overwrite `uniqueKey`). The pinned expectations in `web-crawler-connector.test.ts:163-180` (`sourceUrl`, `metadata.url`, `id`) are unaffected by design.
