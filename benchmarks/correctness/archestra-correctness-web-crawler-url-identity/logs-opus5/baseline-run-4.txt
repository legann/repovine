## Deliberately unchanged

- **Request URLs.** `crawler.run(…)` (`[expr]`) and discovered links (`:593`) still fetch the URL as the site links it. A server decides whether `/docs` and `/docs/` are the same resource; the test fixture is exactly such a server — `web-crawler-connector.test.ts:723-731` matches `[expr]` exactly and 404s otherwise — and `:547-549` pins the title fallback to the *fetched* URL.
- **Crawl scope and exclude patterns.** `isPathInScope` still matches user regexes against the linked `[expr]` (`web-crawler-connector.ts:569-571`), documented that way in `docs/pages/platform-knowledge-connectors.md:327`. Canonicalizing that input would silently change existing configs.
- **Other connectors' identities.** `previousIds` is optional and the loop reads `[expr]` (`connector-sync.ts:552`), so e.g. Asana's stable ids (`asana/asana-connector.ts:23`) behave exactly as before.
- **No data migration.** Re-keying `source_id` in SQL would break old pods mid-rollout — the expand/contract rule in `drizzle-migration-linter/README.md:88-98` — and would need the normalization reimplemented in SQL. Sync-time adoption reuses the real code path instead.
- **Stale-document pruning.** Sync never deletes vanished documents; `KbDocumentModel.deleteByConnectorAndSourceId` (`models/kb-document.ts:332`) has no production caller and full cleanup is force-resync (`routes/knowledge-base.ts:1038-1092`).
