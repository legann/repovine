## Why the new rules key the crawl frontier and not the stored URL

`normalizeCrawlUrl`'s output is not just an identifier — it is the URL fetched over the wire (`crawler.run(…)` at :131, :172; discovered links at :589) **and** the string hashed into `ConnectorDocument.id` (:459) and stored as `sourceUrl`/`metadata.url`. Applying the new rules there breaks two things:

1. **Fetching.** Requesting `/docs` when the site serves `/docs/` is a different HTTP request. The in-repo test server routes by exact pathname (`web-crawler-connector.test.ts:722-731`), so stripped start URLs 404.
2. **Already-indexed documents.** That id becomes `kb_documents.source_id`, the only key a later sync uses to find an existing row (`connector-sync.ts:419-422`, `:504`). Re-keying makes every indexed page look new: `ingestDocument` inserts a duplicate while the original is never matched again. Nothing prunes it — the only document deletes are connector deletion (`routes/knowledge-base.ts:1074`) and `deleteByConnectorAndSourceId` (`models/kb-document.ts:332`), which has no sync-time caller. The orphan stays searchable with content frozen at its last sync.

Keying the frontier instead delivers the dedup with byte-identical document ids and source URLs.

## Behavior delta and residual risk

`[expr]`/`[expr]` variants are the concrete fix: Crawlee's default request key only strips `utm_`-prefixed params (`@apify/utilities.normalizeUrl`), so those variants are fetched twice today and, absent a `[expr]`, produce two identical documents. Trailing-slash and `[expr]` dedup already happened incidentally inside Crawlee's key; the connector now owns that semantic rather than inheriting it from a transitive dependency. My filter is purely additive — Crawlee's own dedup remains as a second layer, so no existing collapse (e.g. query-param ordering) is lost.

Residual risk:
- A site serving genuinely different content at `/a` and `/a/`, or varying content by tracking parameter, is now indexed once. This matches standard crawler behavior and is the requested trade.
- Which variant wins is crawl-order dependent, so a page first reached through a tracking URL is stored under that URL. Unchanged from today, and cleaning it up would require the re-keying this change avoids.
- `seenPageKeys` lives per crawler instance (`:202`), so it resets each sync — correct, since each sync rebuilds the frontier.
- Untested by execution: `pnpm test`, `pnpm lint`, `pnpm type-check` need running in a bootstrapped checkout. The change adds no imports or exports (no knip impact) and all new symbols are module-internal.
