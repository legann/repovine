The strengthened normalization is a **crawl-frontier key**, not a rewrite of the URL that gets fetched or stored. That split is what keeps already-indexed documents intact:

- `buildDocument` hashes the page's own canonical URL for the document id (`:462-467`), and `connector-sync.ts:419-422` looks documents up by exactly that id. Rewriting the canonical URL would re-key every affected row — `connector-sync.ts` has no prune pass, so old rows would linger as stale duplicates alongside new ones. `sourceUrl`, `metadata.url`, and ids are byte-identical to before.
- Requests keep the form a link actually used. Servers do distinguish `/docs` from `/docs/` — the existing suite's own fixture proves it (`web-crawler-connector.test.ts:722-731` routes on exact `pathname` with routes like `"/docs/"`), so fetching a synthesized slash-stripped URL would 404.
- Host lowercasing needs no code: WHATWG parsing folds it for http(s), and every URL enters through `new URL` (`normalizeCrawlUrl` at `:615`). Verified: `[expr]`. Default-port stripping is inherited by building the key on `normalizeCrawlUrl`.

## Residual risk

- **Not bootstrapped.** `platform/node_modules` is absent and the `pnpm` shim exits 127, so I could not run `vitest`, `tsc`, or `biome`. I validated the normalization logic by replicating the three helpers in Node and asserting fold/distinct/claim-order tables plus every URL the existing suite uses (all pass), and verified the wiring by reading. Unrun: the real crawl path.
- **First-variant-wins fetch.** If a broken variant is discovered before a working one (`/a` 404s, `/a/` works), the page is now missed where two fetches previously succeeded. Inherent to URL dedup; mitigated by only ever requesting URLs that appeared as real links.
- **Pre-existing rows for now-folded variants.** A site that previously produced two rows for `/a` and `/a/` keeps both; the survivor refreshes, the loser goes stale. Nothing in `connector-sync.ts` deletes documents that stop appearing, so pruning would be a separate change.
- **Cross-sync variant flap.** Identity still tracks whichever variant is discovered first, so a site that reshuffles its links can shift a page's id. Unchanged from today's behavior, not introduced here.
- `enqueueLinks` retains its own dedup as a second layer; this filter runs ahead of it and is authoritative for variant folding.
