## What I changed

**1. `platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts`**

`normalizeCrawlUrl` (:605) now lowercases the host, strips the seven tracking params, and drops a trailing slash on non-root paths, keeping the default-port branch.

Two details worth flagging:
- Tracking params are removed by filtering **raw `[expr]` tokens**, not via `url.searchParams.delete()`. `searchParams` re-serializes *every* surviving pair on mutation, which would rewrite percent-encoding and change the identity of URLs carrying no tracking param at all. Verified: `[expr]` survives byte-identical.
- `buildAllowedPathPrefixes` (:471) now reads `config.startUrl` instead of the normalized URL. This is a regression the task's change introduces: the trailing slash is what distinguishes "crawl this directory" from "crawl this page's directory", and normalization destroys it. I reproduced it — a `https://example.com/docs/` connector would have silently widened from `/docs/` to the **entire origin**.

**2. `.../migrations/0313_renormalize_web_crawler_source_ids.sql`** (new, + `meta/0313_snapshot.json`, `meta/_journal.json`)

Required by "every document already indexed must continue to be served correctly". `[expr]` persists `sha256(…)` as `kb_documents.source_id`; `kb-document.ts:44` makes `[expr]` unique; and `connector-sync.ts:499-512` inserts a **new row** on any unmatched `source_id` with no prune step. So without a backfill the first sync duplicates every affected page and search returns both copies. The migration re-keys existing rows, deleting rows that collapse onto one identity (chunks cascade).
