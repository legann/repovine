## What changed

**1. `platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts`**

`normalizeCrawlUrl` (:603) now strips the seven tracking params, removes trailing slashes on non-root paths, lowercases the host, and keeps the existing default-port stripping. Two details are deliberate:

- The query is only rewritten when a tracking param is actually present. Assigning `url.search` re-serializes the whole query string (`[expr]`→`[expr]`), which would silently change the identity of every URL carrying none. Splitting the raw query preserves the encoding and order of surviving params.
- Every step is idempotent (`/a//` → `/a`, not `/a/`). That is what makes the re-key safe — see below.

`buildAllowedPathPrefixes` (:465) now reads `config.startUrl` instead of its normalized form. This was a real regression I hit: with the slash stripped, a start URL of `https://site.com/docs/` derived scope `[expr]` instead of `[expr]`, silently widening the crawl to the whole origin. Simulated across start URLs and links: **0 scope decisions changed** after the fix.

**2. `platform/backend/src/database/migrations/0313_rekey_web_crawler_document_source_ids.sql`** (new), plus the `meta/_journal.json` append and `meta/0313_snapshot.json` chain entry.

This is the part the task's "must continue to be served correctly" hinges on. `kb_documents.source_id` is the *persisted* form of this normalization (`buildDocument` :447 hashes it; `connector-sync.ts:504` stores it), written once and never re-derived, under a unique `[expr]` index (`kb-document.ts:44`). `connector-sync.ts:419` looks documents up by that key and there is no prune step — so without a re-key the very first sync after this change inserts a *second* row for every affected page and kb search returns both. The migration re-derives the identity from `source_url` (the exact string the old normalization hashed), merges collisions keeping the freshest row, and updates the served `source_url`.

## Residual risk

1. **The biggest one: this changes what gets *fetched*, not just what gets stored.** The crawler now requests `/docs` where it used to request `/docs/`. Most servers 301 to the slash form and the redirect handler follows same-origin in-scope redirects (:236–255), so it recovers — but a server that 404s the slash-less form will stop re-fetching. Existing rows stay served (no prune); content goes stale. If you want to avoid this, the follow-up is to split the *fetch* URL from the *identity* URL; I did not do that unilaterally since it's a design change beyond the ask.
2. **Existing tests will fail, and I left them alone per your constraint.** `web-crawler-connector.test.ts:163`, `:271`, `:291`, `:317-318` pin the old trailing-slash URLs, and `createTestSite` routes by exact pathname with only `/docs/`-style routes registered — so those crawls now 404 rather than merely returning different strings. These need fixture routes plus updated expectations.
3. Migration SQL was validated on Postgres 16; the backend suite runs migrations on PGlite. Same major and all functions used are core (`sha256`, `convert_to`, `string_to_array`, `WITH ORDINALITY`), but installs are blocked in this worktree so I could not execute it there.
4. Exclude patterns anchored on a trailing slash (e.g. `/private/$`) no longer match, since canonical paths no longer end in `/`.
5. The merge **deletes** least-recently-updated duplicate rows (chunks cascade). Intentional, but it is data removal.
6. `metadata.url` and `content_hash` are not rewritten; because metadata feeds the hash, the next sync detects the change and repairs both.
