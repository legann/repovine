### Three decisions worth flagging

**Host lowercasing needs no code.** The WHATWG parser already does it: `[expr]` → `https://example.com/Path`. Same for default ports — `http://example.com:80/a` parses to `http://example.com/a`, so the existing block at `:615-620` is already a no-op. I kept it as instructed and recorded the parser's guarantees in a comment instead of adding dead code.

**Tracking params are filtered as raw text, not via `URLSearchParams`.** `searchParams.delete()` re-serializes the whole query *even when the param is absent* — I measured `[expr]` → `[expr]`. Going through it would have changed the identity of pages carrying no tracking param at all.

**Fetch URL and identity URL are now separate.** Stripping the trailing slash inside `normalizeCrawlUrl` changes what gets *requested*, and `createTestSite` matches paths exactly (`[expr]`, test:725) with ~14 tests registering `"/docs/"` — those would 404. It's also riskier in production, depending on server redirects. `buildDocument` already models this split (`url` vs `fetchedUrl`, `:462-463`), so canonicalization goes on the identity path. All four requested rules still apply to identity.

## 2. Why the migration exists

`normalizeCrawlUrl`'s output is hashed into `kb_documents.source_id` — persisted once, never re-derived:

- `connector-sync.ts:419-422` matches existing documents by `findBySourceId(…)`
- `connector-sync.ts:504` writes `sourceId: doc.id` on insert
- `kb-document.ts:44-47` — unique index on `[expr]`
- No prune step: the only delete in `connector-sync.ts` is `KbChunkModel.deleteByDocument` at `:479`

So the first sync after this change would insert a second row per re-keyed page, and search would return it twice, permanently. The migration re-keys in place — the PK is untouched, so chunks, embeddings and search vectors keep serving without re-indexing. It's safe because `[expr]` and `source_url` is plain text; rows failing that check are skipped.
