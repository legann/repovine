## What I changed

**1. `platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts`**

Normalization now runs on two axes, because the existing `normalizeCrawlUrl` served two different jobs:

| Function | Used for | Rules |
|---|---|---|
| `normalizeCrawlUrl` (`617`) | URLs fetched, enqueued, scope-checked | fragment, default port, **tracking params**, **lowercase host**; path preserved |
| `canonicalizeDocumentUrl` (`637`) | document identity | all of the above **+ trailing-slash folding on non-root paths** |

`normalizeCanonicalUrl` (`596-605`) — the path feeding `buildDocument` — now uses the canonicalizing variant, so identity is where slash-folding lands. `TRACKING_QUERY_PARAMS` (`52`) holds the seven listed params. Nothing new is exported (keeps `knip --production` green).

Two deliberate details: host lowercasing is explicit but a **no-op** — WHATWG `URL` already lowercases the host during parsing, which I verified; and `stripTrackingParams` (`654`) rebuilds the query only when a tracking param is actually present, because `URLSearchParams` re-serializes everything it touches (`[expr]` → `[expr]`) and would otherwise change the identity of untracked URLs for no reason.

**2. `platform/backend/src/database/migrations/0313_recanonicalize_web_crawler_source_ids.sql` (new) + `meta/_journal.json`**

This is the "already-indexed documents must still be served" requirement. The repovine annotation on this module carried a consumer-scoped risk, and I verified every claim in code:

- `buildDocument` hashes the canonical URL into the document id (`web-crawler-connector.ts:456`)
- connector-sync persists it as `source_id` and matches on it (`connector-sync.ts:421`, `:504`)
- unique index on `[expr]` (`kb-document.ts:44-47`)
- **no prune** — the only delete is chunk-level for an existing row (`connector-sync.ts:479`)

So without re-keying, the first sync after this change inserts a second row per affected page while the stale row keeps its chunks, and kb search returns the page twice — permanently, since `source_id` is written once and never re-derived. The migration re-derives from `source_url`, collapses rows that fold to one canonical URL (chunks cascade via `kb-chunk.ts:44`), then re-keys survivors and syncs `source_url`/`metadata.url`. It's scoped to rows whose `source_id` equals `sha256(…)` — the connector's own derivation — and the transform is idempotent, so re-running is a no-op.

Since the annotation warned this exact class of bug is a SQL/TS normalization mismatch (precedent: `0131_fix_agent_tool_trailing_underscores`), I ported the SQL's expressions to JS and diffed them against the TS canonicalizer over 25 stored-URL shapes — IPv6 hosts, userinfo, percent-encoding, non-default ports, `[expr]`, `[expr]`, case-sensitivity, tracking names appearing inside values. All agree. I also removed the one PG-specific escaping dependency (regex backreferences, which have no precedent in this repo's migrations) in favor of a guarded `RTRIM`.

## Deliberately left unchanged

- **Fetch/enqueue/scope axis keeps the trailing slash.** `createCrawler:194-198` feeds the normalized start URL into `buildAllowedPathPrefixes`, which derives default scope from that slash (`472-485`: `[expr]`). Folding it there turns `/docs/` into prefix `/`, silently widening the crawl from the configured subtree to the whole host, and loosening the `beforeRedirect` containment check (`238-249`). It would also make the crawler request a URL the origin may not serve.
- **`connector-sync.ts`** — connector-agnostic; it just persists `doc.id` (`:421`, `:504`), so identity policy belongs to the connector. Changing it would touch all ~20 connectors.
- **Other connectors** — both normalizers are module-private (only `WebCrawlerConnector` is exported, `:73`) and the migration filters `[expr]` (`0313:37`).
- **`query.ts:267`** — read path returns the stored `sourceId` verbatim; no derivation to update.
