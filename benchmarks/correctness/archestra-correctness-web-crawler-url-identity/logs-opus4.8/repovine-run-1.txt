## What I changed and why

Two files, one behavior change plus the data-consistency work it requires.

**1. `platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts`**
- **Strengthened `normalizeCrawlUrl`** (now exported): drops the fragment (existing), **lowercases the host**, **strips tracking params** (`utm_source/medium/campaign/term/content`, `gclid`, `fbclid` via a new `TRACKING_QUERY_PARAMS` constant), keeps **default-port stripping** (existing), and **trims a trailing slash on non-root paths**. Exported so the re-key (below) reuses the identical function.
- **Fixed `buildAllowedPathPrefixes`** to derive the default crawl scope from `config.startUrl` instead of the normalized start URL. Without this, trimming the trailing slash would silently widen a directory start URL (`[expr]` → prefix `/docs/`) to the whole origin (`/`). This is a required correction *caused by* the normalization change, not optional.

**2. `platform/backend/src/database/seed.ts`**
- Added **`renormalizeWebCrawlerDocumentIdentities`**, wired into `seedRequiredStartingData` (fail-soft via `.catch`, matching the repo's startup-task pattern at `server.ts:960/996/1003`). It re-keys already-stored `web_crawler` `kb_documents` to the new normalization: for each connector (own transaction) it recomputes `[expr]`, updates `source_id`+`source_url`, and merges collisions (two stored URLs collapsing to one) by keeping the freshest row and deleting the rest.

**Why the re-key is mandatory (not optional):** the normalized URL *is* the document identity — `buildDocument` hashes it into `kb_documents.source_id` (`connector-sync.ts:504`), incremental sync matches by `[expr]` (`connector-sync.ts:419-422`), and there is **no prune step** (`connector-sync.ts:393-532`). Changing the normalizer without re-keying means the first post-deploy sync inserts a *new* row per already-indexed page and orphans the old one — search returns the page twice. Doing it in TS (reusing the normalizer) rather than SQL avoids the SQL/TS normalization divergence that migration `0131` had to repair.

## Summary, files, and residual risk

**Behavior:** trivially-different URLs for the same page now canonicalize to one identity (tracking params, trailing slash, host case, default port). Verified empirically with Node — all required transforms correct, exact-key param matching (no `utm_source_id` false positive), **idempotent**, and `newNorm(…)` (so re-keyed rows match what a future crawl produces). Every already-indexed document remains served exactly once: startup re-key aligns stored `source_id`s before any sync, so sync updates in place instead of duplicating.

**Files touched:** the connector (normalizer + scope fix) and `seed.ts` (startup re-key). No tests added/modified (per constraints).

**Residual risk:**
- **`metadata.url` staleness** — the re-key updates `source_url` (the primary citation field search returns) but not the mirror in `kb_documents.metadata.url`; for pages whose content doesn't change on the next sync, that mirror keeps the old form until a content change rewrites metadata (`connector-sync.ts:468-476`). Cosmetic.
- **Startup cost** — loads a connector's documents into memory per transaction (bounded by `maxPages`), and runs every boot (idempotent no-op after the first pass), consistent with existing `seed.ts` reconciliations.
- **Fail-soft trade-off** — a persistent error on one connector aborts that boot's remaining connectors; retried (idempotent) next boot. Log counts are best-effort (a transaction retry can slightly inflate them); DB state stays correct.
- **Query re-serialization** — stripping params via `URLSearchParams` canonicalizes query encoding (e.g. `[expr]`→`[expr]`) even without tracking params, so such pages are also re-keyed; benign, and re-key + crawler use the same function so no duplication results.
- **Could not run `tsc`/`biome`** here (`node_modules` absent). Types were hand-verified against the schema/model types and formatting against biome's rules; recommend `pnpm --dir backend type-check` + `biome check` before merge.
