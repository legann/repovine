## What I changed and why

The task's four normalization items split cleanly by risk. Three were already applied in the working tree (uncommitted) and are safe; one conflicts with the frozen test oracle; and the "served correctly" clause is the real hidden work.

**Committed baseline** (`HEAD`) had a minimal `normalizeCrawlUrl` (hash + default-port strip only). The **working tree** already added host-lowercasing and tracking-param stripping. I kept those and added the persistence reconciliation the annotation flagged.

| File | Change | Why |
|---|---|---|
| `web-crawler-connector.ts` | Export `normalizeCrawlUrl`; add + export `deriveWebCrawlerDocumentId`; `buildDocument` reuses it | Make the identity derivation (`sha256(…)`) one shared function so the connector and the backfill can never diverge |
| `models/kb-document.ts` | Add `findIdentitiesByConnectorType` + `reindexSourceIdentity` | Models-only DB access; `reindexSourceIdentity` can rewrite `source_id`, which the schema-restricted `update()` cannot |
| `database/seed.ts` | Add idempotent `renormalizeWebCrawlerDocumentIdentities()`, called from `seedRequiredStartingData()` | Re-key already-stored identities onto the new normalization at startup, before the next sync |

**Why the backfill is required (the annotation's core point):** `kb_documents.source_id` = `sha256(…)`, persisted once and never re-derived (`[expr]`), and connector-sync has no prune step. Changing the normalizer changes the hash, so the next sync inserts a *second* row for an unchanged page (`findBySourceId` misses → `create`), and full-text search returns both (`kb-chunk.ts:171` joins every row's chunks). The backfill recomputes each `web_crawler` document's identity through the *same* `normalizeCrawlUrl`, rewrites rows in place, and drops rows that now collapse onto an identity another row already holds (chunks cascade via `kb-chunk.ts:44`; the page stays served by the survivor). It is idempotent and provably collision-safe: a normalized URL is a fixed point, so any row occupying a survivor's target slot would itself be canonical and win that slot, making the mover a deleted duplicate instead.

**Why `seed.ts` and not a SQL migration:** the established path the annotation cites (0131) was a trivial `REGEXP_REPLACE` on plaintext. Here the identity is a **hash of a WHATWG-normalized URL**, and `url.searchParams.delete()` re-serializes the query as `application/x-www-form-urlencoded` (`b c`→`[expr]`). SQL regex cannot reproduce that, so a SQL re-key would silently mis-key exactly the tracking-param rows — re-introducing the SQL/TS mismatch class 0131 existed to fix. `seed.ts` already hosts startup data-migrations that reuse app logic SQL can't express (`migrateSecretsToEncrypted`, `seed.ts:739`); reusing the TS normalizer there is the only faithful option.

## Summary

**Behavior:** crawled URLs now canonicalize by lowercasing host, stripping default ports, and dropping tracking params (`[expr]`, `gclid`, `fbclid`) — so trivially-different URLs collapse to one document. A startup backfill brings every already-indexed `web_crawler` document's stored identity onto the current normalization, so no page is duplicated in search after the change. Trailing-slash stripping is intentionally not applied (frozen-test conflict, cited above).

**Files:** connector (share the id derivation, export the normalizer), `kb-document` model (two identity methods), `seed.ts` (the re-key backfill). No schema/migration change — only existing columns are touched.

**Verification:** `tsgo` type-check ✓, Biome ✓, knip dev+production ✓, and the three directly-affected suites (`web-crawler-connector`, `kb-document`, `seed`) = 68 tests ✓. The connector suite passing confirms the trailing-slash contract is preserved.

**Residual risk:**
- Re-keyed rows re-embed once on the next sync (stale `contentHash`) — a one-time cost, not a correctness issue.
- The backfill loads all `web_crawler` identity rows into memory (bounded per connector; consistent with `migrateSecretsToEncrypted`). It runs per-op via models rather than in one transaction; crash-safety rests on idempotency, not atomicity.
- I ran the directly-affected suites, not the full 400+ backend suite; changes are additive and localized, but I did not exhaustively prove no unrelated integration test asserts on `seedRequiredStartingData`'s effects.
- The requested trailing-slash normalization is unimplemented pending resolution of the test conflict.
