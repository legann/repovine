## Summary

Strengthened the web crawler's URL normalization and reconciled the already-stored document identities that depend on it.

### 1. Files changed and why

| File | Change | Why |
|---|---|---|
| `platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts` | Rewrote `normalizeCrawlUrl`; added `TRACKING_QUERY_PARAMS` const + `stripTrackingQueryParams` helper | Canonicalizes trivially-different URLs to one identity |
| `platform/backend/src/database/migrations/0313_normalize_web_crawler_tracking_params.sql` | New data migration | Re-keys already-indexed documents so the identity change doesn't duplicate them |
| `platform/backend/src/database/migrations/meta/_journal.json` | Appended entry idx 313 | Registers the migration (Drizzle can't run `generate` here — no `node_modules`) |

**Normalizer** (`normalizeCrawlUrl`): now, in addition to the existing hash strip + default-port strip, it (a) lowercases the host and (b) strips tracking query params `[expr]` (case-insensitive key match). Tracking params are removed by filtering the raw query text rather than round-tripping through `URLSearchParams`, so retained params keep their exact order and byte encoding — which keeps the derived `source_id` deterministic **and** lets the SQL migration reproduce the same canonical URL.

**Why the migration is required, not optional.** `normalizeCrawlUrl` is the document's identity chokepoint (repovine annotation on the module): `connector-sync.ts:ingestDocument` persists its output as `[expr]` with `source_url` = that URL, looks documents up by `[expr]`, and **never prunes**. So a normalization change alone would, on the first sync, re-key every affected page to a new `source_id`, insert a second row, and make search return both. The migration strips tracking params from stored `source_url`s textually (identical algorithm to the TS), recomputes `source_id`, and collapses rows that now share an identity (keeping the canonical/freshest; `kb_chunks` cascade on delete). It's scoped to `web_crawler` connectors and only touches rows whose URL actually changed. Same shape as the cited precedent `0131_fix_agent_tool_trailing_underscores` (journal entry + `.sql`, no snapshot).
