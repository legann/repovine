## Summary

The web crawler stored each page's identity as `sha256(…)` in `kb_documents.source_id`, written once at ingest and matched by `[expr]` with **no prune step**. Strengthening the normalizer alone would therefore re-key every affected page on the next sync — inserting a duplicate row while the old row keeps serving stale content (exactly the risk the module annotation flags). So the change is two parts: the normalizer, and a data migration that brings the already-stored identities into line.

### Behavior change

**Normalization split across two layers, by design:**

- `normalizeCrawlUrl` (fetch + scope + identity base) now also: lowercases the host (explicit; WHATWG already does this for http/https) and strips `utm_source/utm_medium/utm_campaign/utm_term/utm_content/gclid/fbclid`. Default-port and fragment stripping are kept. These are **fetch-safe** (servers ignore tracking params; host is case-insensitive).
- **Trailing-slash removal is applied to the document identity only** (`normalizeCanonicalUrl` → new `stripIdentityTrailingSlash`), not to the URLs the crawler fetches. `/a/` and `/a` can be different resources on the origin, so the crawler still fetches the path as written while `/a/` and `/a` canonicalize to one stored document. This also keeps `buildAllowedPathPrefixes` directory-scoping intact.

Net effect: trivially-different URLs (`/a` vs `/a/`, `[expr]`/`gclid`/`fbclid` variants, mixed-case host, default ports) now collapse to one `kb_documents` row.

**Migration:** for each `web_crawler` document it recomputes the canonical URL from the stored `source_url` (strip tracking params + trailing slash), re-derives `sha256`, de-duplicates rows that collapse to the same identity (keeps the already-canonical row, else the most recently updated; deletes the rest — `kb_chunks` follow via `ON DELETE CASCADE`), and only rewrites rows whose `source_id` actually changes.
