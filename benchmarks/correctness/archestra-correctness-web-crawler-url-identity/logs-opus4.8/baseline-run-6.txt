## What happened

I strengthened the normalization, but **not** in the function that produces a document's canonical URL — because that function determines document identity, and re-keying it would have orphaned every page this connector has ever indexed.

[source-heavy implementation detail removed — files and functions are identified elsewhere]

So the change splits one concept into two:

- **`normalizeCrawlUrl`** — the URL actually fetched, and the basis of document identity. It only removes things a server cannot key on: fragment, default port, host casing, tracking parameters. The path is untouched.
- **`crawlPageKey`** — decides whether two URLs are the same page. It adds trailing-slash removal on non-root paths and query-parameter ordering, and is handed to Crawlee as the request `uniqueKey`.

## Residual risk

The one case that still re-keys: a document whose canonical URL previously **baked tracking parameters into it** (a page with no `[expr]` first reached via a tracking link) gets a new `source_id`, and the old row lingers as a stale duplicate. Force-resync is the remediation. Worth noting that such a document's identity was *already* unstable — I reproduced it: reordering the links on the source page flipped the stored canonical URL to `[expr]`. The change makes identity deterministic for those pages going forward; it can't retroactively rename the rows they created.

Two smaller ones. Trailing-slash identity is still discovery-order dependent: if a site links both `/a` and `/a/`, the document keeps whichever form was seen first, so a link reordering between syncs can re-key it. That is today's failure mode, now with a much narrower variant space; closing it entirely requires re-keying the existing corpus. And `metadata` participates in `contentHash` (`connector-sync.ts:416`), so affected documents will re-chunk and re-embed once on the next sync — cost, not correctness.

Finally, the "lowercase the host" and default-port rules are belt-and-braces: the WHATWG `URL` parser already lowercases hosts and drops `:80`/`:443` at parse time, so neither can re-key anything. I kept both explicit — the first because you asked for it, the second because it was already there.
