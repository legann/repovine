## What happened

I strengthened the normalization, but split it into **two** functions rather than one, because the single existing `normalizeCrawlUrl` is used for four different jobs and one of the four requested rules is unsafe in three of them.

**Files changed: one** — `platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts`.

- `normalizeCrawlUrl` (the URL we fetch, store, and scope from) now strips the seven tracking parameters, lowercases the host, and keeps the existing hash/default-port stripping.
- A new `canonicalCrawlKey` adds trailing-slash removal on non-root paths, and is used **only** as a page-identity key.
- `enqueueAllowedLinks` dedupes discovered links by that key against a per-crawl `Set` seeded with the start URL, so `/a`, `/a/`, `[expr]`, and `[expr]` are fetched once and produce one document.

## Why trailing-slash stripping is confined to the key

Putting it in `normalizeCrawlUrl` breaks two things, both of which I verified rather than assumed:

**1. It silently widens the crawl scope.** `createCrawler:182` feeds `normalizeCrawlUrl(…)` into `buildAllowedPathPrefixes`, whose line 469 is `[expr]`. Strip the slash and it falls through to line 472. I ran the function verbatim:

[code excerpt removed — 2 line(s)]

A `/docs/`-scoped crawl becomes a whole-origin crawl. This connector scopes deliberately — `beforeRedirect` (lines 226-256) exists to stop out-of-scope redirects — so that is a scope escalation, not a cosmetic change.

**2. It orphans every already-indexed document**, which is what your constraint forbids. The chain:

| Location | Fact |
|---|---|
| `web-crawler-connector.ts:444-449` | `[expr]`, and `sourceUrl` is the same URL |
| `connector-sync.ts:419-421`, `502-512` | that `id` is the `sourceId` upsert key — miss ⇒ `INSERT` |
| `database/schemas/kb-document.ts:44-47` | `uniqueIndex(…)` — a new id doesn't collide, it coexists |
| `models/kb-document.ts:332` | `deleteByConnectorAndSourceId` exists but **has zero callers** — nothing prunes |
| `models/kb-chunk.ts:117` | search joins `kb_documents`, so the orphan keeps being served |

Every directory-style URL (`/docs/`, `/docs/install/`) would get a new `source_id` on the next sync: a fresh row inserted, the old row left behind, never refreshed, still returned by search. Keeping the path as authored keeps `doc.id` byte-identical, so existing rows are found and updated in place.

## Residual risk

The one case that can still create a duplicate: a page whose **only** indexed URL carried a tracking parameter. It was stored as `[expr]`; it will now be fetched and stored as `https://x/a`, so a new row appears and the old one goes stale while remaining searchable. This is forced by the "strip tracking parameters" requirement — it cannot be avoided while also honoring that bullet. It's narrow: `normalizeCanonicalUrl` prefers the page's `[expr]`, which rarely carries tracking params. Pre-existing `/a` vs `/a/` duplicate pairs collapse to one going forward, with the loser going stale for the same reason.

Cleaning those up needs a prune the codebase doesn't currently perform — `KbDocumentModel.deleteByConnectorAndSourceId` is the right hook and is already written, just uncalled. I did not wire it up or write a backfill migration, since both reach well outside the file you scoped and a migration can't be generated here (`drizzle-kit` needs the toolchain, and hand-naming migration files is forbidden by the migrations skill).
