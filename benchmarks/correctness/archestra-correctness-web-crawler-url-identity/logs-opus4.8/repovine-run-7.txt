## 3. Changed behavior & residual risk

**Behavior:** `[expr]` → `[expr]`. Trivially-different URLs (tracking-decorated, trailing-slash, host-case variants) now collapse to one identity for both crawl-frontier dedup and document `source_id`. Crawl scope is unchanged; path/query **case** is intentionally preserved (only host is lower-cased, per spec).

**Residual risks:**

1. **Re-key duplicates on next sync (primary).** `source_id` = `sha256(…)`, written once, and `connector-sync` never prunes. For already-indexed docs whose stored identity contained a tracking param or a non-root trailing slash, the new normalizer yields a different `source_id` → `findBySourceId` misses → a **new row is inserted while the stale row remains**, so that page is returned twice by kb search until reconciled. Docs without those traits keep their exact identity (verified) and are unaffected. **Full correctness needs a follow-up data migration** re-keying existing `web_crawler` `source_id`s (re-normalize `source_url`, recompute the hash, dedup collisions), mirroring `0131_fix_agent_tool_trailing_underscores.sql`. I did not ship it here because: it's a destructive dedup of `kb_documents`/`kb_chunks` (rule #8 — no DB modifications without approval); the repo's SQL-only migrations can't safely re-implement `[expr]` semantics without recreating the very SQL/TS mismatch 0131 fixed; and a safe version needs a `.test.ts` (cf. 0297/0299), which the task forbids.

2. **Fetch 404 on slash-strict servers.** A discovered/seed `/page/` is now fetched as `/page`; a server that serves only `/page/` and doesn't redirect would 404 it. Mitigated in practice by the connector's existing same-origin, in-scope redirect following (`beforeRedirect`, :236), which follows the common `/page` → `/page/` 301.

3. **Query re-serialization** is confined to URLs that actually carry a stripped param (guarded `[expr]`), so untouched query strings keep their original `[expr]`-encoding.
