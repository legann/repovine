I strengthened the crawler's URL normalization, but split it into two functions rather than one — because `normalizeCrawlUrl` turned out to have three jobs, and only some of them can safely absorb all four rules.

## What I changed

One file: `platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts`.

**`normalizeCrawlUrl` (`:626`)** — now also strips the seven tracking parameters and lowercases the host, on top of the existing fragment and default-port stripping. This function's output is the URL that gets fetched, scope-checked, and hashed into the document id, so it only touches parts that cannot change which resource an origin serves.

**`canonicalPageKey` (`:646`)** — new. Adds trailing-slash folding on top of `normalizeCrawlUrl`. Used solely as a crawl-time dedupe key.

**`enqueueAllowedLinks` (`:412`) + `createCrawler` (`:202`)** — a `queuedPageKeys` set, seeded with the start URL, drops a discovered link whose canonical key is already queued. This is what actually makes trivially-different URLs resolve to one page.

`stripTrackingParams` (`:654`) only mutates `searchParams` when a tracking key is present, because assigning to `searchParams` re-encodes the entire query string (`[expr]` → `[expr]`) — that would silently change the fetched URL and the document id of every page carrying an encoded query param.

## Why the trailing-slash rule could not go in `normalizeCrawlUrl`

Folding `/docs/` → `/docs` there breaks three things:

1. **It changes what gets fetched.** `normalizeCrawlUrl` feeds `crawler.run()` at `:131` and `:172`, and every discovered link at `:598`. `/docs/` and `/docs` are distinct HTTP requests; a start URL of `/docs/` would be requested as `/docs`.
2. **It silently widens the crawl scope.** `:193` normalizes the start URL and hands its pathname to `buildAllowedPathPrefixes`, which at `:493` branches on `path.endsWith(…)`. With the slash gone, `/docs/` falls to the parent-directory branch and yields `/` — the whole host. I confirmed this: the naive normalization turns the prefix `/docs/` into `/`. No test covers it.
3. **It orphans every indexed document.** `doc.id` is `sha256(…)` (`:468`) and is persisted as `kb_documents.source_id` (`connector-sync.ts:504`), the only key matching a crawled page to its indexed row (`connector-sync.ts:419-422`). Re-hashing a different string means `findBySourceId` misses, a duplicate row is inserted, and the old row is never reconciled — `deleteByConnectorAndSourceId` (`models/kb-document.ts:332`) has zero callers, and the retrieval join (`models/kb-chunk.ts:117-127`) has no freshness filter. The stale copy would be served forever.

So the fold happens at the dedupe key, where it collapses `/docs/guide/` and `/docs/guide` to one fetched page without rewriting any URL that is requested, scoped, or hashed.

I verified the pure logic by transcribing the helpers into a script (tests can't run — this worktree has no `node_modules`). All six trivial variants of one page collapse to a single key; tracking params are stripped case-insensitively while `[expr]` and the lookalike `[expr]` survive; `[expr]` stays `[expr]` when no tracking param is present; IPv6 brackets, IDN punycode, port and userinfo all round-trip the `hostname` setter. I also walked each URL the existing test file pins (`:163`, `:175`, `:178`, `:271`, `:317`, `:648`, `:667`) — each still normalizes to its expected value.

## Residual risk

Two, both worth naming.

**A page previously indexed under a URL containing tracking params changes its `source_id`.** That page is exactly what the task asks to canonicalize, so the churn is intended — but because no purge path exists, the old row lingers and keeps being served alongside the new clean one until the connector is deleted. Documents whose URLs carry no tracking params — the overwhelming majority, and everything with a `[expr]` — keep their id and are updated in place. I did not add a migration or purge: reconstructing the mapping is impossible (old and new `source_url` are different URLs), and deleting indexed rows is not something I'd do without asking.

**Enqueue dedupe can drop a page if a site links the bare form `/a` before `/a/` and hard-404s the bare form.** In practice servers redirect `/a` → `/a/`; the `beforeRedirect` hook permits same-origin in-scope redirects, `loadedUrl` restores the slash, and the document keeps its identity. Only a server that 404s the bare form loses the page, and it surfaces in the run's `skipped` list rather than failing silently.
