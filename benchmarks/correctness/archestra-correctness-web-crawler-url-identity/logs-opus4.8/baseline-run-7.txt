## What I changed

**`platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts`** (only file):

1. `TRACKING_QUERY_PARAMS` — the seven listed identifiers.
2. `normalizeCrawlUrl` now strips tracking parameters, and documents that the URL parser already guarantees the lowercase host. Default-port and fragment stripping unchanged.
3. New `canonicalPageKey` — folds a trailing slash on non-root paths.
4. `createCrawler` holds a per-crawl `Set` of page keys (seeded with the start URL); `enqueueAllowedLinks` filters discovered links against it.

## The split, and why

The task asks for four rules in one normalizer, but two of them cannot live in the same function. `buildDocument` hashes the normalized URL into the document id (`web-crawler-connector.ts:467`), and `connector-sync.ts:419` looks documents up by exactly that id. **The normalized URL *is* the primary key of every indexed document.** Stripping a trailing slash inside `normalizeCrawlUrl` would re-key every directory-style URL (`/docs/` → `/docs`), so on the next sync `findBySourceId` misses, a fresh row is inserted, and the original row is orphaned — it is never re-synced and never pruned, because the only delete path is connector deletion (`routes/knowledge-base.ts:1074`). That directly violates the "must continue to be served correctly" constraint. It would also change what gets *fetched*: `/a/` and `/a` are distinct request targets, and the test server routes on exact pathname (`web-crawler-connector.test.ts:725`), so a rewritten seed 404s.

So tracking parameters — which servers ignore, making the stripped URL equally fetchable — are removed from the URL the crawler fetches and stores. The trailing slash is folded only in `canonicalPageKey`, which decides whether a discovered link is a page already queued. Both rules deliver the stated goal (the variants are crawled and indexed once) while every already-indexed document keeps its byte-identical `sourceUrl` and id.

Three existing assertions pin this and now still hold: `[expr]` (`:178`), the `sourceUrl` list including `/docs/install/` (`:163`), and the redirect destination `/docs/dest/` (`:271`).

## Deliberately left unchanged

- **`buildAllowedPathPrefixes` (`:483`)** — derives crawl scope from the start URL's path, branching on `path.endsWith(…)` at `:492`. Had I stripped the trailing slash in `normalizeCrawlUrl`, a seed of `/docs/` would fall through to `path.slice(…)` and yield `[expr]` — silently widening a docs-scoped crawl to the entire origin. Preserving the slash keeps this function correct with no edit.
- **`pathMatchesPrefix` (`:577`)** — already normalizes a prefix's trailing slash, so configured prefixes were never affected.
- **`normalizeCanonicalUrl` (`:607`)** and **`buildDocument` (`:467`)** — untouched, which is what holds document identity stable.
- **`connector-sync.ts` / `KbDocumentModel`** — no id-migration or backfill needed, precisely because identity is preserved. `kb_documents` has a unique index on `[expr]`, so an id-churning change would have needed one.

## Residual risk

- **Sites where `/a` and `/a/` are genuinely different pages** now get only the first-linked one indexed. This is inherent to the requested deduplication.
- **Which variant wins is link-order dependent.** Stable for a given site, but a site that reorders links could flip the stored URL of such a page, producing a new id and leaving the old row as a stale duplicate.
- **A page previously indexed under a tracking-param URL** gets a new id (the clean URL) and its old row lingers as an unpruned duplicate. This affects only URLs that carried tracking params into their stored canonical URL — exactly the duplicates being collapsed — and the page itself continues to be served.
- **`searchParams.delete` re-serializes the query** when a tracking param is actually removed, so `[expr]` stores as `[expr]`. Only touches URLs already changing.
- Redirect destinations are not registered in the dedup set, so a link to a page reachable only via redirect can still be fetched twice. Pre-existing; `connector-sync` collapses those at the document level via `sourceId`.
