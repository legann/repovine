## What changed

**Duplicate-page canonicalization now happens at two coordinated levels in `platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts`, and a data migration re-keys every already-indexed document so it keeps being matched, updated, and served after the change.**

`normalizeCrawlUrl` is now the canonical page identity: lowercased host, no fragment, no default port (kept from before), tracking params stripped (`utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`, `gclid`, `fbclid`), and the trailing slash removed from non-root paths. It feeds document identity (`id` = sha256, `sourceUrl`, `metadata.url`) and the crawlee request `uniqueKey`, so `/page`, `/page/`, and `[expr]` now produce one fetch and one document with a deterministic id. A second function, `normalizeFetchUrl` (exactly the old behavior: fragment + default-port strip), is what actually gets fetched and scope-checked — stripping slashes from *request* URLs would 404 on servers that don't redirect slashless paths, and canonicalizing the start URL would silently widen a `/docs/` crawl scope to the whole host (`buildAllowedPathPrefixes` treats a slashless path as a file).

## Files changed and why

- `platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts` — strengthened `normalizeCrawlUrl`; added `normalizeFetchUrl`, `stripTrackingParams`, `buildStartRequest`, and the `TRACKING_QUERY_PARAMS` set; start requests and `enqueueLinks` now carry a canonical `uniqueKey` while fetching the discovered form. `stripTrackingParams` filters the raw query string instead of `URLSearchParams` so surviving params keep their original bytes (URLSearchParams would re-encode `[expr]` as `[expr]`, shifting identities of untouched URLs).
- `platform/backend/src/database/migrations/0313_rekey_web_crawler_document_source_ids.sql` (+ `meta/_journal.json` via `drizzle-kit generate --custom`) — re-keys stored rows. The repovine graph annotation flagged this as one contract: `kb_documents.source_id` is the persisted sha256 of the old normalization, sync matches rows by `[expr]` (`connector-sync.ts:419`) with **no prune step**, so without the migration the first sync after this change would insert a duplicate of every affected page and search would keep returning the stale copy. The SQL mirrors the two new rules byte-for-byte on `source_url` (which holds exactly the string that was hashed), recomputes `[expr]`, and where several rows collapse into one canonical URL keeps the most recently updated row and deletes the rest (chunks cascade via `kb-chunk.ts:44`). This follows the repo's precedent of `0131_fix_agent_tool_trailing_underscores.sql`, which re-keyed stored values after the same class of normalization change.
- `repovine.annots.json` — module annotation updated through `write_annotation` to record the two-tier design and the migration contract.
