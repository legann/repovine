## What changed

**One file: `platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts`** (+66/−2). No other file needed changes.

The normalization is deliberately split across two layers, because document IDs are `sha256(…)` (`buildDocument`, line 459) and the sync pipeline keys documents by that ID (`connector-sync.ts:419`):

1. **`normalizeCrawlUrl` (line 617)** — the URL that gets fetched, stored as `sourceUrl`, and hashed into the document ID — now additionally:
   - strips the tracking params `utm_source/medium/campaign/term/content`, `gclid`, `fbclid`, guarded by a `has()` check so URLs *without* tracking params are never re-serialized (deleting any search param rewrites the whole query, e.g. `[expr]`→`[expr]`, which would have silently changed IDs of unrelated indexed pages);
   - explicitly lowercases the host (the WHATWG parser already guarantees this, so zero ID churn — same defensive style as the existing default-port stripping, which is kept).
2. **`buildRequestUniqueKey` (line 645)** — a new Crawlee request-dedup key applied to the start request (`buildStartRequest`, used at both `crawler.run` call sites, lines 131/172) and to every discovered link via `enqueueLinks.transformRequestFunction` (line 430). On top of `normalizeCrawlUrl` it removes a trailing slash on non-root paths, strips the remaining `[expr]` prefix family, and sorts query params — so slash/tracking/param-order variants collapse to **one fetched page per crawl**, while the fetched URL and stored identity keep the site's original form.

**Why the trailing-slash rule lives in the dedup key, not in `normalizeCrawlUrl`:** stripping it from the identity URL would re-ID every already-indexed `/dir/`-style page. Since documents are only ever deleted with their connector (`routes/knowledge-base.ts:1074` — there is no stale-document pruning), that would leave a permanently stale duplicate row for essentially every existing document. It would also change which URL is fetched (breaking slash-sensitive servers) and contradict the behavior the existing test suite pins (`web-crawler-connector.test.ts:163-180` asserts `sourceUrl` and `sha256` IDs with trailing slashes intact; the test HTTP server 404s slash-stripped paths). The key must also be *at least* as canonical as Crawlee's default (verified against the actual `v3.14.1` source: `Request.computeUniqueKey` → `normalizeUrl`, which strips `[expr]`, sorts params, and trims a trailing slash) — otherwise setting an explicit `uniqueKey` would regress dedup that already exists; hence the sort and `[expr]`-prefix handling in the key.

## Deliberately unchanged, with proof of scope

- **Serving/query path** — `query.ts:265` returns `sourceUrl` straight from the stored row; the only URL-hash lookup anywhere is at ingest time (`connector-sync.ts:419` `findBySourceId`). Nothing recomputes URL hashes at serve time, so every existing document keeps serving unchanged with no code change.
- **Crawl-scope derivation** — `buildAllowedPathPrefixes` (line 475) derives the allowed prefix from the normalized start URL's pathname; safe untouched because `normalizeCrawlUrl` still never rewrites the path (had slash-stripping gone there, a start URL of `[expr]` would have widened scope from `/docs/` to `/`).
- **Redirect guard** — the `beforeRedirect` hook (lines 241-266) validates raw redirect targets inside got's internal redirect handling (per its own comment, line 228); canonicalizing there would change which redirects are refused, which the task doesn't ask for.
- **SSRF check** — `assertPublicCrawlUrl` (line 636) uses only the hostname, unaffected by query/path normalization.
- **`normalizeCanonicalUrl`** (line 595) — untouched by design: it inherits tracking-param stripping through `normalizeCrawlUrl`, and a site-declared `[expr]` is kept verbatim otherwise (pinned by `web-crawler-connector.test.ts:178-180`).
- **Tests** — per constraint; all 23 existing tests traced statically against the change (no test uses query params, uppercase hosts, or slash-variant links, and fetch/identity slash behavior is unchanged).
- **Docs** — `docs/pages/platform-knowledge-connectors.md:299-322` describes crawl scope and extraction only, making no claims about URL normalization or dedup, so nothing there becomes stale.

## Behavior summary and residual risk

**Changed behavior:** tracking-param URL variants (including `gclid`/`fbclid`, which Crawlee's built-in dedup ignores) now canonicalize to the clean URL everywhere — fetch, dedup, `sourceUrl`, and document ID — so they merge with the clean URL's existing document; trailing-slash variants of the same path collapse to a single crawl request per sync; host case and default ports are normalized explicitly. Document IDs are byte-stable for every URL the new rules don't target.

**Verification done despite the frozen worktree** (installs/tests are intentionally blocked here): the exact pure-function logic was executed under plain Node — 23 assertions covering every rule, the byte-stability guard, and an exhaustive 324-pair sweep proving the new dedup key merges everything Crawlee's default merges; the Crawlee `uniqueKey` semantics were confirmed from the tagged v3.14.1 sources.

**Residual risk:** (1) I could not run `pnpm type-check`/vitest in this environment; the untested surface is two long-stable Crawlee 3.x API touchpoints (`run(…)`, `enqueueLinks.transformRequestFunction`). (2) Documents previously indexed under tracking-param URLs re-ingest once under their clean identity; the old rows linger (no pruning exists) and keep serving, same as any page that disappears from a site. (3) An `excludePathPatterns` regex written to match tracking params no longer sees them on discovered links — those URLs now crawl in clean form instead of being excluded.
