## What changed

Two trivially-different URLs for the same page now canonicalize to one document identity, and a data migration re-keys everything already indexed so existing documents keep being matched, updated in place, and served — instead of being stranded next to duplicates on the first re-crawl.

### Files changed

**`platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts`**
The normalization is split into two tiers, because the old single function fed two consumers with different correctness needs:

- `normalizeCrawlUrl` (`web-crawler-connector.ts:606`) — applied to every fetched/discovered/scope-checked URL: fragment removal (existing), default-port stripping (existing, kept), explicit host lowercasing, and tracking-parameter removal (`utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`, `gclid`, `fbclid`; `web-crawler-connector.ts:49`). It deliberately **keeps** trailing slashes: servers may treat `/docs` and `/docs/` as different resources, so the crawler must request the path exactly as published. Tracking params are removed textually (`stripTrackingQueryParams`, `web-crawler-connector.ts:636`) rather than via `URLSearchParams`, whose round-trip re-encodes kept parameters (`[expr]` → `[expr]`) and would silently change the identity of URLs with no tracking params at all.
- `normalizeDocumentUrl` (`web-crawler-connector.ts:625`) — document identity: everything above plus non-root trailing-slash removal. `normalizeCanonicalUrl` (`:593-602`) now routes through it, so `buildDocument`'s `sha256` id, `sourceUrl`, and `metadata.url` all use the canonical form.

**`platform/backend/src/database/migrations/0313_rekey_web_crawler_source_ids.sql`** (+ generated `meta/_journal.json` entry, via `drizzle-kit generate --custom`)
`kb_documents.source_id` is the persisted sha256 of the normalized URL, matched on every sync by `[expr]` (`connector-sync.ts:419-422`), written once (`connector-sync.ts:502-512`), with no prune step — so without a re-key, the first crawl after deploy inserts a duplicate row next to each stale one and search returns both forever. Following the repo's precedent for exactly this class of change (`0131_fix_agent_tool_trailing_underscores`), the migration: (1) collapses rows whose URLs canonicalize identically, keeping the most recently updated (chunks cascade, `schemas/kb-chunk.ts:42-44`); (2) re-keys survivors to the new sha256. Stored URLs are already WHATWG-serialized (lowercase host, no default port, no fragment), so the SQL mirrors only the two new steps, textually, to stay byte-identical with the TypeScript. Two statements because the duplicates must be gone before the re-key writes into the unique index `kb_documents_source_idx` (`schemas/kb-document.ts:44-47`).

`repovine.annots.json` was updated through `write_annotation` (normalizer↔migration contract recorded); the repovine server also appended `.repovine/` to `.gitignore` — tooling housekeeping, not part of the patch.
