## What changed and why

**One file changed: `platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts`.** The normalization is split into two tiers, because the document identity is `sha256(…)` and that hash is the `kb_documents` upsert key — any URL class whose canonical form changes gets re-keyed and its already-indexed row orphaned:

- **`normalizeCrawlUrl` (line 618)** — the canonical URL that is fetched, stored as `sourceUrl`, and hashed into the document id — now also **strips tracking query parameters**: any `[expr]` name plus `gclid`/`fbclid` (new `TRACKING_QUERY_PARAMS` const at line 38, `isTrackingQueryParam` at line 649; case-insensitive). Tracking params never select content, so stripping is safe for fetching, and it makes document identity deterministic instead of dependent on which link variant a crawl discovered first. **Host lowercasing** is inherent here: WHATWG `URL` lowercases http(s) hosts before `href` serialization (verified: `HTTP://EXAMPLE.com/PaTh` → `http://example.com/PaTh`). Default-port stripping kept as-is per the task.
- **New `crawlUniqueKey` (line 639)** — a request-queue dedup key applied as the crawlee `uniqueKey`: **removes trailing slashes on non-root paths**, lowercases the host explicitly, and sorts remaining query params. `/page/`, `/page`, and `[expr]` now collapse to one crawl request and one document. It is wired in at all three enqueue points: the `sync` and `testConnection` start requests via `buildStartRequest` (lines 124, 165, 607) and discovered links via `transformRequestFunction` in `enqueueAllowedLinks` (line 422).

Trailing-slash removal deliberately lives **only** in the dedup key, not in the canonical URL: `/docs` and `/docs/` can be different HTTP resources, and re-keying would orphan nearly every already-indexed directory-style document. The existing tests pin exactly this contract — `sourceUrl` of `[expr]` and `[expr]` with slashes intact (`web-crawler-connector.test.ts:163-180`) — so all 24 tests keep passing unchanged. Sorting in the key is not a task bullet but prevents a regression: crawlee's default uniqueKey (apify `normalizeUrl`) already sorted params and stripped `[expr]`/trailing slashes; once we set explicit keys we must cover the same space. Setting the key on the start request too is required, not cosmetic — otherwise a root start URL (`/` → crawlee default key `http://host`, ours `http://host/`) would be fetched twice.

## Related paths deliberately left unchanged, with proof

- **Ingestion upsert** — `connector-sync.ts:419` looks up by `[expr]` where `[expr]`; it's connector-agnostic, and compatibility is handled by keeping ids stable rather than adding alias lookups. `ConnectorDocument` (`types/knowledge-connector.ts:546`) has no previous-id field to populate.
- **Serving path** — search reads stored rows only: `models/kb-chunk.ts:117` and `:174` select `d.source_url` from `kb_documents`; `knowledge-base/query.ts:265` returns it. No code recomputes the URL hash at read time (only `buildDocument`, web-crawler-connector.ts:452, ever computes it), so every already-indexed document keeps being served byte-for-byte as before.
- **Deletion/pruning** — the only bulk delete is on connector deletion, `routes/knowledge-base.ts:1074`; `deleteByConnectorAndSourceId` has no production callers. There is no stale-document pruning to adapt.
- **Crawl scope** — `buildAllowedPathPrefixes` (web-crawler-connector.ts:468) derives scope from the start URL's pathname; param-stripping never touches the pathname and the trailing slash is preserved in `normalizeCrawlUrl`, so a `/docs/`-scoped crawl stays `/docs/`-scoped.
- **Redirect guards** (web-crawler-connector.ts:230-259) — redirect targets are fetched as the server dictates; identity is normalized afterward via `normalizeCanonicalUrl` (line 588) → `normalizeCrawlUrl`, which already strips tracking params from redirect-added query noise.
- **Crawlee context wrapper** — `basic-crawler.js` spreads our `transformRequestFunction` over its own depth-marking one; safe because the connector never sets `maxCrawlDepth` and tracks depth via `userData.depth` (web-crawler-connector.ts:267, 425).

## Behavior summary and residual risk

After this change, one page reachable under tracking-param, trailing-slash, host-case, or param-order variants is crawled once and indexed once, under a canonical URL free of tracking params; fetches for enqueued URLs no longer carry `[expr]`/`gclid`/`fbclid`. Residual risks: (1) documents previously indexed under a tracking-param URL re-key on the next sync — the new clean-URL row updates in place thereafter, while the old row remains served with its last-indexed content until the connector is deleted (no pruning exists; this churn is confined to exactly the duplicate class the task targets, and such ids were already discovery-order-unstable before). (2) Slash-variant identity is first-discovered-wins within a crawl; a site serving both `/page` and `/page/` as 200 with no redirect or `[expr]` could re-key a page once if its internal link style flips between crawls. (3) An `excludePathPatterns` regex written to match tracking params (e.g. `[expr]`) no longer matches discovered links, since filtering sees the canonicalized URL.
