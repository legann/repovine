## Summary

**Done.** URL normalization in the web-crawler connector is strengthened so trivially-different URLs canonicalize to one page, while every already-indexed document keeps its identity and keeps being served. One file changed: `platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts` (+41/−2).

### What changed and why

The change works at two layers, because the codebase pins different requirements on each:

1. **`normalizeCrawlUrl` (line 611)** — the normalization applied to the URL the crawler dials and to document identity (`sourceUrl`, `metadata.url`, and the sha256 document id at line 458):
   - now strips the tracking query params `utm_source/medium/campaign/term/content`, `gclid`, `fbclid` (case-insensitive; new `TRACKING_QUERY_PARAMS` constant at line 36),
   - explicitly lowercases the host (line 614),
   - keeps the existing fragment and default-port stripping.
   URLs without tracking params come out byte-identical to before (verified: reading `searchParams.keys()` doesn't re-serialize the query), which is what keeps existing document ids stable.

2. **`crawlUniqueKey` (line 639) + explicit crawlee `uniqueKey`** — trailing-slash removal on non-root paths lives in the request-queue dedupe key, set on the start request via `buildCrawlRequest` (lines 130, 171) and on discovered links via `transformRequestFunction` (line 428). `/docs/page/`, `/docs/page`, and `[expr]` now collapse to one fetch and therefore one document per crawl. The key also sorts query params, preserving the dedup strength crawlee's default key provided before the override.

**Why trailing-slash stripping is confined to the dedupe key** (this is the load-bearing design decision): rewriting the path of the *dialed* URL breaks servers that 404 the slash-stripped form — the connector's own test fixture is such a server (`web-crawler-connector.test.ts:722-739` routes by exact pathname, no redirect); and rewriting the path in *identity* would re-hash every already-indexed page ending in `/`, orphaning its row into a permanently-stale duplicate on the next sync. The existing tests pin both: fetched-URL slash preservation (`:548`) and slash-preserving `sourceUrl`/`id` (`:163-166`, `:178-180`, `:271`, `:317`, `:667`).

### Why already-indexed documents keep being served correctly

- Re-sync matches existing rows by `[expr]` where `sourceId` is the connector's URL hash (`connector-sync.ts:419-422`). Since normalization is byte-stable for URLs without tracking params, re-crawls keep updating the same rows instead of duplicating them.
- No serving path recomputes URL hashes: documents are listed/fetched by DB id (`[expr]`), and RAG retrieval joins chunks to documents by `document_id`, returning the stored `source_url` (`[expr]`; `knowledge-base/query.ts:265-267`). A repo-wide search confirmed `normalizeCrawlUrl` and the URL-hash derivation exist only in this connector.

### Code paths deliberately left unchanged

- `buildAllowedPathPrefixes` (`web-crawler-connector.ts:474`) — crawl scope derives from the start URL's pathname; safe because `normalizeCrawlUrl` never rewrites the pathname, so scope for `https://site/docs/` stays `/docs/` (a naive slash-strip would have widened it to the whole site).
- `connector-sync.ts` ingestion and `models/kb-document.ts` lookups — generic engine keyed by the connector-supplied id; correctness follows from id stability (`connector-sync.ts:419`).
- Bulk deletion exists only behind the explicit force-full-resync route (`routes/knowledge-base.ts:1073-1075`); regular syncs never prune, so no cleanup logic needed changing.
- `docs/pages/platform-knowledge-connectors.md:299-323` — describes the crawler at a level this change doesn't alter ("stores each page with its canonical URL when one is present"), so no docs edit.
- Tests untouched per the task constraint; noting explicitly (per repo policy) that no new tests were added for the new behavior.

### Residual risk

- Documents previously indexed under tracking-param URLs (only possible where the page had no canonical link) get a new identity on the next crawl; the old row stays served but goes stale until a force full re-sync wipes it. That re-identification is the point of the fix and unavoidable.
- When tracking params are stripped, surviving query params are re-serialized by `URLSearchParams` (e.g. `[expr]`→`[expr]`) — affects only URLs whose identity changes anyway.
- Slash-variant pages without canonical links resolve to whichever variant a crawl discovers first; a site that flips its internal link style between syncs can still re-identify such pages (bounded now to one duplicate instead of unbounded growth).
