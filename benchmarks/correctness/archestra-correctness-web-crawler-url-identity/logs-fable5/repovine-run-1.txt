## What changed

**Behavior.** Web-crawler URL canonicalization is now two-tier, both in `platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts`:

- `normalizeCrawlUrl` (every URL the crawler *fetches*: start URL, discovered links, skipped-item ids) now also lowercases the host and strips the seven tracking params (`utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`, `gclid`, `fbclid`), on top of the existing hash and default-port stripping. It deliberately leaves the path untouched.
- New `normalizeDocumentUrl` (document *identity*: `doc.id`, `sourceUrl`, `metadata.url` via `normalizeCanonicalUrl`) applies fetch normalization **plus** trailing-slash removal on non-root paths. So `/docs/`, `[expr]`, `HOST-case`, and `:443` variants of a page now collapse into one document.

The fetch/identity split matters: fetching a slash-stripped path against a strict-routing server (like the test fixture, which routes exact paths — `web-crawler-connector.test.ts:722-731`) 404s or, worse, indexes the error page. Sites keep receiving the URLs they advertised; only the stored identity is canonicalized. Two supporting details: query filtering works on raw `[expr]`-pairs rather than `URLSearchParams` so kept params keep their exact bytes (making identities reproducible in SQL), and `buildAllowedPathPrefixes` now derives the default crawl scope from the raw configured start URL so slash-stripping can never widen a `/docs/` scope to the whole host.

**Migration `0313_renormalize_web_crawler_source_ids.sql`** (+ drizzle journal/snapshot, generated via `drizzle-kit generate --custom`). `kb_documents.source_id` is the persisted sha256 of the normalized URL, written once and never re-derived, and connector sync has no prune (`connector-sync.ts:419-422`, `:502-512`) — without a re-key, the first sync after this change would insert a duplicate row beside every stale one. Following the repo's precedent (`0131_fix_agent_tool_trailing_underscores.sql`, same SQL/TS normalization-mismatch shape), the migration mirrors `normalizeDocumentUrl` in SQL, deletes rows that collapse onto the same canonical URL keeping the most recently updated (chunks cascade via `kb-chunk.ts:42-44`), and re-keys survivors' `source_id`/`source_url`.
