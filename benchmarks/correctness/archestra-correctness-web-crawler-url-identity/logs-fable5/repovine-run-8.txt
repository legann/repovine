## Summary

The web crawler now canonicalizes trivially-different URLs to one document, and a data migration re-keys every already-indexed document so it keeps resolving under the new identity. Verified by type-check, lint, the drizzle consistency checks, the existing test suite, and a differential PGlite harness for the migration SQL.

The one design decision worth knowing: trailing-slash removal applies only to **document identity**, not to the URLs the crawler fetches. `/a` and `/a/` can be different HTTP resources (the repo's own test servers 404 the slash-stripped form), so rewriting fetch URLs would have broken crawling slash-routed sites outright. Tracking-param stripping and host lowercasing are safe pre-fetch and apply everywhere.

## Files changed

**`platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts`** (+43/−4)
- `normalizeCrawlUrl` (line 608) — the chokepoint for every fetched/enqueued URL — now also lowercases the host explicitly and strips `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`, `gclid`, `fbclid` (line 35). Hash removal and default-port stripping are kept.
- New `normalizeDocumentUrl` (line 625) adds non-root trailing-slash removal on top, and `normalizeCanonicalUrl` (lines 593–602) now routes all document identity through it, so the document `id` (sha256 of the canonical URL), `sourceUrl`, and `metadata.url` all use the full canonical form.
- Param stripping filters the raw query string rather than using `URLSearchParams`, so surviving pairs keep their original encoding — required for the SQL migration to reproduce the transform byte-for-byte.

**`platform/backend/src/database/migrations/0313_renormalize_web_crawler_source_ids.sql`** (+ journal/snapshot in `meta/`, generated via `drizzle-kit generate --custom`)
Why it must exist: `kb_documents.source_id` is the persisted sha256 of the old canonical URL, sync matches rows by `[expr]` (`connector-sync.ts:419-421`) and has no prune step — without re-keying, the first sync after this change would insert a duplicate row for every affected page and search would return both forever (this is the exact mismatch migration `0131_fix_agent_tool_trailing_underscores.sql` fixed for tool names). The migration, scoped to `[expr]`, recomputes the canonical URL from `source_url` (SQL replica of the TS transform), keeps the most recently updated row when several collapse to one canonical URL (chunks cascade via `kb-chunk.ts:44`), and updates `source_id`/`source_url` in place. Host/port normalization needs no re-key: stored URLs are WHATWG serializations, which already apply both.
