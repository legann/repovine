## What changed and why

**The problem behind the ask.** `normalizeCrawlUrl` is the single chokepoint whose output becomes the document identity: `buildDocument` sets `[expr]` and `[expr]` (`web-crawler-connector.ts:449-460`), connector-sync persists that id as `kb_documents.source_id` — written once at create (`connector-sync.ts:504`), matched on every later sync (`connector-sync.ts:419-422`), unique per connector (`database/schemas/kb-document.ts:44-47`) — and sync has no prune step. So a normalization change alone would strand every already-indexed document under its old hash: the first sync would insert a duplicate row per page and search would serve both fresh and stale copies. The repo has fixed exactly this class before with a data migration (`0131_fix_agent_tool_trailing_underscores.sql`).

### Files changed

1. **`platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts`**
   - `normalizeCrawlUrl` (request-level, used for the start URL, discovered links, and scope checks) now also lowercases the host and strips tracking params (`utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`, `gclid`, `fbclid`); default-port and fragment stripping kept.
   - New `normalizeDocumentUrl` (identity-level, reached via `normalizeCanonicalUrl`) adds trailing-slash removal on non-root paths. The split is deliberate: trailing-slash stripping is the one transform that can change what a server returns (strict servers 404 `/docs` when only `/docs/` exists), so it applies to the document identity but never to a URL the crawler fetches. `/path` and `/path/` still collapse to one document.
   - Tracking params are removed textually (split `[expr]` / filter / join) rather than via `URLSearchParams`, so surviving params keep their original byte form — this keeps the TS function and the migration's SQL provably equivalent and avoids re-keying URLs whose queries merely contain `[expr]`-style encodings.
2. **`platform/backend/src/database/migrations/0313_web_crawler_url_normalization.sql`** (+ drizzle-generated `meta/_journal.json`, `meta/0313_snapshot.json`) — generated via `drizzle-kit generate --custom` per the migrations skill. Step 1 merges stored web-crawler rows that normalize to the same URL (keeps the most recently updated; `kb_chunks` cascade per `kb-chunk.ts:43`); step 2 re-keys survivors to `[expr]` and updates `source_url`. It applies only the two new transforms — stored URLs are already fragment-free, default-port-stripped, and lowercase-host because the old normalizer emitted WHATWG serializations. Both transforms are idempotent, which provably prevents transient unique-index collisions during the single-pass UPDATE.
3. **`repovine.annots.json`** (via `write_annotation`) — module annotation updated to record the two-level normalization and the source_id↔migration contract.

### Deliberately unchanged, with proof

- **Crawl-scope derivation** `buildAllowedPathPrefixes` (`web-crawler-connector.ts:471-484`) reads `[expr]`; `normalizeCrawlUrl` still preserves the path byte-for-byte, so a start URL of `https://site/docs/` still scopes to `/docs/`. Putting slash-stripping in the request-level function would have silently widened that scope to the whole host.
- **Fetch/enqueue path** (`web-crawler-connector.ts:131`, `:172`, `:193`, `:426-429`): still requests the discovered path form — confirmed by all redirect/scope/crawl tests passing with zero 404s.
- **`connector-sync.ts` ingest** (`:419-422`, `:467-489`, `:502-512`): after the migration, sync finds migrated rows by the new `source_id` and refreshes their `sourceUrl`/`metadata` through the existing content-hash-mismatch update path — no code change needed.
- **`KbDocumentModel`** (`models/kb-document.ts:151-166`) and **citations**: chunks and citations resolve documents by uuid `id` (`models/kb-document.ts:18-34`), which survivors keep; the frontend uses `sourceUrl` only as an href (`knowledge-graph-citations.tsx:126-129`). Nothing dangles.
- **Migration leaves `metadata.url` stale** intentionally; the content hash covers metadata (`connector-sync.ts:404-416`), so the next sync's mismatch refreshes it.
