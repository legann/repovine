## Summary

**File changed:** `platform/backend/src/knowledge-base/connectors/web-crawler/web-crawler-connector.ts` (only file touched, no tests modified).

### What changed and why

The connector had one normalization function, `normalizeCrawlUrl`, used for *everything*: the crawl seed URL, every discovered link that gets fetched, and the final canonical URL that becomes the document's `id`/`sourceUrl`. I split it into two, because trailing-slash removal is safe for document identity but not for a URL that's actually requested:

| Function | Used for | Rules applied |
|---|---|---|
| `normalizeCrawlUrl` (existing, extended) | Seed URL (`sync`/`testConnection`), discovered links (`normalizeDiscoveredUrl`) — i.e. anything that becomes a real HTTP request | hash strip (existing), **lowercase host (new)**, default-port strip (existing), **strip utm_source/utm_medium/utm_campaign/utm_term/utm_content/gclid/fbclid (new)** |
| `normalizeDocumentUrl` (new) | Only the document's canonical `id`/`sourceUrl`/`metadata.url`, via `normalizeCanonicalUrl` | everything above, **plus strip a trailing slash on non-root paths (new)** |

**Why the split, not one function:** tracing the connector's own test suite (`web-crawler-connector.test.ts`) showed its test HTTP server keys routes by exact pathname (`createTestSite`, `web-crawler-connector.test.ts:722-731`), and nearly every fixture registers only the `"/docs/"` (with-slash) route. If trailing-slash stripping were applied to the literal fetch/enqueue URL, the crawler's own seed request would 404 against real servers that don't alias `/docs` and `/docs/` — a real, not just theoretical, production risk (many static hosts/frameworks don't treat these as equivalent). Confining it to `normalizeDocumentUrl` avoids that while still collapsing `/docs` and `/docs/` into the same document.

### Related code paths deliberately left unchanged (with proof)

- **`buildAllowedPathPrefixes`** (`web-crawler-connector.ts:469-482`) and its callers (`:191-195`, `:352-360`): untouched. It derives the default crawl scope from whether the start URL's path ends in `/` (directory vs. single page). Since `normalizeCrawlUrl` still never touches `pathname`, this function receives byte-identical input to before my change — I verified this explicitly rather than assuming it, since I initially "fixed" it defensively and then reverted that once confirming it wasn't needed. Independent confirmation that trailing-slash-on-`startUrl` is meaningful here: the shared `connectorUrlSchema` used by other connectors' base URLs strips trailing slashes at parse time (`platform/backend/src/types/knowledge-connector.ts:73-77`), but the web crawler's `startUrl` field deliberately uses its own schema chain that omits that step (`knowledge-connector.ts:346-355`).
- **`pathMatchesPrefix`** (`web-crawler-connector.ts:563-569`): untouched — it already strips a trailing slash off the *prefix* before comparing, so scope matching was already trailing-slash-tolerant on the pathname side.
- **`normalizePathPrefix`** (`web-crawler-connector.ts:499-505`): untouched — operates on explicit user-supplied `includePathPrefixes`, independent of `normalizeCrawlUrl`; not in scope per the task.
- **`assertPublicCrawlUrl`/`resolveHostname`/`isBlockedAddress`** (`:645-679`): untouched — DNS and IP-range checks are already case-insensitive on hostname.
- **`WebCrawlerConfigSchema.startUrl`** (`platform/backend/src/types/knowledge-connector.ts:346-355`): untouched — task scoped the change to the connector file, and this raw value is exactly what `buildAllowedPathPrefixes` needs preserved.

### Residual risk

1. **One-time KB duplication on next sync.** I traced `connector-sync.ts`: syncs upsert by `[expr]` where `[expr]`, with **no garbage collection** of stale rows on a normal sync (only an explicit "force resync" wipes and rebuilds, `routes/knowledge-base.ts:1039-1078`). Since canonicalUrl changes for pages that had a trailing slash/mixed-case host/tracking params, the next sync will insert new rows alongside old ones for the same logical page, until someone force-resyncs that connector. This does **not** break serving of already-indexed documents — `sourceUrl` is a static, stored string never re-derived at read time (verified through `query.ts`→`kb_chunk.ts`→frontend citation rendering) — but it is a known duplication side effect worth flagging before rollout.
2. **Expected test breakage (not fixed, per "do not modify tests").** Implementing "remove a trailing slash on non-root paths" for document identity necessarily changes `sourceUrl`/`metadata.url`/`id` for any page whose canonical path ends in `/` — the common case in this fixture suite. These existing assertions in `web-crawler-connector.test.ts` now encode the old (pre-normalization) values and will fail: lines 163-166, 175, 178-180, 271, 317-318, 648, 667-668. This is the direct, unavoidable consequence of the requested behavior, not a bug in the change.
3. **Out of scope by task's explicit wording:** remaining (non-tracking) query-param ordering, `www.`/IDN normalization, trailing-dot hostnames — none requested, none touched.
