- Added `normalizeDocumentUrl()` — `web-crawler-connector.ts:625-637` — layered on top of the existing `normalizeCrawlUrl()` (so hash-stripping and default-port-stripping are inherited, not duplicated). It additionally strips the tracking params and removes a trailing slash from non-root paths.
- Rewired the 3 return points of `normalizeCanonicalUrl()` (`web-crawler-connector.ts:591-606`) from `normalizeCrawlUrl` to `normalizeDocumentUrl`. This is the **only** function that feeds a document's `id`/`sourceUrl`/`metadata.url` (via `extractPage` → `buildDocument`), so it's the single correct place to apply stronger canonicalization.
- **Host lowercasing: no code added.** I verified with Node's native `URL` (`[expr]`, also confirmed for mixed-case, IDN/punycode, and IPv6 hosts) that the WHATWG URL parser — which `normalizeCrawlUrl` already calls — lowercases the host unconditionally as part of parsing. Adding an explicit `[expr]` would be dead code, so I left it out and am reporting it as already-satisfied rather than newly-implemented.

## Summary

**Behavior:** a page's document identity (`id`, `sourceUrl`, `metadata.url`) now also drops the 7 tracking params and a non-root trailing slash; host-casing was already normalized. Everything the crawler actually requests over the network, and how it derives crawl scope, is byte-for-byte unchanged.

**Already-indexed documents:** confirmed via the sync/storage code (`connector-sync.ts`, `models/kb-document.ts`, `query.ts`) that `kb_documents.id` is an independent random UUID, not derived from the URL — `sha256(…)` only lives in a separate `source_id` column used as a dedup key during sync. Nothing re-fetches or re-derives it at read/citation time, so existing rows keep serving correctly regardless of this change.

**Residual risk:**
1. **5 existing tests will fail** (`web-crawler-connector.test.ts`, e.g. lines 163-180, 271, 317-318, 648, 667-668) — they pin exact `sourceUrl`/`id`/`metadata.url` strings for trailing-slash directory URLs. This is the direct, unavoidable consequence of implementing "remove a trailing slash on non-root paths," confirmed by statically simulating the new normalization against the fixtures (couldn't run the real suite — this worktree has no `node_modules`). Per the task constraint I didn't touch the test file.
2. **One-time duplicate rows per affected page**: on the next sync, a page whose canonical form changes will miss the `findBySourceId` lookup (old hash) and insert a new row instead of updating in place; the old row isn't auto-deleted (no connector has stale-document reconciliation — only whole-connector delete or force-resync clears rows). Both rows stay individually correct/servable; the cost is duplicate near-identical search results until a force-resync.
3. Trailing-slash collapsing is a heuristic: a server that genuinely serves different content at `/x` vs `/x/` would now have both collide onto one document — inherent to the requested rule, not an implementation bug.
