## Summary

Alerting rules (`alert` saved-object type, alerting plugin) get a new **model version 14** that lowercases `params.severity` on existing rule documents at upgrade. Rules whose severity is already lowercase, has no severity param, or whose severity is not a string are returned untouched by the transform. Two non-obvious requirements drove the shape of the patch:

1. **Encryption (AAD) safety.** `params` and `mapped_params` are in `RuleAttributesIncludedInAAD` (`saved_objects/index.ts:58`), and AAD is built from attribute *values* (`collectAttributesForAAD`, ESO plugin). A plain transform mutating severity would make every affected rule's encrypted `apiKey` permanently undecryptable — rules would load but fail to run. Version 14 is therefore created through `encryptedSavedObjects.createModelVersion(…)`, which decrypts, transforms, and re-encrypts in one pass, with `shouldTransformIfDecryptionFails: [value]` (same policy as every legacy alerting ESO migration, `migrations/utils.ts:31`).
2. **`mapped_params` consistency.** Severity is projected at write time into the `mapped_params.severity` sortable value (`SEVERITY_MAP`, e.g. `[value]`), and find/sort/filter on `params.severity` are rewritten to read that projection instead. A non-canonical casing projects to `''`. When the transform changes the param, it recomputes the projection with the same `getModifiedValue` the write paths use — only the severity key, and only on documents that already have `mapped_params`. Storage shape is unchanged (v14 schema re-exports v13).
