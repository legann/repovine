## Summary

Added saved-object **model version 14** for the alerting rule type (`alert`) that lowercases `params.severity` on existing rule documents during upgrade. Rules with no `severity` param, a non-string `severity`, or an already-lowercase value pass through the transform unchanged.

**Where the migration lives:** `x-pack/platform/plugins/shared/alerting/server/saved_objects/model_versions/rule_model_versions.ts`. Because `params` is in the rule's AAD list (`RuleAttributesIncludedInAAD` in `saved_objects/index.ts:58`), rewriting it invalidates the AAD binding of the encrypted `apiKey`/`uiamApiKey`. Version 14 is therefore wrapped in `encryptedSavedObjects.createModelVersion(…)`, which decrypts, applies the transform, and re-encrypts in one pass — the same pattern as the only prior production usage (`actions/server/saved_objects/model_versions/connector_token_model_versions.ts`). `shouldTransformIfDecryptionFails: true` matches the plugin's long-standing legacy policy (`shouldMigrateIfDecryptionFails: true` in `saved_objects/migrations/utils.ts`), so an undecryptable rule has its encrypted keys stripped with a logged warning instead of failing the whole upgrade.

## Deliberately unchanged, with proof of scope

- **`mapped_params.severity`** — a stored, derived copy used only for rule-list sort/filter. It is re-derived from `params` on every rule write (`application/rule/methods/update/update_rule.ts:365`, `application/rule/transforms/transform_rule_domain_to_rule_attributes.ts:30`, `rules_client/common/bulk_edit/update_rule_in_memory.ts:289` via `getMappedParams`, `rules_client/common/mapped_params_utils.ts:31-44`). A rule stored with `High` already has `mapped_params.severity: ''` today (`SEVERITY_MAP` has lowercase-only keys, `[expr]`); rewriting it would change persisted values beyond the requested case normalization, and its current state is preserved exactly, so pre-upgrade behavior is unchanged.
- **`ad_hoc_run_params` SOs** embed a copy of rule `params`, but by documented design they freeze "the rule as it was configured when the backfill job was scheduled" (`[expr]`), and they are not rules.
- **`alerting_rule_template` SO and the `alerting_v2` plugin's own `ruleModelVersions`** — different saved-object types; the described severity feature (canonical `[expr]`) is the classic alerting plugin's, as proven by `SEVERITY_MAP` in `mapped_params_utils.ts:19-24`.
- **Legacy migrations (`saved_objects/migrations/`)** — that map covers only ≤8.8.0 pre-model-version upgrades (`migrations/index.ts:48-88`); the task explicitly asks for a model version.
- **Rule write paths** — the task covers existing stored rules only; create/update validation is untouched.

## Residual risk

- **Could not execute typecheck/lint/jest**: this worktree is intentionally not bootstrapped (bootstrap is blocked by the environment). Verification was static: every imported type's export was confirmed in its package index, and the code mirrors the compiling `connector_token_model_versions.ts` pattern line-for-line.
- **CI snapshot test** `encrypted_saved_objects/integration_tests/ci_checks/check_registered_types.test.ts` enumerates model versions per ESO type and will need `[expr]` added to its inline snapshot (regenerated with `-u` by design, to trigger security review); I left it untouched per the no-test-changes constraint.
- **Unconditional re-encryption**: `createModelVersion` re-encrypts `apiKey` for every rule doc, including already-lowercase ones — new ciphertext, identical plaintext and AAD, so no functional change; this is inherent to the wrapper and matches the connector-token precedent. Rules whose key was already undecryptable (e.g., lost encryption key) get it stripped with a warning instead of aborting the upgrade — such rules already could not run, and this mirrors the plugin's legacy migration behavior.
- **Serverless/ZDT is safe without a multi-stage release**: the registration (encrypted/AAD attribute sets) is unchanged, and AAD is computed from current document values, so the previous Kibana version can still decrypt migrated docs.
