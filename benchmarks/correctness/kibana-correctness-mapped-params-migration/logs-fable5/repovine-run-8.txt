## What changed

On upgrade, every stored rule (`alert` saved object) below model version 14 passes through a transform that:
- lowercases `params.severity` when it is a string whose lowercase form differs (`High` → `high`, `MEDIUM` → `medium`);
- when it does rewrite the param and the document already has a `mapped_params` object, recomputes `mapped_params.severity` to the canonical sortable projection (`high` → `[value]`). This is required because find/sort/filter on severity read the stored `mapped_params` projection instead of `params` (`find_rules.ts` via `mapped_params_utils.ts`), and the write paths that keep the two consistent don't run during migration — without this, a normalized rule would still be invisible to severity filters;
- leaves the document untouched when `severity` is absent, not a string, or already lowercase.

Because `params` and `mapped_params` are part of the rule's encryption AAD (`saved_objects/index.ts:67-68`) and the type encrypts `apiKey`/`uiamApiKey`, a plain transform would have made every migrated rule's API key undecryptable — rules would load but fail to run. The version is therefore built with `encryptedSavedObjects.createModelVersion(…)` (decrypt → transform → re-encrypt), with `shouldTransformIfDecryptionFails: [value]` mirroring the legacy rule migrations (`migrations/utils.ts:31`).
