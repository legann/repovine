## Summary

Rule `severity` params are normalized to lowercase by a new saved-object **model version 14** on the `alert` type. The transform runs once per document at upgrade (or lazily on read in serverless), lowercases `params.severity` when it is a string with non-lowercase characters, and leaves every other document byte-identical in attribute content.

Two hidden couplings drove the design, and both are handled:

1. **`params` and `mapped_params` are AAD attributes of an encrypted type** (`saved_objects/index.ts:58-77`; the type encrypts `apiKey`/`uiamApiKey`). A plain model version that rewrites `params` would break decryption of every changed rule's API key, silently killing rule execution. Version 14 is therefore wrapped in `encryptedSavedObjects.createModelVersion(…)` (decrypt → transform → re-encrypt), with `shouldTransformIfDecryptionFails: [value]` matching the plugin's long-standing migration policy (`saved_objects/migrations/utils.ts:31`) so an already-undecryptable rule degrades with a logged warning instead of failing the upgrade.
2. **`severity` is a `MAPPED_PARAMS_PROPERTIES` param projected into the stored `mapped_params.severity`**, which find/sort/filter read *instead of* `params.severity` (`rules_client/common/mapped_params_utils.ts`). A non-canonical-case severity projects to `''` at write time, so when the transform changes the param it also recomputes the projection through the same writer function (`getModifiedValue`), e.g. `High` → params `high` + `mapped_params` `[value]`. This mirrors the 8.2 legacy migration, which recomputed `mapped_params` inside a migration the same way. `mapped_params` is only updated where it already exists — no document gains a field it didn't have.
