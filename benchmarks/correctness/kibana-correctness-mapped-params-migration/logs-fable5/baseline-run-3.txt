## What changed

On upgrade, every rule document whose `params.severity` is a string with non-lowercase characters (e.g. `High`, `MEDIUM`, `Critical`) is rewritten with `severity.toLowerCase()`. Rules with no `severity` param, a non-string `severity`, or an already-lowercase value return the document untouched. No other attribute, param, or the storage shape is modified.

## Where the migration lives

The rule saved object (`alert`) registers `modelVersions: ruleModelVersions` at `x-pack/platform/plugins/shared/alerting/server/saved_objects/index.ts:147`. I added version `'14'` there with an `unsafe_transform` change — the change type core designates for mutating existing data (`data_backfill` is documented as only for newly introduced fields, `src/core/packages/saved-objects/server/src/model_version/model_change.ts:107-109`). The transform follows the existing `typeSafeGuard` idiom used in `entity_manager/server/saved_objects/entity_definition.ts:121-122`.

- `x-pack/platform/plugins/shared/alerting/server/saved_objects/schemas/raw_rule/v14.ts` (new) — re-exports the v12 schema, mirroring how `v13.ts` handles a no-shape-change version.
- `x-pack/platform/plugins/shared/alerting/server/saved_objects/schemas/raw_rule/index.ts` — exports `rawRuleSchemaV14`.

## Related paths deliberately left unchanged

- **`mapped_params.severity`** — a derived, search-only copy stored as sort keys (`[value-set]`), built from `params.severity` via `SEVERITY_MAP` in `rules_client/common/mapped_params_utils.ts:19-24`. Its values are lowercase by construction, and it is recomputed on every rules-client write (`application/rule/methods/update/update_rule.ts:365`, `rules_client/common/bulk_edit/update_rule_in_memory.ts:289`, `application/rule/transforms/transform_rule_domain_to_rule_attributes.ts:30`). A rule stored with `High` already has `mapped_params.severity: ''` today; rewriting it in the migration would change persisted data beyond case normalization, which constraint 1 excludes.
- **Rule SO mappings and schema** — `params` is a `flattened` field (`common/saved_objects/rules/mappings.ts:91-94`) and the schema accepts any string value (`[expr]`, `schemas/raw_rule/v1.ts:277`, carried through v12). A value-only change needs no `mappings_addition` and no schema change, so v14 reuses the v12 shape.
- **Legacy migrations map** — `saved_objects/migrations/index.ts` is frozen at `'8.8.0'`; model versions are the mechanism for everything after, so nothing was added there.
- **Write-path casing enforcement for future rules** — rule params are opaque to the alerting framework; casing validation on create/update belongs to each rule type's own `validate.params` schema. The task scopes the change to migrating existing rules.
- **`schemas/raw_rule/latest.ts`** — types `RawRule` off the v12 schema; v14 introduces no shape change, same as when v13 was added.
