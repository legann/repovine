## Summary

Rule saved objects (`alert` type, alerting plugin) get **model version 14**: on upgrade, any rule whose `params.severity` is a string that isn't already lowercase has it lowercased (`High` → `high`, `MEDIUM` → `medium`), and the derived `mapped_params.severity` projection is recomputed with the same mapping the write paths use (`getModifiedValue`: `[expr]`, e.g. `high` → `[value]`). Rules with no `severity` param, a non-string value, or an already-lowercase value pass through as identity. The transform is wrapped in `encryptedSavedObjects.createModelVersion` with `shouldTransformIfDecryptionFails: [value]`, because `params` and `mapped_params` are AAD-included for this encrypted type — the wrapper decrypts and re-encrypts `apiKey`/`uiamApiKey` so every rule keeps decrypting and executing after the upgrade.

Two facts drove the two non-obvious decisions:
- **ESO wrapper is mandatory**: `params` and `mapped_params` are in `RuleAttributesIncludedInAAD` (`saved_objects/index.ts:58-77`). Changing them in a plain model version would break API-key decryption for every normalized rule.
- **`mapped_params.severity` must be recomputed in the same transform**: find/sort/filter on `params.severity` is rewritten to read `mapped_params.severity` (`rules_client/common/mapped_params_utils.ts`), non-canonical casing projects to `''`, and the projection is only recomputed by rules_client write paths — which never run during migration. Lowercasing only `params` would leave a params/projection desync no writer can produce and keep normalized rules invisible to severity filtering. This is a value fix on an existing schema field (`raw_rule/v1.ts:271-275`), not a storage-shape change.

- **Live ESO registration** (`index.ts:306-315`) — untouched; AAD/encrypted-set membership is identical, so this is serverless/ZDT-safe in a single release (value change only, no membership change).
