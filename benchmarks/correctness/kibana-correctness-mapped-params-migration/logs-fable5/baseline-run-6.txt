## Summary

**What changed:** On upgrade, every alerting rule (`alert` saved object) now migrates through new model version `14`, which lowercases `params.severity` when it is a string containing uppercase letters (`High` → `high`, `MEDIUM` → `medium`). Rules with no `severity` param, a non-string `severity`, or an already-lowercase value pass through untouched. Because `params` is part of the rule's AAD (`RuleAttributesIncludedInAAD`, `saved_objects/index.ts:67`), the transform is wrapped in `encryptedSavedObjects.createModelVersion`, which decrypts each document before the transform and re-encrypts after — so `apiKey`/`uiamApiKey` remain decryptable and every rule keeps loading and executing normally. No storage-shape change: the v14 schema is a pure re-export of v13.

**Where the migration lives:** model version `'14'` in `x-pack/platform/plugins/shared/alerting/server/saved_objects/model_versions/rule_model_versions.ts`, following the ESO-wrapped pattern of `actions/server/saved_objects/model_versions/connector_token_model_versions.ts`. The ESO input/output registrations are identical frozen snapshots of the live `alert` registration (the registration itself doesn't change). `shouldTransformIfDecryptionFails: true` matches the policy of all prior alerting rule migrations (`saved_objects/migrations/utils.ts:31`).

**Files changed** (all under `x-pack/platform/plugins/shared/alerting/server/saved_objects/`):
- `model_versions/rule_model_versions.ts` — static map converted to `getRuleModelVersions(…)` factory (versions 1–13 untouched); added the transform, the frozen ESO registration, and version `'14'`
- `model_versions/index.ts`, `index.ts` — renamed export; `setupSavedObjects` now passes its ESO setup contract into the factory
- `schemas/raw_rule/v14.ts` (new) — re-exports the v13 schema, mirroring the existing `v13.ts` no-shape-change precedent
- `schemas/raw_rule/index.ts` — exports `rawRuleSchemaV14`

**Related paths deliberately left unchanged, with proof:**
- **`mapped_params.severity`** (derived sortable copy): it is computed only at rule write time (`getMappedParams`, `rules_client/common/mapped_params_utils.ts:31-44`, called from `application/rule/transforms/transform_rule_domain_to_rule_attributes.ts:30` and bulk edit) and already stores `''` for miscased severities (`[expr]`, `mapped_params_utils.ts:104-109`). Leaving it preserves exact pre-upgrade search/sort behavior; recomputing it would change stored values beyond case normalization, violating the constraint. It self-corrects on the next rule save.
- **Rule templates** (`alerting_rule_template`): they store `params` (`schemas/raw_rule_template/v1.ts:19`) but are a separate SO type and are not rules — the task scopes to "each existing rule".
- **Backfill snapshots** (`ad_hoc_run_params`): embed rule `params`, but by documented design they preserve "the rule as it was configured when the backfill job was scheduled" (`data/ad_hoc_run/types/ad_hoc_run.ts:23-32`).
- **`alerting_v2` plugin**: its rule type is `alerting_rule` (`alerting_v2/common/saved_object_types.ts:8`) and stores no severity in saved objects; severity there is derived per alert event at runtime (`server/lib/rule_executor/build_alert_events.ts`).
- **Legacy `migrations/` system**: pre-8.8 mechanism; the type is on model versions (`saved_objects/index.ts:147`) and the task asks for a model version.
- No test in the repo imports the renamed `ruleModelVersions` export, and the core registered-types CI snapshot doesn't exist in this tree (verified by search); no tests were added or modified.

**Residual risk:** every rule document is decrypted/re-encrypted once during the migration (ciphertext bytes change even for untouched rules — inherent to ESO model versions; logical attributes are identical). Rules that already fail decryption migrate with encrypted attributes stripped plus a logged warning, the same policy every previous alerting migration used. The lowercasing applies to any rule type's string `severity` param — consistent with the framework's own global severity handling, but a hypothetical out-of-tree rule type using case-significant severity values would be normalized too. Finally, this environment blocks bootstrap/typecheck/tests, so the change was verified by static reading against in-repo precedents (connector-token ESO model version, fleet `unsafe_transform`) rather than a compiler run.
