## Summary

Added a saved-object model version (v14) to the alerting **`alert`** rule type that lowercases each existing rule's `params.severity` on upgrade. Already-lowercase, missing, and non-string severities are returned byte-identical.

## 1. Where the migration is localized

The `alert` saved-object type registers `modelVersions: ruleModelVersions` (`.../server/saved_objects/index.ts:147`) — the single registry that runs against every existing rule during upgrade. I **appended** model version `'14'` (the sanctioned append-only extension; released versions are frozen).

Change type: **`unsafe_transform`**, per the core docs — `data_backfill` is explicitly "should only be used to backfill newly introduced fields… mutating existing data… can lead to data corruption" (`model_change.ts:107-109`), whereas `unsafe_transform` is the documented tool for "an arbitrary transformation" of existing data (`model_change.ts:145-185`). Idiom matches the synthetics precedent (`.../private_locations/model_version_1.ts:57-64`).
