## Summary

Added saved-object **model version 14** to the alerting rule (`alert`) type that normalizes each existing rule's `params.severity` string to lowercase during upgrade.

### Where I localized it
The `alert` SO type is registered by the primary plugin `x-pack/platform/plugins/shared/alerting` (`[expr]`, `saved_objects/index.ts:46`). Its model-version registry is `server/saved_objects/model_versions/rule_model_versions.ts` (latest was v13). That's where the migration belongs.

### Files changed
| File | Change |
|---|---|
| `server/saved_objects/schemas/raw_rule/v14.ts` | **New.** Re-exports the v13 schema (no data-shape change). Mirrors how `v13.ts` re-exports v12. |
| `server/saved_objects/schemas/raw_rule/index.ts` | Export `rawRuleSchemaV14`. |
| `server/saved_objects/model_versions/rule_model_versions.ts` | Convert `ruleModelVersions` from a static map to a factory `[expr]`; add v14 wrapped in `encryptedSavedObjects.createModelVersion(…)` with an `unsafe_transform` that lowercases `params.severity` and recomputes `mapped_params`. |
| `server/saved_objects/index.ts` | Build a `ruleEncryptedSavedObjectTypeRegistration` from the existing `RuleAttributesToEncrypt`/`RuleAttributesIncludedInAAD` consts and pass it (plus `encryptedSavedObjects`) into the factory. |

### Two traps the task embedded (both handled)
1. **`params` is in AAD** (`index.ts:67`), and the rule is an **encrypted SO** (`apiKey`, `uiamApiKey`). A plain transform of `params.severity` would leave the encrypted API key undecryptable → the rule couldn't execute. Wrapping v14 in `createModelVersion` decrypts with the pre-migration AAD and re-encrypts with the new one — this is what satisfies *"must continue to load and function normally."* Precedent: `actions/.../connector_token_model_versions.ts`.
2. **`severity` is a `MAPPED_PARAMS_PROPERTIES` param** also projected to the stored `mapped_params.severity` (read by rule find/sort/filter). Every write path keeps `[expr]` (`[expr]`), and the 8.2 migration recomputes it the same way (`migrations/8.2/index.ts`). v14 recomputes it so a normalized `high` actually sorts/filters as high instead of staying the empty projection a non-canonical case produced.

### Behavior
`High`/`MEDIUM`/`Critical` → `high`/`medium`/`critical`, with `mapped_params.severity` recomputed (e.g. `''` → `[value]`). Rules already lowercase, missing `severity`, or with a non-string `severity` are returned unchanged. Storage shape is unchanged (same fields; only the severity value and its derived projection change).
