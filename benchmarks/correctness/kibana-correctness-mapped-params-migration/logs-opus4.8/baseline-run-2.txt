## 1. What changed

I added **model version `14`** to the `alert` saved-object type that lowercases each rule's `params.severity`.

The decisive constraint is that the `alert` type is an **Encrypted Saved Object**, and `params` is part of its AAD (`RuleAttributesIncludedInAAD`, `saved_objects/index.ts:81`). Mutating `params.severity` changes the AAD used to encrypt `apiKey`/`uiamApiKey`. A plain model-version transform would leave those attributes encrypted under the *old* AAD, so the next decryption would fail and the rule would stop running. The migration therefore goes through `encryptedSavedObjects.createModelVersion`, which decrypts under the pre-transform AAD, applies the transform, and re-encrypts under the post-transform AAD — so every rule still loads and runs.

## 2. Localization & files changed

Localized to the alerting plugin's rule saved-object model versions: `x-pack/platform/plugins/shared/alerting/server/saved_objects/`.

## Summary

- **Behavior:** On upgrade, existing rules with a non-lowercase string `params.severity` (`High`, `MEDIUM`, `Critical`, …) are rewritten to canonical lowercase. Rules already lowercase, without a `severity` param, or with a non-string `severity` are left semantically unchanged. All rules are decrypted and re-encrypted once (behavior-preserving; same plaintext and AAD), which is required to keep AAD consistent and matches the precedent of the 8.2 rule migration.
- **Files:** one model-version file (now a function, adds v14), the SO registration wiring in `saved_objects/index.ts`, and a new shape-preserving `v14` raw-rule schema + its export.
- **Residual risk:**
  1. The ESO `check_registered_types` model-version snapshot must be regenerated (`jest -u`) — left undone per the "don't modify tests" constraint; it's the intended Security-review tripwire.
  2. For a rule whose secrets already fail to decrypt (rotated/missing key), `shouldTransformIfDecryptionFails: true` strips the encrypted attributes — identical to the existing legacy-migration behavior for such already-broken rules; no new breakage.
  3. `mapped_params.severity` stays stale until the rule's next write; search/sort behavior is unchanged from today, and rule execution is unaffected.
