## Summary

I added saved-object **model version 14** to the alerting rule (`alert`) type that lowercases the free-form `params.severity` value in place.

### Where I localized the migration

The rule's `severity` is a free-form entry inside the `params` record (`schema.recordOf(…)`), and `params` is listed in the rule's **decryption AAD** (`RuleAttributesIncludedInAAD`, `saved_objects/index.ts:67`). Because the `alert` type is an Encrypted Saved Object, mutating an AAD attribute requires re-encryption — so the transform is wrapped with `encryptedSavedObjects.createModelVersion` (decrypt → transform → re-encrypt), mirroring the existing precedent in `actions/.../connector_token_model_versions.ts`.

### Files changed

| File | Change |
|---|---|
| `.../saved_objects/model_versions/rule_model_versions.ts` | `ruleModelVersions` became a factory `[expr]`. Added version **14**: an `unsafe_transform` (`normalizeSeverityParamToLowercase`) inside `createModelVersion`, with `[expr]` (encrypted/AAD attribute *sets* unchanged) and `shouldTransformIfDecryptionFails: true`. |
| `.../saved_objects/index.ts` | Extracted the rule ESO registration to one const `ruleSavedObjectTypeRegistration` (single source of truth), reused for `encryptedSavedObjects.registerType(…)` and passed into `ruleModelVersions(…)`. Imported `EncryptedSavedObjectTypeRegistration`. |
| `.../saved_objects/schemas/raw_rule/v14.ts` (new) | Re-exports the v13 schema (no shape change), matching the v13-re-exports-v12 precedent. |
| `.../saved_objects/schemas/raw_rule/index.ts` | Exports `rawRuleSchemaV14`. |

The transform is a no-op (returns the document unchanged) when `severity` is absent, non-string, or already lowercase; otherwise it replaces only `params.severity` and preserves every other attribute (including the decrypted `apiKey`, which `createModelVersion` re-encrypts).

### Related paths deliberately left unchanged

- **`mapped_params.severity`** (`rules_client/common/mapped_params_utils.ts`) — the denormalized sort key. Left as-is because (a) the constraint says *"do not change the persisted storage shape beyond the case normalization"*, and (b) it is derived from `params.severity` via `SEVERITY_MAP` (lowercase keys, `[expr]`) and recomputed on every write (`transform_rule_domain_to_rule_attributes.ts:30`, `update_rule.ts:365`, `bulk_edit/update_rule_in_memory.ts:289`). For a non-lowercase severity, `getModifiedValue` already returned `''` (`[expr]`), so this migration introduces no regression and enables a correct recompute on next write.
- **Snooze condition `severity_equals` values** (`[expr]`) — already schema-constrained to lowercase literals; not the rule's `severity` param.
- **`alerting_v2` plugin** — its rule schema has no `severity` param (`grep` of `common/saved_object_types.ts` and its `rule_model_versions.ts` returns none); out of scope.
- **`create` schema / app-layer writes** — not tightened; the task covers existing stored rules, and adding case validation to `create` would risk rejecting valid writes.

### Changed behavior & residual risk

- **Behavior:** On upgrade, every `alert` doc migrates to v14; rules with mixed-case `params.severity` get it lowercased. Already-lowercase / no-severity rules are functionally unchanged. All rules continue to load.
- **Re-encryption of all rule SOs** — inherent to an ESO model version: `createModelVersion` re-encrypts each `alert` doc (new IV) even when severity is untouched. Decrypted values and behavior are identical; only ciphertext changes (same pattern as `connector_token` v2).
- **`shouldTransformIfDecryptionFails: true`** — a rule whose `apiKey` genuinely can't be decrypted (corrupt/rotated key) migrates with the key stripped and a warning, rather than failing the whole upgrade. Rules with a decryptable key or a `null` key (disabled rules — skipped at decrypt, `encrypted_saved_objects_service.ts:560`) are fully preserved.
- **Validation not run:** this benchmark worktree is intentionally not bootstrapped (`node_modules` empty; bootstrap output: *"Do not run … type_check/jest; finalize from static reading"*), so `type_check`/`eslint`/`jest` could not be executed.
