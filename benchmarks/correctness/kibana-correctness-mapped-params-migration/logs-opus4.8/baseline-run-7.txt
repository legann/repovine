### The critical, non-obvious decision: ESO re-encryption

`params` is in the rule's **AAD** (`RuleAttributesIncludedInAAD`, `saved_objects/index.ts:67`). Rewriting `params.severity` changes the AAD, so the encrypted `apiKey`/`uiamApiKey` (`create_model_version.ts` decrypt→transform→encrypt) must be re-encrypted or the rule's API key becomes undecryptable and the rule stops running. Hence `createModelVersion` with `inputType`/`outputType`, matching the `connector_token` precedent. I verified the frozen snapshot's encrypt/AAD members equal the live registration exactly (2 + 18, zero diff), and `getAAD` uses `stableStringify` (`encrypted_saved_objects_service.ts:661`), so AAD is order-independent — re-encryption at migration is byte-compatible with decryption at read time.

I used `unsafe_transform`, not `data_backfill`: core docs (`model_change.ts:107`) state `data_backfill` must not mutate existing data. `shouldTransformIfDecryptionFails: true` matches legacy alerting ESO migrations (`migrations/utils.ts:31`). The transform touches only mis-cased string severities; already-lowercase / absent / non-string are returned unchanged.
