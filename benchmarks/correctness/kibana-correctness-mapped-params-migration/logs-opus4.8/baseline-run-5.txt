## 1. What I implemented

A new saved-object **model version `14`** for the alerting rule type (`alert`) that lowercases each rule's `params.severity`. It runs through the Encrypted Saved Objects (ESO) decrypt→transform→re-encrypt pipeline because `params` is part of the rule's AAD.

The transform (`normalizeRuleSeverityParam`) is deliberately conservative:
- non-string / absent `severity` → returned unchanged;
- already-lowercase `severity` (`toLowerCase()` equals original) → returned unchanged;
- otherwise only `params.severity` is replaced with its lowercase form; every other param and attribute is spread through untouched.

## 3. Summary

**Behavior change:** On upgrade, every existing `alert` rule with a mis-cased `params.severity` (e.g. `High`, `MEDIUM`, `Critical`) is normalized to lowercase (`high`, `medium`, `critical`). Rules already lowercase, or without a `severity` param, keep identical persisted values. Because `params` is in AAD, the migration decrypts, normalizes, and re-encrypts via `createModelVersion`, so API keys stay decryptable and rules load and run unchanged. The storage shape is untouched — only the `params.severity` string value changes.

**Files touched (high level):** the alerting plugin's rule model-version definition, its barrel re-export, and the SO/ESO registration wiring — 3 files, +84/−17.
