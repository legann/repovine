## Summary

I added **model version 14** to the alerting rule (`alert`) saved object. On upgrade it lowercases each rule's `params.severity` value in place; rules whose severity is already lowercase, non-string, or absent pass through untouched. Because `params` is part of the rule's encryption AAD, the transform is wrapped in the Encrypted Saved Objects `createModelVersion` decrypt → transform → re-encrypt pass so `apiKey`/`uiamApiKey` stay decryptable — without that wrapper, changing `params` would make every rule with an API key fail to decrypt after upgrade.

## Where I localized the migration

The rule model-version map: `x-pack/platform/plugins/shared/alerting/server/saved_objects/model_versions/rule_model_versions.ts` (versions 1–13 already lived here; 14 is next in sequence). The rule SO type consumes it at `saved_objects/index.ts:147` (`modelVersions: ruleModelVersions`).

## Residual risk

- **Toolchain not run.** `node_modules` is empty and a from-scratch Kibana bootstrap is out of scope for this sandbox, so `scripts/type_check`/`eslint` didn't run. I validated syntax (`node --experimental-strip-types --check` on all five files) and matched types against the actual `CreateEsoModelVersionFnOpts`, `SavedObjectModelUnsafeTransformFn`, and `EncryptedSavedObjectTypeRegistration` definitions plus the `connector_token`/`fleet` precedents. Worth a `type_check` + `eslint` pass in a bootstrapped tree.
- **All rules are re-encrypted at the v13→v14 boundary**, including already-lowercase ones. This is inherent to any ESO AAD-attribute migration (`createModelVersion` always decrypts then re-encrypts); it is behavior-preserving — same decrypted `apiKey`, same AAD, new ciphertext IV only. It cannot be avoided without leaving mis-cased rules' encryption broken.
- **Undecryptable rules:** `shouldTransformIfDecryptionFails: true` (as in both precedents) keeps a single bad doc from blocking the whole upgrade; such a rule is stripped of its (already-unusable) encrypted key and continues, rather than failing Kibana startup.
- **Snapshot tests:** in full Kibana, adding a model version updates the `alert` hash in `check_registered_types.test.ts`. No such snapshot exists in this repo snapshot (searches were empty), and per the task I changed no tests — flag for the team if that test is present upstream.
