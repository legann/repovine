## Summary

Added rule saved-object **model version 14** that lowercases each stored rule's `params.severity` in place. Because `params` is part of the rule's encryption AAD, the migration is wrapped in `encryptedSavedObjects.createModelVersion` so each rule is decrypted with the pre-migration value, transformed, and re-encrypted against the normalized value — otherwise the rule's encrypted `apiKey`/`uiamApiKey` would become undecryptable and the rule would stop functioning.

### Where the migration lives / files changed

The rule is the `alert` SO type (`[expr]`), registered in `server/saved_objects/index.ts` with `modelVersions: ruleModelVersions`. That is the single localization point.

| File | Change |
|---|---|
| `[expr]` | `ruleModelVersions` const-map → function of `[expr]`; added version `'14'` via `createModelVersion` with an `unsafe_transform` (`normalizeSeverityCase`) that lowercases string `params.severity`, returning the doc unchanged when severity is already lowercase, non-string, or absent. `[expr]` (the AAD/encrypted sets are unchanged; only a subfield value changes). `shouldTransformIfDecryptionFails: true`. |
| `[expr]` | Built `ruleTypeRegistration` (mirrors the existing `encryptedSavedObjects.registerType`, referencing the same `RuleAttributesToEncrypt`/`RuleAttributesIncludedInAAD` arrays so they can't drift) and passed it plus `encryptedSavedObjects` into `ruleModelVersions(…)`. |
| `[expr]` (new) | Re-exports `rawRuleSchema` from `./v13` — no shape change (`params` stays a `[expr]` record). |
| `[expr]` | Exports `rawRuleSchemaV14`. |

Pattern basis: `[expr]` (in-repo `createModelVersion` on an ESO) and synthetics `transformGeoProperty` (in-repo `unsafe_transform` fixing existing malformed data).

Rewriting stored `mapped_params` would exceed "do not change the persisted storage shape beyond the case normalization"; the normalized `params.severity` yields a correct recompute on the next write. |
| Write-time normalization (rules_client create/update) | Task scope is a "saved-object migration … that normalizes each **existing** rule" — an upgrade-time transform of already-stored values, not the create/update path. |
| Snooze `severity_equals.value` | Distinct field under `[expr]`, already constrained to lowercase literals by schema (`v12.ts:27-37`); not `params.severity`. |
| Rule templates (`alerting_rule_template`) and other alerting SO types | The rule is `alert` (`saved_objects/index.ts:43`); templates are a separate type with their own model versions and aren't described as holding mis-cased stored rule severity. |

### Changed behavior & residual risk

- **Behavior:** On upgrade, every rule advances to model version 14. Rules with a mixed-case string `params.severity` (`High`, `MEDIUM`, `Critical`, …) get it lowercased; already-lowercase / non-string / absent severities are untouched. Encrypted attributes are re-encrypted so all rules keep loading and functioning.
- **Verification:** The worktree is intentionally un-bootstrapped (bootstrap/type_check/jest are blocked), so this was verified by static type-tracing against the two in-repo precedents above, not by running `scripts/check.js`. Per the task, no tests were added or modified.
- **Risk — full re-encryption:** `createModelVersion` re-encrypts *all* rule docs at v14, including unchanged ones (inherent to ESO model-version migrations; identical to connector_token's no-op re-encrypt). One-time rewrite churn; functionally transparent.
- **Risk — decryption failures:** `shouldTransformIfDecryptionFails: true` means a rule whose secrets can't be decrypted (e.g., rotated/lost encryption key) has them stripped + re-encrypted with a logged warning; the rule still loads but its API key would need regeneration. This satisfies "must continue to load" and matches the connector_token precedent.
- **Risk — generic scope:** the transform lowercases `params.severity` for any rule type (params is an untyped record). This aligns with existing framework behavior — `getMappedParams` already treats `params.severity` as the canonical severity for all rule types (`mapped_params_utils.ts:14-17`) — and matches the task's stated lowercase-canonical space.
