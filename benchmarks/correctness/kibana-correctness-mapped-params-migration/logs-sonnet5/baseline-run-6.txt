## Summary

**Migration location:** `alert` saved-object type, new **model version 14**, in `x-pack/platform/plugins/shared/alerting/server/saved_objects/model_versions/rule_model_versions.ts`.

### Why `unsafe_transform` + `createModelVersion` (not a plain backfill)

- `params` is listed in `RuleAttributesIncludedInAAD` (`saved_objects/index.ts:58-77`) — it's Additional Authenticated Data for the encrypted `apiKey`/`uiamApiKey` attributes. The ESO service builds AAD by stringifying the *full value* of every AAD attribute (`encrypted_saved_objects_service.ts` `getAAD`/`collectAttributesForAAD`), so changing `params.severity` changes the AAD, which would make `apiKey`/`uiamApiKey` undecryptable unless re-encrypted during the migration.
- `data_backfill` is documented as for backfilling **new** fields only ("using such transformations to mutate existing data... can lead to data corruption" — `model_change.ts`); normalizing an existing value is a mutation, so I used `unsafe_transform`, matching the precedent in `synthetics/.../private_locations/schema.ts` (`transformGeoProperty`, which also fixes bad legacy data in place).
- Wrapped the whole model version in `encryptedSavedObjects.createModelVersion(…)` so the framework decrypts with the old `params`, applies the transform, then re-encrypts with the new `params` — same pattern as `actions` plugin's `connector_token_model_versions.ts` v2.

### Residual risk

- Every existing rule gets decrypted/re-encrypted once at this version bump (even when severity is already lowercase) — inherent to how ESO model versions work, not something this change can avoid.
- `shouldTransformIfDecryptionFails: true` means a rule whose `apiKey` was already undecryptable before this migration stays that way but no longer blocks the upgrade — consistent with existing precedent in this same plugin (`createEsoMigration`'s `shouldMigrateIfDecryptionFails`).
- `mapped_params.severity` stays stale for affected rules until their next save (see table above) — cosmetic (sort/filter only), not a load/execution issue.
