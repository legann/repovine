## Summary

I added model version **14** to the `alert` saved-object type, which normalizes `params.severity` to lowercase.

### Where the migration is localized

| File | Change |
|---|---|
| `x-pack/platform/plugins/shared/alerting/server/saved_objects/schemas/raw_rule/v14.ts` (new) | Re-exports v13's schema unchanged — no shape change, matching the existing convention (v13 does the same re-export from v12) |
| `x-pack/platform/plugins/shared/alerting/server/saved_objects/schemas/raw_rule/index.ts` | Added `rawRuleSchemaV14` export |
| `x-pack/platform/plugins/shared/alerting/server/saved_objects/model_versions/rule_model_versions.ts` | Added `normalizeSeverityParamCase` transform + model version `'14'`; converted `ruleModelVersions` from a plain object to a function taking `encryptedSavedObjects` (needed to call `createModelVersion`) |
| `x-pack/platform/plugins/shared/alerting/server/saved_objects/index.ts` | Updated the one call site to `ruleModelVersions(…)` |

**Why `createModelVersion`, not a plain `unsafe_transform`:** `params` is listed in `RuleAttributesIncludedInAAD` (`saved_objects/index.ts:58-77`), so it's part of the additional authenticated data used to encrypt the rule's `apiKey`/`uiamApiKey`. Any change to `params`'s content — even just a value's casing — changes the AAD, so a plain transform would leave existing rules with an undecryptable `apiKey` after upgrade. `createModelVersion` decrypts under the old attribute values, applies the transform, then re-encrypts under the new ones. This mirrors how the legacy (pre-model-version) migrations for this exact type mutate `params` (`migrations/8.0`, `migrations/8.5`), which all go through the ESO-aware wrapper for the same reason. Confirmed by reading `create_model_version.ts`'s actual decrypt→transform→encrypt implementation, not just by analogy.

**The transform itself** (`rule_model_versions.ts:36-57`): reads `params.severity`; if it's not a string or is already lowercase, returns the document unchanged (same reference — no-op); otherwise returns a new document with only `severity`'s case changed, all other `params` keys and rule attributes preserved via spreads.

### Deliberately left unchanged, with source

- **`mapped_params.severity`** — a separate top-level SO attribute (not part of `params`), derived by `getMappedParams()` in `rules_client/common/mapped_params_utils.ts`. Its own lookup (`[expr]`) is already case-sensitive and silently produces `''` for any non-lowercase input today — a pre-existing, independent bug unrelated to the `severity` param itself. The task says "severity param" and "do not change the persisted storage shape beyond the case normalization"; touching this separate, already-broken field would be a distinct fix outside that scope.
- **`alerting_v2` plugin's own `ruleModelVersions`** (`x-pack/platform/plugins/shared/alerting_v2/server/saved_objects/model_versions/rule_model_versions.ts`) — a different, separate SO type. Its schema (`schemas/rule_saved_object_attributes/v1.ts`) has no `params`/`severity` field at all, confirmed by grep.
- **ES mapping** — untouched; `params` is mapped as `flattened`, so a value-only change requires no mapping update.
