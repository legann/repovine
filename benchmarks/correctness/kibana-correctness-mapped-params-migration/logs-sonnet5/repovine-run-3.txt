## Where the migration is localized

The single canonical registration point for `alert` (rule) saved-object model versions: `x-pack/platform/plugins/shared/alerting/server/saved_objects/model_versions/rule_model_versions.ts`. This was the only place repovine's search surfaced (already carrying an annotation warning about exactly this class of change), and file-system inspection confirms it's the sole definition site for `ruleModelVersions`.

**The critical finding**: `params` and `mapped_params` are both listed in `RuleAttributesIncludedInAAD` (`saved_objects/index.ts:58-77`) — they're Additional Authenticated Data for the rule's encrypted `apiKey`/`uiamApiKey`. A plain `unsafe_transform` mutating `severity` inside either would change the AAD without re-encrypting, making every affected rule's API key undecryptable — silently breaking rule execution. That's why the migration is wrapped in `createModelVersion` (decrypt with old AAD → transform → re-encrypt with new AAD), following the exact pattern already used by `connector_token_model_versions.ts` in the actions plugin.

I also fixed `mapped_params.severity` (via the existing `getModifiedValue` helper, not reimplemented), not just `params.severity`. The annotation on this module states that `mapped_params` is a separate stored projection that find/sort/filter reads instead of `params`, and non-canonical-case severities project to `''` there. Fixing only `params.severity` would leave the search projection permanently wrong for previously-affected rules — I didn't want it to be like that.
