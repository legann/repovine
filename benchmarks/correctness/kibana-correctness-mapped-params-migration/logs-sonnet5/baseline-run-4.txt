## Summary

**Localization.** The `alert` saved-object type (`x-pack/platform/plugins/shared/alerting/server/saved_objects/index.ts`) has a `modelVersions` map (`rule_model_versions.ts`, versions 1–13) where every existing entry is either a no-op or a `mappings_addition` — none mutate data. That matters here: `params` (which holds `severity`) is listed in `RuleAttributesIncludedInAAD` and is used to build the encryption AAD for `apiKey`/`uiamApiKey`. A plain `unsafe_transform`/`data_backfill` touching `params` would leave existing ciphertext bound to the pre-migration AAD and break API-key decryption for every rule the migration fixes — violating "every existing rule must continue to load and function normally." Kibana ships `encryptedSavedObjects.createModelVersion(…)` for exactly this case (decrypt → transform → re-encrypt with new AAD), mirroring the `createEsoMigration` helper this same plugin's legacy migrations (8.0.0, 8.2.0) already use to safely mutate `params`. I used that wrapper for the new version.
