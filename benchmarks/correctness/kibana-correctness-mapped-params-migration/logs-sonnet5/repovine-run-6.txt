## Where I localized the migration

The `severity` param belongs to the **`alerting`** plugin's `alert` saved-object type (`x-pack/platform/plugins/shared/alerting/server/saved_objects`) — the production rule store used by stack alerts, security detection rules, observability, etc. I ruled out the sibling `alerting_v2` plugin (`alertingVTwo`) early: its `ruleSavedObjectAttributesSchema` (`saved_objects/schemas/rule_saved_object_attributes/v1.ts`) has no `params`/`severity` field at all — it's a different, unrelated rule model.

## The key subtlety: encrypted-saved-objects AAD

`params` and `mapped_params` are both listed in `RuleAttributesIncludedInAAD` (`saved_objects/index.ts`) — they're Additional Authenticated Data for the rule's encrypted `apiKey`/`uiamApiKey`. A plain `unsafe_transform` that rewrites `params.severity` would leave the old ciphertext in place while every future decrypt recomputes AAD from the new value — permanently breaking decryption of every affected rule's API key (rules fail to run). So model version 14 is wrapped in `encryptedSavedObjects.createModelVersion(…)` (precedent: `actions/server/saved_objects/model_versions/connector_token_model_versions.ts`), which decrypts with the pre-transform attributes, runs the transform, then re-encrypts with the post-transform attributes — keeping ciphertext and AAD consistent. `[expr]` is set so a single already-corrupt rule can't abort the migration for every other rule, matching the same real precedent.

The transform itself also recomputes `mapped_params.severity` (via the existing `getModifiedValue`/`SEVERITY_MAP` helper) alongside `params.severity`, since `mapped_params` is the projection find/sort/filter actually read — leaving it stale would keep those broken for the very rules we just fixed.

## What I deliberately left unchanged, and why

- **Model versions 1–13**: untouched. `rule_model_versions.ts` carries a repovine annotation flagging this exact surface as append-only/frozen ("Released versions are frozen — new behavior is appended as a new version"); version 14 is a pure addition.
- **`risk_score`** (the other `MAPPED_PARAMS_PROPERTIES` entry): untouched. The transform only overrides the `severity` key on `mapped_params`, spreading the rest, so it can't touch `risk_score` even incidentally.
- **Rules with no `severity` param, or already-lowercase `severity`**: the transform returns the original `doc` reference unchanged (`[expr]`). Source: `mapped_params_utils.ts`'s `SEVERITY_MAP` only has lowercase keys, confirming lowercase is already the canonical form these paths expect.
- **ES mappings**: no `mappings_addition`. `common/saved_objects/rules/mappings.ts` already maps `params` as `flattened` and `mapped_params.severity` as `keyword` — value-only changes need no mapping update.
- **`alerting_v2`**: out of scope per its schema (no `severity`/`params` field), confirmed above.
