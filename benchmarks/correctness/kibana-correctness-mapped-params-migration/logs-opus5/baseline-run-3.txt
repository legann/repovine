## Where I localized the migration

`params` is listed in `RuleAttributesIncludedInAAD` (`x-pack/platform/plugins/shared/alerting/server/saved_objects/index.ts:58-77` — *"these fields are used to construct decryption AAD and must remain in this array to prevent decryption failures during migration"*). Rewriting `params.severity` therefore changes the rule's AAD, so the model version must decrypt and re-encrypt via `encryptedSavedObjects.createModelVersion`, matching the only production precedent in the repo (`x-pack/platform/plugins/shared/actions/server/saved_objects/model_versions/connector_token_model_versions.ts:56-73`).

I used `unsafe_transform`, not `data_backfill`: core states data_backfill *"should only be used to backfill newly introduced fields… using such transformations to mutate existing data of the document can lead to data corruption or inconsistency"* (`src/core/packages/saved-objects/server/src/model_version/model_change.ts:107-109`), and it deep-merges via lodash (`base-server-internal/src/model_version/build_transform_fn.ts:61`).

## Residual risk

- **One test file needs a follow-up you must apply.** `x-pack/platform/plugins/shared/encrypted_saved_objects/integration_tests/ci_checks/check_registered_types.test.ts` has an inline snapshot listing `[expr]` …; it will fail until `[expr]` is added (`jest_integration -u`). I left it alone per the "do not add or modify tests" constraint — it's an intentional tripwire requiring Kibana Security review of ESO model versions. The sibling `getRegisteredTypeHashMap` snapshot and `ESO_TYPES_COUNT` are *not* affected, because `createModelVersion` builds throwaway service instances (`encrypted_saved_objects/server/plugin.ts:162-173`) instead of registering into the main service.
- **Every rule is decrypted and re-encrypted**, not just mis-cased ones: `createModelVersion` has no equivalent of the legacy `isMigrationNeededPredicate`, so the crypto pass runs on all `alert` docs. This adds upgrade time proportional to rule count and widens exposure to pre-existing decryption problems.
- **`shouldTransformIfDecryptionFails: true`** means a rule whose `apiKey` cannot be decrypted has that attribute stripped (with a warning) instead of aborting the whole upgrade. Such rules were already non-functional. This matches `createEsoMigration`'s `shouldMigrateIfDecryptionFails: true` used by every prior alerting rule migration (`saved_objects/migrations/utils.ts:31`).
- **Stale `mapped_params.severity`** for migrated rules until their next update, per the table above.
