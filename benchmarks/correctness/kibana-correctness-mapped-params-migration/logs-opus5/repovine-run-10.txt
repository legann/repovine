## Where I localized the migration

Model version **14** on the `alert` saved object, in the alerting plugin's model-version registry. Two facts drove the localization beyond a plain param rewrite:

1. **`params.severity` is projected into a second stored field.** `mapped_params.severity` holds a sortable form (`SEVERITY_MAP`: `high` → `'60-high'`), and `find` rewrites every sort field, search field, and KQL filter on `params.severity` to `mapped_params.severity` (`find_rules.ts:87-107` via `mapped_params_utils.ts:104-109`). Only the rule write paths recompute it (`transform_rule_domain_to_rule_attributes.ts:30`), and migrations don't run them. A non-canonical severity projects to `''`, so normalizing `params` alone would leave the rule still invisible to severity filters. The transform recomputes `mapped_params` with the same `getMappedParams` helper the writers use — same precedent as the 8.2 migration (`migrations/8.2/index.ts:21`).

2. **`params` and `mapped_params` are both in the rule's ESO AAD** (`saved_objects/index.ts:58-77`), and AAD is built from attribute *values* (`encrypted_saved_objects_service.ts:642-661`). Rewriting them invalidates the encrypted `apiKey`/`uiamApiKey`. So version 14 is wrapped in `encryptedSavedObjects.createModelVersion` to decrypt → transform → re-encrypt. Without it, every touched rule would fail API-key decryption and stop executing after upgrade.

## Residual risk

- **Not verified by tooling.** This worktree isn't bootstrapped, so `node scripts/type_check`, eslint, and Jest are unavailable. Correctness is from static reading; each type and call shape was checked against an existing in-repo precedent (`connector_token_model_versions.ts`, `migrations/8.2/index.ts`, `examples/eso_model_version_example`).
- **Missing CI fixture.** `packages/kbn-check-saved-objects-cli/src/migrations/__fixtures__/alert/` stops at `10.13.0.json`; version 14 needs a `10.14.0.json`. I did not add it — it's test data consumed by `test_upgrade.ts`/`test_rollback.ts`, which the "do not add or modify tests" constraint excludes, and it's generated by `node scripts/check_saved_objects --fix` against a live ES+Kibana. The "Check changes in Saved Objects" CI step will need that run.
- **Non-canonical severity labels get lowercased too.** The spec is "normalize to lowercase; leave unchanged only if already lowercase or absent," so a rule type using `params.severity` for a differently-cased label would be rewritten. The framework only recognizes the four canonical values (`SEVERITY_MAP`), so this should be inert, but it is a behavior change for such rules if any exist.
- **Upgrade cost.** Version 14 decrypts and re-encrypts every rule, not just the ones it rewrites — inherent to `createModelVersion`. Rules whose API key already fails to decrypt have their encrypted attributes stripped rather than failing the upgrade, matching the pre-existing `createEsoMigration` behavior.
