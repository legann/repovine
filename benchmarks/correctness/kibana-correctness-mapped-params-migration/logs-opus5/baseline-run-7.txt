The non-obvious part: `params` is in `RuleAttributesIncludedInAAD` (`saved_objects/index.ts:58-77`), and AAD is `stableStringify(…)` over attribute **values** (`encrypted_saved_objects_service.ts:642-662`). A plain `data_backfill` would rewrite `params.severity` and leave every migrated rule's `apiKey`/`uiamApiKey` undecryptable. MV14 therefore goes through `encryptedSavedObjects.createModelVersion`, which decrypts → transforms → re-encrypts (`create_model_version.ts:84-140`), with the ESO registration pinned as both `inputType` and `outputType` since encryption/AAD membership is unchanged. This mirrors `actions/server/saved_objects/model_versions/connector_token_model_versions.ts`. I verified the pinned registration matches the live one exactly (type, 2 encrypted attrs, all 18 AAD attrs).

The backfill returns `[expr]` unless `severity` is a string that differs from its lowercase form; backfill results are deep-merged (`build_transform_fn.ts:61`), so sibling params survive.

## Residual risk

- **All rules are re-encrypted, not just affected ones.** `createModelVersion` collapses changes into one unconditional transform — there's no per-document opt-out, so every rule doc is decrypted and re-encrypted at upgrade. Cost is proportional to rule count.
- **`shouldTransformIfDecryptionFails: true`.** A rule whose API key already fails to decrypt is migrated with encrypted attributes stripped and a logged warning, rather than failing the whole upgrade. Such a rule needs its API key regenerated (a rule edit). The alternative would abort the entire SO migration; `true` matches both in-repo precedents.
- **Not verified by execution.** This worktree has no `node_modules`, so `type_check`, `eslint`, and Jest could not run. I verified imports, exported type names, and the required-vs-optional `attributes` field statically. Per instructions, no tests were added or modified.
- Serverless ZDT is single-stage-safe: the ESO registration is unchanged, so a co-running previous version builds AAD from the migrated attributes and still decrypts. CI's "Check changes in Saved Objects" will report a new model version for `alert` (expected; baselines live in a GCS bucket, nothing committed to update).
