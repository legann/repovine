## Where I localized it

The `severity` param lives on the alerting **rule** saved object (`alert`), registered in `x-pack/platform/plugins/shared/alerting/server/saved_objects/index.ts:115`. The decisive constraint is at `index.ts:58-77`: `alert` is an **encrypted saved object** and `params` is in `RuleAttributesIncludedInAAD`. Rewriting `params.severity` changes the AAD, so a plain model version would make `apiKey`/`uiamApiKey` undecryptable on every rule it touched. The migration therefore goes through `encryptedSavedObjects.createModelVersion` (decrypt → transform → re-encrypt), following the in-repo precedent at `x-pack/platform/plugins/shared/actions/server/saved_objects/model_versions/connector_token_model_versions.ts:56`.

## Residual risk

- `shouldTransformIfDecryptionFails: true` matches the plugin's own precedent (`migrations/utils.ts:31`) and prevents one undecryptable rule from failing the whole upgrade — but for such rules the ciphertext is stripped permanently, so a later restore of an old decryption key can no longer recover the API key. The alternative aborts the upgrade, which I judged worse.
- `createModelVersion` has no per-document predicate (unlike legacy `createMigration`'s `isMigrationNeededPredicate`), so v14 decrypts and re-encrypts **every** rule, not only miscased ones. Correct, but it adds a crypto pass over all rules at upgrade.
- The ESO registration in `rule_model_versions.ts` is a deliberate pinned copy of the one in `setupSavedObjects`. It must not be updated when the live registration changes; a future AAD change needs a new pinned pair, as in `connector_token_model_versions.ts`. I added a comment saying so.
- Lowercasing is unconditional for any string `severity`, per the task statement. A rule type storing a case-sensitive `severity` outside the four canonical values would also be lowercased.
