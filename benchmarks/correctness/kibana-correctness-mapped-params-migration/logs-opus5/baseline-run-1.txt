## Where I localized it

The `severity` param lives on the alerting **rule** saved object (`alert`), under `attributes.params` — a `flattened` field (`common/saved_objects/rules/mappings.ts:91`) typed as `[expr]` (`schemas/raw_rule/v1.ts:277`). Detection rules and any other rule type that stores `severity` all land here, so a single model version on `alert` covers them.

The decisive constraint: **`params` is in the rule's encryption AAD** (`saved_objects/index.ts:67`), and AAD is built from attribute *values* (`encrypted_saved_objects_service.ts:661`). Rewriting `params.severity` with a plain model version would leave every touched rule's `apiKey` permanently undecryptable. So the change is wrapped in `encryptedSavedObjects.createModelVersion`, which decrypts with the pre-transform AAD and re-encrypts with the post-transform AAD.

The transform returns the document untouched when `severity` is absent, non-string, or already lowercase.

## Residual risk

  - `encrypted_saved_objects/integration_tests/ci_checks/check_registered_types.test.ts` — the `modelVersionMap` inline snapshot needs `[expr]` (jest_integration `-u`). The `hashMap` `"alert"` entry should *not* change: it hashes the ESO registration (`encrypted_saved_objects_service.ts:170`), which I kept byte-identical.
  - `packages/kbn-check-saved-objects-cli/src/migrations/__fixtures__/alert/10.14.0.json` — required for any new model version (`get_type_fixtures.ts:20`). Since MV14 has no shape change, it's `10.13.0.json` with its two keys renamed to `10.13.0`/`10.14.0`; `[expr]` generates it.
- **Every rule is decrypted and re-encrypted on upgrade**, not just mis-cased ones — `createModelVersion` has no per-document predicate (unlike legacy `createMigration`'s `isMigrationNeededPredicate`). Migration cost scales with total rule count, and ciphertext changes for all rules. Attribute values for already-lowercase rules are byte-identical.
- **`shouldTransformIfDecryptionFails: true`** means a rule whose `apiKey` can't be decrypted has its encrypted attributes stripped with a logged warning. This matches every existing rule migration (`migrations/utils.ts:31`), and such keys were already unusable.
- **Serverless ZDT is safe**: the AAD attribute *set* is unchanged, so the previous Kibana version constructs the same AAD and decrypts migrated rules.
- Non-canonical values (e.g. `Sev1`) are lowercased, not mapped to a canonical label — that's what "normalize to lowercase" specifies.
