## Where I localized it

The `severity` param lives inside the freeform `params` record of the **`alert` saved object** (`schemas/raw_rule/v1.ts:280` — `[expr]`), whose model versions are defined in `server/saved_objects/model_versions/rule_model_versions.ts`. So the migration is a new **model version 14** on that type.

The decisive constraint: `alert` is an encrypted saved object (`apiKey`, `uiamApiKey` — `saved_objects/index.ts:51`, `:306`), and **`params` is part of the AAD** (`saved_objects/index.ts:58-68`). AAD covers attribute *values*, so rewriting `params.severity` in a plain `data_backfill` would leave every touched rule's API key permanently undecryptable. The change is therefore wrapped in `encryptedSavedObjects.createModelVersion(…)` (decrypt → transform → re-encrypt), following `actions/server/saved_objects/model_versions/connector_token_model_versions.ts`.

## Residual risk

1. The transform runs on **every** rule doc, not just mixed-case ones — `createModelVersion` takes no predicate. Extra decrypt/re-encrypt cost on large rule sets; correctness unaffected.
2. `shouldTransformIfDecryptionFails: true` means a rule with an undecryptable `apiKey` migrates with its encrypted attributes stripped (warning logged) rather than blocking the upgrade. Such a rule already could not execute. This mirrors the existing alerting migrations.
3. Rules that had non-canonical casing kept a stale `mapped_params.severity` (it was written as `''` on a `SEVERITY_MAP` miss) until their next write — severity filtering/sorting for them is no better and no worse than before.
4. `params` is mapped `flattened` (`common/saved_objects/rules/mappings.ts:91-94`), so an exact-term query for `params.severity: "High"` stops matching after the upgrade. That is the intent of the normalization.
5. Serverless/ZDT is single-stage-safe: the AAD attribute set and ESO registration are unchanged, so the previous Kibana version still decrypts migrated docs.
