## Two things that made the naive patch wrong

**1. `params` is in the rule's decryption AAD.** `RuleAttributesIncludedInAAD` (`saved_objects/index.ts:58`) lists both `params` and `mapped_params`, and `getAAD` stable-stringifies AAD attribute **keys and values**. Rewriting `params.severity` with a plain `data_backfill` would invalidate the stored `apiKey` ciphertext — every migrated rule with an API key would stop running. The patch wraps MV14 in `encryptedSavedObjects.createModelVersion(…)`, which decrypts before and re-encrypts after the transform. The AAD *attribute list* is unchanged, so both registrations are the same object.

**2. `severity` is a mapped param.** `mapped_params.severity` stores a sortable projection (`'60-high'`) via `SEVERITY_MAP`, whose keys are lowercase-only — so `'High'` currently projects to `''`. The find path rewrites sorts/search fields/KQL filters on `params.severity` to `mapped_params.severity` (`mapped_params_utils.ts`), and the write paths that keep them in sync don't run during migration. Normalizing `params` alone would leave the projection at `''`, so the rule still wouldn't match a `severity: high` filter. The transform recomputes it with `getModifiedValue` — the same helper `getMappedParams` uses. Precedent: the 8.2 migration (`migrations/8.2/index.ts`) is itself an ESO migration that computes `mapped_params`.

Rules with no `severity`, a non-string `severity`, or an already-lowercase one return the document by reference, untouched.

## Residual risk

- **Not verified by tooling.** `node scripts/type_check`, eslint, and Jest are blocked in this worktree (no `node_modules`), so everything above is from static reading. The changes need a real type-check and test run.
- **Every rule is re-encrypted**, including untouched ones — inherent to `createModelVersion` (it merges changes into one decrypt→transform→encrypt pass). This adds upgrade cost proportional to rule count.
- **`shouldTransformIfDecryptionFails: true`** means a rule whose API key can't be decrypted has its encrypted attributes stripped rather than failing the whole index migration. This matches the plugin's existing convention (`createEsoMigration` hardcodes `shouldMigrateIfDecryptionFails: true`); such rules are already non-functional, but the failure mode shifts to "API key missing".
- **`mapped_params` is created** if a rule has a mixed-case severity but no projection object. Practically unreachable — the 8.2 migration backfilled it for every rule with a mapped param — and the created value matches what a writer would persist.
- **Serverless/ZDT** should be single-stage: the AAD attribute list is unchanged, so the previous Kibana version builds AAD identically and reads a canonical lowercase value it already handles. Worth a second opinion from the alerting team before release.
