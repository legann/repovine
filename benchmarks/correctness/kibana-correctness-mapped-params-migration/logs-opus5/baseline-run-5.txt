## Where I localized it

The `severity` param lives on the **`alert` saved object** at `attributes.params.severity`. Confirmed against the security-solution rule schema, where `severity: Severity` is a top-level rule param and `[expr]` (`kbn-securitysolution-io-ts-alerting-types/src/severity/index.ts:11`) — exactly the four canonical values.

The decisive constraint: **`params` is in the rule's AAD** (`saved_objects/index.ts:58-77`). Rewriting it with a plain `data_backfill` would leave `apiKey`/`uiamApiKey` encrypted under the old AAD and permanently undecryptable for every affected rule. So model version 14 is wrapped in `encryptedSavedObjects.createModelVersion(…)`, which decrypts → transforms → re-encrypts in one pass.

The *other* snapshot in that file — the registration hash map — is unaffected, because `createModelVersion` registers into a throwaway service, not the shared one (`encrypted_saved_objects/server/plugin.ts:162-173`).
2. **Rules that already fail to decrypt** get their encrypted attributes stripped with a logged warning rather than failing the upgrade. That matches every existing rule ESO migration (`shouldMigrateIfDecryptionFails: true` in `migrations/utils.ts:31`).
3. **Serverless ZDT is safe**: the AAD attribute *set* is unchanged — only the value of an in-AAD attribute — so an older Kibana builds AAD from the migrated document and decrypts normally.
