## 1. Patch

**File changed:** `platform/backend/src/models/tool.ts` — `ToolModel.slugifyName` (plus a `node:crypto` import).

`slugifyName` is the one function that turns an MCP-exposed tool's name into the platform identifier (stored as `tools.name`). It lowercased, converted whitespace to `_`, and **stripped** every other character. A tool name made entirely of stripped characters (non-ASCII scripts, emoji, punctuation) collapsed to an empty tool segment, so the identifier degenerated to `[expr]`. Every such tool on a server shared that one string, and `bulkCreateToolsIfNotExists` (dedups by `name`) dropped all but one row — "cannot be addressed individually."

The fix slugifies the server and tool segments independently and, **only when the tool segment collapses to empty for a non-empty raw name**, substitutes a deterministic 16-hex SHA-256 suffix of the raw name. Non-empty segments are untouched.

## 2. Where names become identifiers / scope

**The single conversion point** (all callers pass a raw upstream `tool.name`):

Fixing `slugifyName` fixes every caller; no code builds an MCP tool identifier by hand (grep for manual `[expr]` construction outside the agent/`slugify` paths returns nothing).

**Deliberately left unchanged, with proof it's out of scope:**

- **`buildAgentDelegationToolName` → `slugify()`** (`shared/agents.ts:36`): a different identifier space. Its own docstring (`[expr]`): *"These are dynamically generated and are not Archestra MCP tools."* The task scopes to "when an MCP server exposes a tool." Its analogous non-ASCII collapse (`agent__`) is a separate concern.
- **`resolveActualToolName` / `stripServerPrefix`** (`[expr]`): these **recover** the upstream name from an identifier for invocation; they don't mint identifiers. `stripServerPrefix` calls `slugifyName(…)`, whose output (`[expr]`) is unchanged by my guard (`[expr]` → skip hash), so this path is byte-identical.
- **Non-empty collisions** (e.g. `list all repos` vs `list_all_repos`, or `tool@1` vs `[expr]`, all yielding a valid non-empty slug): left as-is. Constraint: *"Do not change the identifier of a tool whose name already yields a usable one."* Each such name already yields a usable, pattern-valid identifier; `slugifyName` is a pure function of `[expr]` with no visibility into siblings, so it cannot disambiguate them without rewriting an already-usable identifier. Only the empty-segment case carries **zero** tool-identifying information and is therefore never "usable," making it the sole safe-to-change set.

**Behavior preservation is provable:** `slug(…)` because `__` is preserved and no whitespace run crosses the literal separator. So splitting into segments is byte-identical to the old combined slugify for every non-empty-tool input — including the existing `[expr]` test (guarded off) and all 11 `slugifyName` tests.

## 3. Summary

- **Changed behavior:** MCP tools whose names slugified to nothing (non-ASCII/emoji/all-punctuation) previously all collapsed to `[expr]` and overwrote each other; each now gets a distinct `[expr]` identifier. Every tool whose name already produced a non-empty slug keeps its exact current identifier.
- **Files touched:** one — `platform/backend/src/models/tool.ts` (the `slugifyName` function + a `node:crypto` import). No tests added or modified.
- **Residual risk:**
  - The 16-hex (64-bit) suffix could theoretically collide with another empty-slug tool on the same server or a real tool literally named that hex string — birthday-negligible at realistic per-server tool counts; widen the slice if ever a concern.
  - `unslugifyName` now returns the hash (not the original non-ASCII name) for these tools, and `resolveActualToolName` still can't map a hash back to the upstream's raw name — so these specific tools remain non-invokable **upstream**. That was already true (they were indistinguishable before); the fix restores distinct *addressability* (listing, assignment, policies). Full upstream invocation for non-ASCII names would need the raw name stored in a column (schema change), which is beyond the "change implementation only" scope.
