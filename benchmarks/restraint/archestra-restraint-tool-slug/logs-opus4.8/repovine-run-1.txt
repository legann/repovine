## Summary

### The bug
`ToolModel.slugifyName(…)` (`platform/backend/src/models/tool.ts:80`) builds a tool's platform identifier — `[expr]` → lowercase → whitespace→`_` → strip `[expr]`. That strip is lossy, so two distinct raw names (differing only in stripped punctuation/whitespace/case, or both stripping to the bare `server__` prefix) reduce to the same `tools.name`. Because the `[expr]` unique constraint is **NULLS-DISTINCT** for external tools, colliding names produce indistinguishable same-name rows that are addressed identically on the wire — "cannot be addressed individually."

### Where names become identifiers, and what changed
`slugifyName` is a **per-tool-pair transform with no view of siblings** (per the module's boundary annotation), so distinctness belongs to the layer that assembles a server's tool set — not the codec. I added a set-aware wrapper and routed every external-discovery batch through it.

| File | Change |
|---|---|
| `models/tool.ts` | **New** `ToolModel.slugifyServerToolNames(…)` (tool.ts:105). Reserves every base slug; a base unique in the set is returned unchanged; only shared bases are disambiguated — first keeps the base, later ones get the smallest free `-N` suffix (never colliding with any reserved base). `slugifyName`/`unslugifyName` are byte-for-byte unchanged. |
| `routes/mcp-server.ts` | Local install (761) + remote install (927) discovery batches use the set helper. |
| `archestra-mcp-server/mcp-servers.ts` | Post-deploy local (1450) + remote (1506) discovery batches use it. |
| `services/mcp-reinstall.ts` | Reinstall sync batch (405) uses it; `rawToolName: tool.name` preserved for raw-name matching. |

A unique base is returned untouched, so working tools keep their exact identifier. |

### Changed behavior
A server exposing tools whose names collide now yields one distinct `tools.name` per tool. The first tool of a colliding group keeps the base slug; later ones get `-2`, `-3`, …. **Every non-colliding tool's identifier is byte-identical to today** and resolves through the unchanged codec/wire exactly as before. No DB migration — distinct names are distinct rows under the existing schema.

### Residual risk
- **Disambiguated slugs don't round-trip upstream.** `server__tool-2` unslugifies to `tool-2`, which the upstream server won't recognize on `tools/call`. This matches the annotation's explicit scope: colliding/degenerate tools were *already* unresolvable upstream; the fix makes them individually addressable **within the platform** (distinct rows, policies, assignments, guardrails UI), which is what the bug was about. The wire is not extended to route them.
- **Within-batch dedup only.** A server exposes its full tool list per discovery, so colliding siblings are always co-present and handled; a collision against a pre-existing row outside the current batch is not.
- **Reinstall stability of suffixed siblings.** A `-N`-suffixed sibling may not stably re-match `syncToolsForCatalog`'s existing-row raw-name extraction, so it can be recreated across reinstalls (new ID, default policies). Affects only colliding tools, which had no stable identity before; non-colliding tools match by their real `rawToolName` and are stable.
