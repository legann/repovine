## Summary

MCP tool names become platform identifiers through `ToolModel.slugifyName(…)` → `[expr]` (builds `[expr]`, whitespace→`_`, strips `[regex]`; `[value]` and `[value]` both collapse to `[value]` under the `[value]` prefix). The write layer then stores/returns those tools under one`tools.name`, so they can't be addressed individually.

The fix adds a **set-aware** pass at the discovery write layer that sees a server's whole tool list. Slugs that are unique in the batch are returned byte-for-byte (every already-working identifier is untouched, including a lone bare-prefix tool); only members of a colliding group are rewritten, each with a deterministic `sha256(…)` short-hash suffix (bump-on-residual-clash) so re-discovery of the same set reproduces the same identifiers.

## Residual risk

- **Reinstall re-sync** still stores colliding tools under a shared slug and may delete the distinct rows first-install created. Scoped to multi-tenant catalogs whose server exposes colliding tools — an edge case that was fully broken before this change, so not a regression from baseline; the primary install/discovery path is fixed.
- **No upstream round-trip**: disambiguated slugs don't map back to a raw upstream name, so colliding/degenerate tools stay unresolvable by the gateway/proxy wire (invariant 7, explicitly out of scope). The fix makes them distinct, addressable DB rows — visible and governable in the guardrails UI, assignable, policy-bearing — not upstream-callable.
- **Suffix stability**: deterministic per raw name, so re-discovering the same set is stable; if the colliding *set* changes membership (a sibling appears/disappears, flipping a tool between lone and colliding), that tool's identifier can change. Inherent to the "never touch a working identifier" constraint.
- **Verification limits**: the worktree is not bootstrapped, so type-check/lint/tests couldn't run. Verified statically — `tsconfig` lacks `noUncheckedIndexedAccess` (so `[expr]` is `string`), the change matches the repo's existing `createHash(…)` convention, only `mcp-reinstall.test.ts` mocks `ToolModel`, and byte-identical output for non-colliding names means existing distinct-name discovery tests are unaffected.
