## Summary

MCP-server tool names are turned into the platform's tool identifier in exactly one place: **`ToolModel.slugifyName(…)`** in `platform/backend/src/models/tool.ts`. It builds the `tools.name` value that uniquely identifies a tool per `[expr]`.

The old code lowercased, replaced whitespace with `_`, then **deleted** every remaining disallowed character. Deletion is lossy, so distinct raw names collapsed to one identifier — e.g. `get.user` and `getuser` both → `srv__getuser`, and any non-latin names (`日本語`, `한국어`, `[expr]`) all → `srv__` (bare prefix). The insert paths use `[expr]` (`tool.ts:767`, `tool.ts:2196`), so the second colliding tool was silently dropped and could not be addressed individually.

### The fix (implementation only)
`slugifyName` now slugifies the server prefix and tool name independently and rejoins with the separator (behaviorally identical for non-lossy input, since the transforms are per-character and `__` is fixed). When the disallowed-character removal actually drops characters from the tool name, it appends a deterministic 12-hex-char SHA-256 suffix of the raw name. Whitespace-only replacement is not treated as lossy, so it doesn't trigger a suffix.

Constraint compliance, checked against every pinned test case and collision scenario (`scratchpad/verify.mjs`):
- **Working identifiers unchanged** — names already in `[expr]` lose nothing, so no suffix; output is byte-identical to before (`list_repos`, `ListRepos`, `atlassianUserInfo`, `get-user`, … all `KEPT`). All 10 exact-value tests and 5 pattern-only tests in `tool.test.ts` pass.
- **Colliding tools now distinct** — `get.user`/`get/user`/`get:user` get separate suffixed ids while the clean `getuser` keeps its exact `srv__getuser`; non-latin names each get a distinct id.
- Deterministic and stable across calls (needed so reinstall/clone don't churn).

### Files changed
- `platform/backend/src/models/tool.ts` — added `[expr]`; rewrote `slugifyName`. No other files.

### Residual risk
- **Distinctness is hash-based**, not a bijective encoding: two different raw names could share an identifier only on a 48-bit SHA-256 prefix collision — negligible for a per-catalog tool set. A suffixed tool could collide with a clean tool literally named `[expr]`; equally negligible.
- **Invocation of these previously-broken tools is not restored by this patch** — `resolveActualToolName` still can't reconstruct a non-`[expr]` upstream name (unchanged, and documented above). The patch delivers exactly what was asked: each such tool now gets a distinct, individually-addressable identifier, and no already-working tool's identifier changes.
