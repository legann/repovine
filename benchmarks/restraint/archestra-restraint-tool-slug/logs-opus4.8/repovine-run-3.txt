## Summary

Fixed the tool-name → identifier collision so colliding tools get distinct identifiers, while every already-working identifier is preserved byte-for-byte.

### Where tool names become identifiers

`ToolModel.slugifyName(…)` (`models/tool.ts:80`) builds `server__tool`, lowercases, and strips chars outside `[expr]`. It's a **per-tool-pair transform with no view of sibling tools**, so names that strip to empty all collapse onto the bare `server__`, and distinct raw names can reduce to the same slug. Because the `tools` composite unique index is NULLS-DISTINCT for regular MCP tools (`database/schemas/tool.ts:83-90`), these collisions persist as **multiple rows sharing one `name`** — unaddressable individually.

The set — the only place a collision is visible — exists at the discovery **write layer** that maps a server's whole tool list to rows.

| `backend/src/models/tool.ts` | New `slugifyServerToolNames(…)`: composes `slugifyName` over the set; returns unique slugs verbatim, disambiguates only collisions with a deterministic `sha256(…)` suffix. `slugifyName`/`unslugifyName` unchanged. |

Determinism: the suffix derives only from the raw name, so re-discovery yields the same identifier regardless of batch order; a unique slug is never touched (reserved up front), so working identifiers can't be displaced.

### Residual risk

- **Reinstall re-collapse (main risk, low severity):** a pod-restart/catalog reinstall runs the untouched raw-name-matching sync, which can re-collapse newly-distinct colliding tools (and drop the extra rows' assignments), returning them to the pre-fix state. Non-colliding tools are unaffected; it never leaves things worse than today's always-collapsed baseline. Repairing it requires extending the frozen raw-name matching contract.
- **No upstream round-trip (by design):** `[expr]` doesn't unslugify to the original raw name, so the gateway can't route a call to it upstream. These names were already unresolvable upstream; the fix makes the tools individually addressable *within* the platform (listing, assignment, policy), which is the stated goal.
- **Length:** disambiguation adds ≤13 chars; a base slug already near the 128-char provider limit could exceed it. Pre-existing (`slugifyName` doesn't cap length either) and only for colliding tools.
