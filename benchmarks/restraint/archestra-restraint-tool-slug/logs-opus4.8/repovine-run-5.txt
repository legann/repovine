## Summary

MCP tool names become identifiers at **`ToolModel.slugifyName(…)`** (`backend/src/models/tool.ts:80`). It builds `server__tool`, lowercases, and strips every char outside `[expr]`. Names that reduce to the same string collide on one `tools.name`; the per‑catalog unique constraint (`database/schemas/tool.ts:83`) then collapses them into a single row. The dominant case: names that strip to empty all become the bare `server__`. Such tools cannot be addressed individually.

`slugifyName` is a per‑pair transform with no view of sibling tools (and is pinned by `tool.test.ts:105` + flagged a frozen boundary), so the distinctness fix belongs in the layer that sees a server's tools as a set — the discovery/write batch.

### What changed

| File | Change |
|---|---|
| `backend/src/utils/mcp-tool-name.ts` | **New.** Pure `[expr]`. Unique slugs (incl. a lone `server__`) pass through byte‑identical; colliding slugs get a stable `[expr]` suffix, guarded against landing on another tool's name. |
| `backend/src/routes/mcp-server.ts` | Local (`:762`) and remote (`:930`) discovery batches route slugs through the helper. |
| `backend/src/services/mcp-reinstall.ts` | `syncToolsForServer` batch (`:406`); `rawToolName: tool.name` left unchanged (sync test contract). |
| `backend/src/archestra-mcp-server/mcp-servers.ts` | `discoverLocalMcpServerTools` (`:1451`) and `discoverRemoteMcpServerTools` (`:1512`) batches. |

Suffix derives only from the raw name, so assignment is order‑independent and stable across re‑discovery. All 5 batch sites feed `bulkCreateToolsIfNotExists` / `syncToolsForCatalog` unchanged.
