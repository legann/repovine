## Deliverables

### 1. Patch implemented
`platform/backend/src/models/tool.ts` — `ToolModel.slugifyName(…)`.

The old body stripped every character outside `[expr]` (deleting, not replacing them). Two tool names on one server that differ only in stripped characters (e.g. non-ASCII scripts `工具`/`导航`, or `a@b`/`[expr]`) collapsed to one slug; the `[expr]` unique constraint then dropped all but one row, so the rest were unaddressable.

The fix keeps the exact same transform, then:
- If the **tool-name portion** loses no character (`[expr]`), return the slug byte-identical — this is the already-usable path.
- Otherwise append `[expr]`, a deterministic per-name suffix, so distinct raw names get distinct identifiers.

The trigger is scoped to the tool portion, so server-name stripping (shared by every tool of a server, never collides two tools) never adds a suffix — that keeps the existing `slugifyName` tests (which pin server-name stripping like `[expr]` → `[expr]`) unchanged.

### 2. Where names become identifiers / what I left alone
`ToolModel.slugifyName` is the single conversion point. Every discovery/create/reinstall caller funnels through it: `[expr]` and `[expr]` (→ `bulkCreateToolsIfNotExists`), `services/mcp-reinstall.ts:406` (→ `syncToolsForCatalog`), `services/apps/app-mcp-backing.ts:73`, `models/tool.ts:839` (clone). **Changed: `tool.ts` only.**

Deliberately unchanged, with the source that scopes each out:
- **`bulkCreateToolsIfNotExists` (primary discovery, `tool.ts:677`)** — matches by full `name` (`[expr]`). Distinct slugs make both rows insert and survive; no logic change needed. This is what fixes the bug.
- **`syncToolsForCatalog` (reinstall/rename, `tool.ts:2007`)** — matches on `rawToolName`/part-after-`__` (`[expr]`). Lossy names already fail to round-trip here *today* (existing key `toolname` vs raw key `tool@name`), independent of my change; its tests (`tool.test.ts:2185-2305`) use only clean names. Rename semantics are unrelated to the collision. Left as-is.
- **Bedrock adapter (`routes/proxy/adapters/bedrock.ts`)** — a per-request shim to Bedrock's stricter `[expr]` with its own reverse map (`toOriginal`, `bedrock.ts:210`) and its own identical `[expr]` dedup (`appendToolNameHash`, `bedrock.ts:239-250`; asserted `bedrock.ts:194`). It renames *already-platform* identifiers and reverses them per response, so it is a separate layer, not "the identifier the platform uses." My 8-hex choice matches this house convention.
- **Upstream execution mapping (`clients/mcp-client.ts:2118-2157`)** — recovers the raw upstream name by stripping the prefix and case-insensitively matching the server's live tool list (`[expr]`); the stripped form of a lossy name is never in that map, so such tools were already non-executable upstream. Unchanged.
- **`shared/utils.ts` `slugify`/`urlSlugify`/`buildFullToolName`** — agent/URL slugs and unsanitized display reconstruction, different charset/purpose. Not the tool identifier.
