## 1. Where tool names become identifiers

`ToolModel.slugifyName(…)` in `platform/backend/src/models/tool.ts` is the single function that turns an MCP-server-exposed tool name into the platform identifier (the `tools.name` column, which has a unique `[expr]` index). All eight discovery/proxy/app-backing call sites funnel through it:

| Call site | Path |
|---|---|
| `[expr]` | K8s + remote server tool discovery |
| `[expr]` | server install / re-list |
| `services/mcp-reinstall.ts:406` | reinstall re-discovery |
| `services/apps/app-mcp-backing.ts:73` | app-backed tool naming |
| `clients/mcp-client.ts:2120` | `slugifyName(…)` → server-prefix stripping |
| `models/tool.ts:839` | clone-catalog tool naming |

## 2. The bug and the fix

`[expr]` **deletes** disallowed characters. A tool name written entirely in a non-Latin script, emoji, or punctuation (e.g. `日本語`, `検索`, `[expr]`, `[expr]`) strips to nothing, so the slug degenerates to `[expr]` with an empty tool segment. Every such tool on one server produces the identical `[expr]` string; the unique index + `onConflictDoNothing` then drop all but one row — they cannot be addressed individually.

The fix (`tool.ts:88-107`): when the raw tool name is non-empty **but** its slugified segment is empty, append a deterministic 16-hex-char `sha256` of the raw name (following the existing in-repo pattern from `chatops-manager.ts`/`service-account.ts`). Each such tool now gets a distinct, deterministic, pattern-valid identifier.

**Constraints held:** any tool whose name already yields a non-empty segment is byte-for-byte unchanged (guard `[expr]`), and the literal empty-input case `slugifyName(…)` still returns `[expr]` (guard `[expr]`), preserving the prefix-generation use in `stripServerPrefix`. Verified against all 15 pinned assertions in `tool.test.ts` and the collision case (5 formerly-identical names → 5 distinct identifiers).

**Files changed:** `platform/backend/src/models/tool.ts` (added `node:crypto` import; rewrote `slugifyName`).

## 4. Summary

- **Changed behavior:** tool names that previously slugified to an empty segment (non-Latin/emoji/punctuation-only) now receive a distinct, deterministic hash-suffixed identifier instead of all collapsing to `[expr]`. Every already-working tool keeps its exact current identifier.
- **Files touched:** `platform/backend/src/models/tool.ts` only — one import, one function.
