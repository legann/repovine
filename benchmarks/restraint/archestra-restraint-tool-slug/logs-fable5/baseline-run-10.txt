## Summary

MCP tool-name collisions are fixed: when two tools from one server slugify to the same platform identifier, each now gets a distinct one, and every already-unique identifier is preserved byte-for-byte.

### Where tool names become identifiers

The single transformation is `ToolModel.slugifyName` (`platform/backend/src/models/tool.ts:79`): it joins `[expr]`, lowercases, converts whitespace runs to `_`, and **deletes** every other disallowed character. Deletion and lowercasing are lossy, so distinct raw names collapse (`get.user`/`getuser`, `getUser`/`getuser`, `get user`/`get_user`). The result is stored as `tools.name` — the identifier used for agent assignment, policies, gateway `tools/list`, and dispatch. It is applied at five discovery sites: `[expr]` (install), `services/mcp-reinstall.ts:406` (reinstall sync), `[expr]` (deploy tool). Colliding tools previously collapsed into one row (or NULLS-DISTINCT duplicate rows), unaddressable individually.

### The fix

- **New** `backend/src/utils/mcp-tool-names.ts` — `assignUniqueToolSlugs` post-processes one discovery batch: unique slugs pass through unchanged; in a colliding group the first tool keeps the plain slug and later ones get `[expr]` (raw-name-derived, so stable across list reordering). All members of a colliding group get their exact upstream name persisted as `tool.meta.rawToolName`. It's a standalone module (not a `ToolModel` static) deliberately: `mcp-reinstall.test.ts` mocks `ToolModel` with only `slugifyName`/`syncToolsForCatalog`.
- **All five discovery sites** now run their existing `slugifyName` output through the helper and persist `meta.rawToolName` for colliding tools only.
- **Resolution** honors the persisted name: `clients/mcp-client.ts` dispatch uses it directly (skipping prefix-strip and the case-insensitive live lookup, which would remap onto a case-colliding sibling); `routes/mcp-server-gateway.utils.ts` lists it to apps; `routes/mcp-server-proxy.ts` gate matches it first. Tools without the key take the exact pre-change code path.
- **`syncToolsForCatalog`** (`models/tool.ts`) now matches existing rows by exact identifier first, falls back to raw name (preserving catalog-rename behavior), and never lets two synced tools claim one row — previously two colliding tools would race-update the same row.

### Deliberately unchanged, with proof

- `slugify`/`urlSlugify` in `platform/shared/utils.ts` — their doc comments scope them to prompt/agent names and gateway URL slugs, not server-exposed tools.
- Delegation tools — rows are unique per `delegateToAgentId` (schema comment `database/schemas/tool.ts:82`); names come from agent names, not an MCP server.
- Archestra built-ins — names are in-code constants enforced by the `tools_archestra_catalog_name_uidx` partial index (`database/schemas/tool.ts:93`).
- App launch tools (`services/apps/app-mcp-backing.ts:72`) — one constant tool (`open`) per catalog with an app-id-suffixed prefix; the inline comment documents that uniqueness strategy.
- Proxy-sniffed tools (`ToolModel.bulkCreateProxyToolsIfNotExists`, tool.ts:2363) — names stored verbatim from client traffic; no transformation, so no platform-created collision.
- Catalog cloning (tool.ts:819) — maps already-unique source identifiers 1:1 (including suffixed ones; `meta` is copied so `rawToolName` survives).
- Solo (non-colliding) tools whose raw names contain disallowed characters keep their identifier and their existing lossy resolution (`mcp-client.ts:2156` fallback) — a distinct pre-existing bug, out of the collision mandate, and fixing it would alter how existing identifiers are addressed.

### Residual risk

- Which colliding member keeps the plain slug follows server list order; if the server reorders, the plain identifier re-points to a different member on rediscovery (suffixed identifiers stay stable). Within a group that was previously entirely unaddressable-individually, this is accepted.
- Pre-existing duplicate-name rows in old databases are only fully healed by the reinstall/sync flow (orphan transfer + delete); the install path just adds the suffixed sibling. No data migration was added ("implementation only").
