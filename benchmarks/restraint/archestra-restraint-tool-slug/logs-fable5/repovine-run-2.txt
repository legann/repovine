## Where tool names become identifiers

The single codec is `ToolModel.slugifyName` (`platform/backend/src/models/tool.ts:80`): `[expr]`, lowercased, whitespace→`_`, disallowed chars stripped. Its output is written to `tools.name` and is the platform's identifier for the tool. Because the transform is lossy (`getUser`, `Get.User`, `get user` all yield `server__getuser`) and the `tools` unique constraint is NULLS-DISTINCT for catalog tools (`platform/backend/src/database/schemas/tool.ts:83-97`, see the comment there), colliding tools silently persisted as multiple rows sharing one name — addressable only as one.

## The fix

New pure utility `dedupeSlugs` in `platform/shared/utils.ts`: given a list of slugs, the first occurrence of each value is returned unchanged; each later duplicate gets the lowest `_n` (n≥2) suffix not occupied by any other slug in the list — so a suffix can never displace the base slug of a different tool (e.g. a genuine `getuser_2` tool keeps its identifier). It is applied at every place a server's tool batch is slugified for persistence — the layer that sees the tool set as a whole:

- `platform/backend/src/routes/mcp-server.ts` — local-install (async discovery) and remote-install batches
- `platform/backend/src/services/mcp-reinstall.ts` — `syncToolsForServer` reinstall batch
- `platform/backend/src/archestra-mcp-server/mcp-servers.ts` — `deploy_mcp_server` local and remote discovery batches
- `platform/backend/src/models/tool.ts` — `cloneToolsAndPoliciesFromCatalog`, where un-prefixing + re-slugifying source names can also collide (raw names containing `__`); distinct clone names additionally fix the source→clone policy remap, which previously collapsed on duplicate names

The clone-reconciliation sets (`discoveredToolNames`) are derived from these batches, so they carry the disambiguated names automatically. I initially added the batch logic as a `ToolModel` static, then moved it to the shared utility because `mcp-reinstall.test.ts` mocks `ToolModel` with only `slugifyName` present — the sites therefore call the (possibly mocked) `slugifyName` per tool and dedupe with the unmocked pure function, keeping every existing test's inputs and assertions intact.

## Deliberately unchanged, with proof

- **The codec** `slugifyName`/`unslugifyName` (`tool.ts:80-93`): per-pair transform with no sibling visibility; changing it would alter the identifier of a lone tool whose name strips to bare `server__` — today a working identifier (graph annotation on `mod:@backend/src/models/tool` pins this as a frozen boundary; unit tests at `tool.test.ts:43-151` pin its output).
- **Wire consumers**: gateway serving (`routes/mcp-server-gateway.utils.ts:60`), proxy matching (`routes/mcp-server-proxy.ts:168`), mcp-client prefix strip/name resolution (`clients/mcp-client.ts:2116-2130`). They resolve stored names against live upstream lists; the same boundary annotation freezes them — a suffixed slug is not routed upstream.
- **`syncToolsForCatalog` matching internals** (`tool.ts` around 2059-2106): untouched; its own comment already documents duplicate-row handling from "previous buggy reinstalls".
- **Proxy-sniffed tools** (`routes/proxy/utils/tools.ts:96-105`): client-supplied names persisted verbatim, deduped in-request at line 63 — no slugification occurs.
- **App launch tools** (`services/apps/app-mcp-backing.ts:72-83`): one tool per app server by construction, name already app-id-suffixed.
- **Delegation tools** (`tool.ts:2441-2485`): named from agent names, looked up by `delegateToAgentId`, not by name; not MCP-server-exposed.
- **Archestra built-ins**: fixed distinct short names, enforced by the partial unique index `tools_archestra_catalog_name_uidx`.

## Residual risk

- Suffix assignment follows the server's `tools/list` order; if a server reorders colliding tools between discoveries, the base slug and `_n` suffix swap between them. Non-colliding tools are unaffected in all cases.
- On reinstall, a suffixed tool's row is deleted and recreated (its name is stable but rawToolName-based matching in `syncToolsForCatalog` can't see it) — the same churn class that already affects any tool whose raw name doesn't survive slugification round-trip today. Fixing that matching was left out to avoid touching behavior of already-working tools.
- Pre-existing duplicate rows in the DB from past collisions are not migrated; the next discovery/reinstall converges them under the new distinct names.
- This worktree has no `node_modules` (verification commands are blocked), so type-check/lint/tests could not be executed; the change was verified by static reading, including against every affected test's mock setup and fixtures.
