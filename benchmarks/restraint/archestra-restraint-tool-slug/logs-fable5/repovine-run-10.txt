## What changed

MCP tool names become platform identifiers in one place: `ToolModel.slugifyName` (`platform/backend/src/models/tool.ts:80`) builds `[expr]`, lowercases it, and strips characters outside `[expr]`. Because stripping is lossy, distinct upstream names ("Foo"/"foo", "foo!"/"foo?", or names that strip to nothing) collapse to one slug, and the batch-insert layers (`bulkCreateToolsIfNotExists`, `syncToolsForCatalog`) then fold them into a single `tools` row — so those tools could not be addressed individually.

The fix follows the module's recorded invariant: distinctness is a property of the layer that sees a server's tools **as a set**, not of the per-pair codec. I added `ToolModel.slugifyNames(…)`, which keeps `slugifyName`'s exact output for every tool whose slug is unique in the batch (including a lone name that strips to the bare `server__` prefix) and gives only later duplicates a numeric suffix (`_2`, `_3`, …), skipping slugs already owned by other tools in the batch (so a real tool named `foo_2` keeps `server__foo_2`). Output is deterministic and first-occurrence-keeps-base, so every identifier that works today is byte-identical after the change.

## Files changed

- `platform/backend/src/models/tool.ts` — added `slugifyNames` beside the untouched codec; in `syncToolsForCatalog`, a matched existing row is now consumed from the raw-name lookup map. Without that, two case-collided batch entries both matched the same row and the second (now suffixed) entry would have *renamed* it, destroying the first tool's working identifier; consuming makes the second entry insert a new row instead. For batches without collisions each raw key occurs once, so this is behavior-neutral.
- `platform/backend/src/routes/mcp-server.ts` — both install discovery paths (local async at ~761, remote sync at ~927) now name batches via `slugifyNames`. The clone-reconciliation `discoveredToolNames` set is derived from the same deduplicated names, so it stays consistent.
- `platform/backend/src/archestra-mcp-server/mcp-servers.ts` — both `deploy_mcp_server` discovery paths (~1450, ~1506) use `slugifyNames`.
- `platform/backend/src/services/mcp-reinstall.ts` — `syncToolsForServer` (~405) uses `slugifyNames` before `syncToolsForCatalog`.

## Deliberately unchanged, with the source proving scope

- **`slugifyName`/`unslugifyName` codec and `parseFullToolName`** (`[expr]`, `[expr]`): the module annotation marks this the frozen stored-identity codec, and its invariant states a per-pair transform cannot distinguish a lone bare-prefix tool from colliding ones — fixing the degenerate case in the codec would change that lone tool's working `server__` identifier.
- **Wire consumers** — `mcp-client.ts` `stripServerPrefix`/`resolveActualToolName` (2118–2157), `mcp-server-gateway.utils.ts:60`, `[expr]`: the annotation freezes these serving/matching contracts and states explicitly that colliding tools are already unresolvable upstream and "the wire is not extended to route" disambiguated slugs.
- **`app-mcp-backing.ts:73`**: creates exactly one launch tool whose name embeds `app.id.slice(…)`; the in-code comment (lines 64–72) documents it as collision-proof by construction.
- **`cloneToolsAndPoliciesFromCatalog`** (`[expr]`): re-derives clone names from stored source names, which are unique per catalog; suffixed names are already slug-safe so the unslugify→reslugify round trip carries them verbatim (`src__foo_2` → `clone__foo_2`), preserving distinctness with no change.
- **Archestra built-in seeding**: names come from compile-time constant records and are additionally enforced by the partial unique index `tools_archestra_catalog_name_uidx` (`[expr]`).
- **`createToolIfNotExists`**: single-tool path, marked "used only in tests and should be removed" in-code; proxy-sniffed names are stored as received, not derived from a server's tool list.

## Residual risk

- Suffix assignment is positional: if an upstream server reorders its `tools/list` between discoveries, which colliding sibling owns `_2` can swap across runs (the identifier set itself stays stable). Unavoidable without storing raw names, which the frozen-consumer contract rules out.
- A suffixed identifier is fully addressable inside the platform (own row, policies, assignments, listing), but a call through it still resolves upstream via the frozen live-list matcher, which cannot single out one colliding sibling — the annotation records this as out of task scope, and those tools were equally unresolvable before.
- On reinstall, a case-collided `_2` row is recreated with a new row id each sync (its raw key can never match); the existing orphan-transfer machinery moves assignments over and the identifier persists — the same churn class the sync already exhibits for whitespace-named tools.
