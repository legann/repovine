## Summary

**Where tool names become identifiers.** `ToolModel.slugifyName` (`platform/backend/src/models/tool.ts:79`) builds every MCP tool identifier as `[expr]` lowercased, whitespace→`_`, with all other disallowed characters *removed*. The removal is lossy, so distinct raw names (`getUser` vs `get.user`) collapse into one identifier. Because the tools table's composite unique constraint contains NULL columns for MCP tools (`database/schemas/tool.ts:83`), such collisions previously produced duplicate same-name rows that could never be addressed individually. The identifier is slugified at five discovery sites and mapped back to the raw name at call time in `mcp-client.ts` (`stripServerPrefix` + `resolveActualToolName`).

**What changed.**
- **New** `backend/src/utils/tool-name-collision.ts` — `dedupeSlugifiedToolNames()`: given a discovery batch of (rawName, slug) pairs, unique slugs pass through byte-identical; within a collision group, the raw name the slug already resolves to today keeps it (identifier-safe charset first, all-lowercase spelling first, then byte order), and every other tool gets `[expr]`. Suffixes are functions of the raw name alone, so assignments are order-independent and survive rediscovery, catalog renames, and the clone/reconcile round-trip.
- **Applied at all five batch discovery sites**: `routes/mcp-server.ts` (local ~L762 and remote ~L936 install), `services/mcp-reinstall.ts` (`syncToolsForServer`), `archestra-mcp-server/mcp-servers.ts` (`discoverLocalMcpServerTools`, `discoverRemoteMcpServerTools`).
- **`models/tool.ts` `syncToolsForCatalog`** now matches incoming tools by the identifier's tool part (after the last `__`) — the same derivation used for existing rows — instead of preferring `rawToolName`. Without this, suffixed rows would be orphan-deleted and recreated (losing policies) on every reinstall; for all previously-matching inputs the keys are identical, and the pinned rename/removal tests remain satisfied. The `rawToolName` field stays (tests assert it is passed) and is marked deprecated.
- **`clients/mcp-client.ts` `resolveActualToolName`** additionally seeds the name map with each raw name's disambiguated slug part (same algorithm), so a suffixed identifier resolves to its exact raw name at call time. Literal lowercase entries are written last and win, so every name that resolves today resolves identically.

**Deliberately unchanged, with the source proving scope:** `slugifyName` itself (per-pair outputs pinned in `[expr]`; unique identifiers must stay byte-identical); app launch tools (`[expr]` — single fixed name already uniqued by app id); Archestra built-in seeding (`tool.ts` `seedArchestraTools` — curated registry names guarded by the partial unique index at `database/schemas/tool.ts:93`); agent delegation names (`shared/agents.ts:36` — derived from agent names, not MCP-server tools); proxy-sniffed tools (`tool.ts:2338` comment — names arrive from LLM traffic already as identifiers); the Apps run path (`mcp-server-gateway.utils.ts:60` lists lowercased parts and `mcp-client.ts:2999` `callToolForServer` forwards names verbatim — already lossy for any non-lowercase raw name, orthogonal to collisions); clone/reconcile code (`[expr]` — needs no change because suffixes are prefix-independent, verified by property test).
