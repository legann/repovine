## What was wrong

`ToolModel.slugifyName` (`platform/backend/src/models/tool.ts:80`) lowercases and strips disallowed characters, so distinct raw MCP tool names (e.g. `Get.User` vs `getuser`) can produce one identifier. The `tools` table's composite unique is NULLS-DISTINCT for regular MCP tools (`database/schemas/tool.ts:83-90`), so discovery persisted several rows sharing one `tools.name` — collapsed by every by-name lookup, gateway dedupe, and assignment mapping, hence "cannot be addressed individually".

## Where names become identifiers, and what changed

Per the module annotation, the codec is a per-pair transform and collision resolution belongs to the layer that sees a server's tool list as a set. That's what I implemented:

- **`models/tool.ts`** — added `ToolModel.slugifyNames(…)`: unique slugs pass through byte-identical; colliding slugs are ordered by raw name (order-independent across rediscoveries) — first keeps the bare slug, the rest get `-2`, `-3`, … suffixes that never take another tool's un-suffixed slug (so a real tool literally named `a_2` keeps its identifier). `slugifyName`/`unslugifyName` are untouched.
- **`models/tool.ts` `syncToolsForCatalog`** — matching is now exact-stored-name first, raw-name heuristic second (rename bridging only); each existing row can be claimed once, and the raw key is derived from the slugified `name` (suffix included) instead of `rawToolName`. Without this, a reinstall would let colliding siblings claim and rename each other's rows, breaking the identifiers the helper just made distinct. `rawToolName` is still accepted/passed (pinned by mocked call-shape tests) and documented as informational.
- **Batch call sites switched to the helper**: `routes/mcp-server.ts` (local-install async discovery ~line 761, remote-install sync discovery ~927), `archestra-mcp-server/mcp-servers.ts` (deploy-tool local ~1450 and remote ~1506), `services/mcp-reinstall.ts` (`syncToolsForServer` ~405).

## Deliberately left unchanged, with the proving source

- **`slugifyName`/`unslugifyName` codec** — annotation marks it a frozen stored/wire-identity boundary; its per-pair output is pinned by `tool.test.ts:43-150`, and changing the degenerate `server__` output would rename a lone empty-slug tool's working identifier.
- **Wire consumers** — `clients/mcp-client.ts` (`stripServerPrefix`/`resolveActualToolName`, lines 2118-2157), `routes/mcp-server-gateway.utils.ts:60`, `routes/mcp-server-proxy.ts:168`: annotation freezes them; suffixed names still carry the `server__` prefix so prefix stripping works, and the annotation states a non-round-tripping disambiguated slug is not a defect this task repairs.
- **LLM-proxy tool sniffing** — `routes/proxy/utils/tools.ts:96-105` passes wire `toolName` verbatim (no slugification); identical wire names are the same tool by definition.
- **App launch tools** — `services/apps/app-mcp-backing.ts:63-76`: one tool per app, name already globally unique via app-id suffix (comment at lines 68-71).
- **Clone provisioning** — `models/tool.ts` `cloneToolsAndPoliciesFromCatalog` (~line 879): derives names from stored source names, which are unique per catalog (comment at the call site); suffixes live in the tool part of the name, so they survive un/re-slugification, and first-install reconciliation (set-based, `mcp-server.ts:781-788`) corrects any leftovers.
- **Credential-validation discovery** — `routes/mcp-server.ts:1176` never persists tools (connection check only).

## Residual risk

- Suffix assignment for tools whose raw names are byte-identical in one `tools/list` (pathological duplicates) falls back to list order; their `-n` pairing can swap across rediscoveries — they are indistinguishable inputs, so no per-tool identity exists to preserve.
- A suffixed identifier does not resolve to an upstream raw name; such tools remain uncallable upstream exactly as colliding tools are today (explicitly out of scope per the module annotation — the wire is not extended).
- Existing DB rows from past collisions (duplicate same-name rows) converge on the next reinstall: the surviving row keeps the shared name, siblings get suffixed rows with fresh default policies.
