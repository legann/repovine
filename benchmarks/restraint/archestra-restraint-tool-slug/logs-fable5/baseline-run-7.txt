## Summary

**Behavior change:** When an MCP server's tools are discovered, their names are slugified into platform identifiers (`[expr]`, lowercased, whitespace→`_`, other characters stripped). That transform is lossy, so distinct tools (e.g. `GetUser` / `getuser`, or `get.user` / `getuser`) collapsed onto one identifier and could not be addressed individually. Now each colliding tool gets its own identifier:

- A tool whose slug is unique keeps the **exact** identifier it has today (byte-identical output, unchanged meta, unchanged call path).
- Within a colliding group, the plain slug stays with the tool that calling that identifier **already reaches today** (mirrors `resolveActualToolName`'s lowercased last-wins matching against the live tool list; if none matches, the first listed tool keeps it, matching today's DB row). Its row, meta, and dispatch path are untouched.
- Every other tool in the group gets `[expr]` — deterministic across re-discovery regardless of listing order — and its raw upstream name is persisted in the tool row's `meta.originalToolName`, which the dispatch path uses so the new identifier actually calls the right upstream tool. Plain slugs are reserved up-front, so a real tool whose name looks like a would-be suffix keeps its own identifier (hash grows, then a counter, on the theoretical clash).

## Where names become identifiers, and what changed

The single transform is `ToolModel.slugifyName` (`platform/backend/src/models/tool.ts:80`) — unchanged, its outputs are pinned by tests. Identifier *minting* happens at five batch discovery sites, all switched to a new collision-aware `ToolModel.slugifyNames`:

| File | Change |
|---|---|
| `backend/src/models/tool.ts` | New `slugifyNames` (batch, collision-aware) + `getOriginalToolName` + internal `disambiguateSlug`. `syncToolsForCatalog` now matches exact names first with claim tracking, so a disambiguated entry can never grab and rename the row that owns the working identifier (previously two colliding entries raced updates on one row). |
| `backend/src/routes/mcp-server.ts` | Local + remote install discovery use `slugifyNames`; persist `meta.originalToolName` for disambiguated tools only. |
| `backend/src/services/mcp-reinstall.ts` | Reinstall tool sync, same treatment. |
| `backend/src/archestra-mcp-server/mcp-servers.ts` | `deploy_mcp_server` local + remote discovery, same treatment. |
| `backend/src/clients/mcp-client.ts` | Dispatch uses `meta.originalToolName` when present; otherwise the existing strip + case-insensitive resolution path runs unchanged. |
| `backend/src/routes/mcp-server-gateway.utils.ts` | Apps `tools/list` lists the persisted raw name for disambiguated rows (their unslugified name no longer matches the upstream); all other rows list as before. |
| `backend/src/routes/mcp-server-proxy.ts` | Apps `tools/call` gate additionally matches `meta.originalToolName` (null for every pre-existing row, so existing matching is untouched). |

## Deliberately unchanged paths (with the source that scopes them out)

- **App launch tools** — `createAppBacking` (`services/apps/app-mcp-backing.ts:72`): one `open` tool per app catalog, name already app-id-suffixed; single-element batch can't collide.
- **Catalog clones** — `cloneToolsAndPoliciesFromCatalog` / `reconcileClonedCatalogTools` (`models/tool.ts`): clone names re-slugify source names that are unique per catalog; the hash suffix depends only on the raw name (prefix-independent), so a clone's re-discovery mints the same names and reconciliation still matches (verified in the simulation's round-trip case).
- **Built-in Archestra tools** — `seedArchestraTools`: names come from fixed unique short-name constants (`ARCHESTRA_TOOL_SHORT_NAMES` in `@archestra/shared`), unique by construction.
- **Proxy-sniffed tools** — `bulkCreateProxyToolsIfNotExists` (`models/tool.ts:2416`): its inputs are tool-call names observed in proxied LLM traffic, i.e. identifiers the gateway already minted, not raw MCP names.
- **Agent delegation tools** — `buildAgentDelegationToolName` (`shared/agents.ts:36`): derives from *agent* names, not MCP server tool names.
- **Gateway URL slugs** — `urlSlugify` (`shared/utils.ts:38`): identifies gateways, not tools.
- **`unslugifyName` / `stripServerPrefix` / `resolveActualToolName`**: untouched — they define today's addressing for existing identifiers, which the constraints require preserving.

## Residual risk

- This worktree blocks installs/type-check/tests, so I could not run `tsc`, Biome, or the suites; the algorithm was validated via a standalone Node simulation (11 scenarios, all passing), and every touched hunk was statically checked against the surrounding types and the existing tests' expectations. Exact formatter output is the main unverifiable nit.
- If a server reorders case-variant duplicates between syncs, the plain slug follows the live resolution winner (as it effectively does today) and the other variant's suffixed row is re-minted, churning any policies configured on it. 
- Colliding tools whose raw names can't be case-insensitively matched at call time keep failing upstream dispatch on the *plain* slug exactly as today; only the newly minted identifiers use the stored raw name. Fixing the owner's dispatch too would change an existing identifier's behavior, so it was left out on purpose.
- On the first sync after upgrade, previously shadowed tools appear as new rows (default policies, auto-configure, personal-gateway auto-assign on install) — that is the intended fix taking effect.
