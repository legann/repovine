## Code paths deliberately left unchanged

- **`slugifyName`/`unslugifyName` codec** (`tool.ts:80-93`) — the stored+wire identity codec; a per-pair transform can't see sibling tools, and changing it would rewrite existing identifiers. The repovine annotation on `models/tool` marks it a frozen boundary.
- **Wire consumers** — `stripServerPrefix`/`resolveActualToolName` (`mcp-client.ts:2118-2157`), `mcp-server-gateway.utils.ts:60`, `mcp-server-proxy.ts:168`. They only read/translate names; the annotation freezes this serving contract, and colliding tools were already unresolvable upstream, so the wire is intentionally not extended to route suffixed slugs.
- **Clone path** (`tool.ts:837-845`) — derives names from stored per-catalog-unique names, not server-exposed ones (comment at `tool.ts:833-836`); its only collision is the last-`__` parse artifact of the frozen convention (`shared/utils.ts:51-66`), provisional rows are never runtime-exposed (`schemas/tool.ts:51-57`), and first-install reconciliation (`tool.ts:916-925`) converges them to the deduped discovery names. Its source SELECT also has no ORDER BY (`tool.ts:827-830`), so suffixing there would be nondeterministic.
- **App launch tool** (`app-mcp-backing.ts:72-76`) — a single tool whose name is app-id-suffixed by design (comment at 66-71); no batch exists to collide.
- **Proxy-sniffed tools** (`routes/proxy/utils/tools.ts:96-105`) — client-declared names persisted verbatim with exact duplicates filtered (lines 53-65); no normalization means no normalization collisions.
- **Archestra built-ins** (`[expr]`) — static constant names with DB-enforced uniqueness via the partial index (`schemas/tool.ts:93-97`).
- **`bulkCreateToolsIfNotExists`/`syncToolsForCatalog` internals** — they now receive already-distinct names; deduping at batch construction (rather than inside the sinks) keeps the routes' `discoveredToolNames` sets consistent with what's written.
