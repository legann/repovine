## Summary

**Changed behavior.** Every MCP-server tool discovered in one batch now gets a distinct stored identifier. Identifiers come from `ToolModel.slugifyName(…)` (`platform/backend/src/models/tool.ts:80`), which lowercases `[expr]`, converts whitespace to `_`, and strips disallowed characters — so distinct raw names like `Get.User` / `getuser` collapsed to one identifier. The `tools` table doesn't prevent this either: its composite unique on `[expr]` is NULLS-DISTINCT and never fires for catalog tools (`database/schemas/tool.ts:89-91`), so colliding tools shared one `tools.name` and could not be addressed individually.

The fix is a new batch-aware `ToolModel.slugifyNames(…)`, used wherever a server's discovered tool list is written as a set:

- A name whose slug is unique in the batch keeps the **byte-identical** `slugifyName` output — no working identifier changes, including the degenerate lone `server__` (name strips to empty) case.
- Within a collision group, the plain slug stays with the tool it *already resolves to* on the wire: `resolveActualToolName` (`clients/mcp-client.ts`) matches the slug's tool part against lowercased live names with last-wins overwrite, so the last group member whose lowercased raw name survives slugification unchanged keeps the base (first member if none does). The rest get `-2`, `-3`, … suffixes, skipping any candidate that is another tool's base slug. Hyphen suffixes can never form a new `__`, so `parseFullToolName`'s last-`__` split (`shared/utils.ts:58`) is unaffected.

**Files changed** (identifier producers only):
- `platform/backend/src/models/tool.ts` — added `ToolModel.slugifyNames`; the existing codec is untouched.
- `platform/backend/src/routes/mcp-server.ts` — local async + remote sync install discovery (2 sites).
- `platform/backend/src/archestra-mcp-server/mcp-servers.ts` — local + remote deploy-tool discovery (2 sites).
- `platform/backend/src/services/mcp-reinstall.ts` — reinstall tool sync (1 site).

**Deliberately unchanged**, each with the source proving it out of scope:
- `slugifyName`/`unslugifyName` (`models/tool.ts:80-93`) and the wire consumers (`mcp-client.ts` `stripServerPrefix`/`resolveActualToolName`, `routes/mcp-server-gateway.utils.ts:60`, `routes/mcp-server-proxy.ts:168`): the module's boundary annotation states the per-pair codec and the serving/matching contract are frozen, and that distinctness "is a property of the layer that holds [a server's tools] together, not of this transform."
- `services/apps/app-mcp-backing.ts:73`: creates exactly one synthetic launch tool per app catalog (single `ToolModel.create`; its own comment shows the app-id suffix already prevents cross-app collisions) — a one-element set cannot collide.
- `cloneToolsAndPoliciesFromCatalog` (`models/tool.ts`, clone path): re-derives names from stored names its own comment documents as unique per catalog; distinct stored names (including suffixed ones) stay distinct after the prefix swap.
- Delegation-tool naming via shared `slugify` (`models/tool.ts`, `AGENT_TOOL_PREFIX` sites): derives from *agent* names, not MCP-server-exposed tools — outside the task statement.
- `createToolIfNotExists`: no production callers (the model's own TODO marks it test-only).

**Verification.** Ten collision/degenerate scenarios executed against the exact algorithm in a standalone script — all pass, including order-independence of the keeper and unique-slug preservation. This worktree blocks typecheck/tests (no node_modules), so compile verification is static; `strict` is on but `noUncheckedIndexedAccess` is not, so the indexed access types check out. repovine graph refreshed after the edits. No tests were added or modified.

**Residual risk.** Suffix *numbering* among multiple non-keeper members of a ≥3-way collision follows the server's list order, so a server that reorders its tool list could swap `-2`/`-3` between those (already unaddressable) tools; the keeper is order-independent. Suffixed identifiers don't round-trip to a raw upstream name, so gateway calls to them still fail upstream — deliberately not extended, per the frozen wire contract; the deliverable is distinct platform identity (row, assignment, policies, UI). On reinstall, a suffixed tool's row is recreated under the same stable name (raw-name matching can't recognize it), the same churn class colliding tools have today. The pre-existing unenforced 128-char cap gains 2 characters on suffixed names.
