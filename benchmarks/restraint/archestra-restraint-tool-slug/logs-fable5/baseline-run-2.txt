## Summary

MCP tool identifiers are now collision-free: when several tool names from one server collapse into the same slug (slugification lowercases, folds whitespace, and drops characters outside `[expr]`), each tool now gets its own identifier. Every identifier that is unambiguous today stays byte-identical, and the disambiguation is deterministic — it depends only on the set of raw names, not their listing order.

**Where tool names become identifiers.** The single transformation is `ToolModel.slugifyName` (`platform/backend/src/models/tool.ts:80`). Five discovery paths feed it batches of server-exposed names: local and remote install (`routes/mcp-server.ts:761`, `:927`), the `deploy_mcp_server` Archestra tool for local and remote (`archestra-mcp-server/mcp-servers.ts:1449`, `:1506`), and reinstall/resync (`services/mcp-reinstall.ts:406` → `ToolModel.syncToolsForCatalog`). At call time, `mcp-client.ts` maps the identifier back to the server's real tool name (`stripServerPrefix` + `resolveActualToolName`).

**The fix.** A new per-batch assignment (`assignUniqueToolSlugs` in `models/tool.ts`): a name whose slug nobody else shares keeps the exact `slugifyName` output; in a collision group, the member whose lowercased name *is* the slug — the tool today's identifier actually reaches — keeps it, and every other member gets a `[expr]` suffix (lengthened deterministically on the theoretical residual clash). Because the suffix derives from the raw name, install, reinstall, clone reconciliation, and call-time resolution all recompute identical identifiers.

**Files changed**
- `models/tool.ts` — shared `slugifyText`, the assignment core, new statics `slugifyNames` (raw name → identifier) and `toolNamesBySlug` (slug part → raw name); `syncToolsForCatalog` now disambiguates its batch via `rawToolName` and matches existing rows by the assigned name's raw part, so two colliding tools no longer rename the same row.
- `routes/mcp-server.ts`, `archestra-mcp-server/mcp-servers.ts` — the four install-discovery sites build names through `slugifyNames`.
- `clients/mcp-client.ts` — `resolveActualToolName` overlays the same per-batch slugs onto its name map, so suffixed (and previously character-stripped) identifiers resolve to the correct upstream tool; all previously-working lookups produce identical mappings.

**Deliberately unchanged, with proof**
- `services/mcp-reinstall.ts` — its call shape is pinned by `mcp-reinstall.test.ts:24-29` (mocks `ToolModel` with only `slugifyName`/`syncToolsForCatalog`) and `:1424-1435` (asserts exact per-tool names + `rawToolName`); disambiguation therefore lives inside `syncToolsForCatalog`.
- App launch tools (`services/apps/app-mcp-backing.ts:72-76`) — one fixed `open` tool whose prefix embeds `app.id.slice(…)`; unique by construction (comment at `:68-71`).
- Clone copying (`models/tool.ts` `cloneToolsAndPoliciesFromCatalog`) — consumes existing DB identifiers, not server names; converges via first-install reconciliation, and the raw-name-derived hash makes cloned suffixed names match discovery exactly.
- Proxy-sniffed tools (`routes/proxy/utils/tools.ts:96-105`) — names stored verbatim from LLM requests; no name→identifier transformation exists there.
- Agent delegation tools (`shared/agents.ts:36-38`) — built from platform agent names, not MCP-server tool names.
- Archestra built-ins — static names with uniqueness enforced by the `[expr]` type and the partial unique index (`database/schemas/tool.ts:93-97`).
- Apps run path (`routes/mcp-server-gateway.utils.ts:60`, `mcp-client.ts` `callToolForServer`) — lists/forwards upstream-native names verbatim; identifier construction is not involved.
