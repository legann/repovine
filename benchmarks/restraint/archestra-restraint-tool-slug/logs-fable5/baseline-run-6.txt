## What was broken

`ToolModel.slugifyName` (`platform/backend/src/models/tool.ts:80`) builds a tool's platform identifier as `[expr]` lowercased, whitespace→`_`, all other disallowed characters dropped. The transform is lossy, so distinct tool names on one server collapse into one identifier (`getUser`/`get.user` → `srv__getuser`; `Get User`/`get_user` → `srv__get_user`). Discovery then dedupes by name, leaving a single DB row for several upstream tools — only one (at most) is addressable.

## The fix

**Minting** — new batch-aware API in `models/tool.ts`: `ToolModel.slugifyNames(…)` on top of `ToolModel.disambiguateToolSlugs(…)`.
- A tool whose slug is unique in the batch keeps **byte-for-byte** today's `slugifyName` output (`slugifyName` itself is unchanged; it now delegates to a shared `slugifyToolNameText` helper producing identical bytes).
- In a colliding group, the single tool whose lowercased name equals the shared slug keeps it — that is the tool the identifier already routes to today via case-insensitive resolution, so its working identifier is preserved exactly. Every other member gets `[expr]`, lengthened deterministically on the (freak) clash with another slug. The suffix depends only on the raw name, so identifiers are stable across list order, re-discovery, and catalog renames. When zero or several members lowercase to the shared slug (pure case twins), routing today is list-order-dependent, so no one owns it and all get suffixes.

**Identifiers are minted in exactly five discovery sites, all switched to the batch API**: `routes/mcp-server.ts` (local install ~line 761, remote install ~line 927), `services/mcp-reinstall.ts` (`syncToolsForServer`, ~line 405), `archestra-mcp-server/mcp-servers.ts` (`discoverLocalMcpServerTools` ~1450, `discoverRemoteMcpServerTools` ~1506).

**Addressing** — `clients/mcp-client.ts` `resolveActualToolName` recomputes the same assignment from the live tool list and adds slug→raw-name entries to its resolution map, non-overwriting, so each suffixed identifier invokes its own upstream tool. Existing lowercase lookups (the path working identifiers use) are untouched.

**Stability across re-syncs** — `syncToolsForCatalog` now matches existing rows by exact identifier first, then raw name, then incoming slug, with claim tracking. Without this, suffixed rows would be deleted and recreated on every reinstall (losing policies/assignments), and colliding raw names would double-claim one row.

## Deliberately unchanged, with proof of scope

- **App launch tools** — single fixed-name tool with an app-id-suffixed prefix, unique by construction (`services/apps/app-mcp-backing.ts:66-76` and the comment there).
- **Agent delegation tools** — minted from agent names, not MCP server tool names (`shared/agents.ts:36-38`).
- **Archestra built-ins** — fixed compile-time short-name registry, no collisions possible (`shared/archestra-mcp-server.ts`, `ARCHESTRA_TOOL_SHORT_NAMES`).
- **Catalog clone re-prefixing** (`models/tool.ts` `cloneToolsAndPoliciesFromCatalog`) — re-prefixes already-unique identifiers; the suffix rides along verbatim and re-discovery reproduces it (hash input is the raw name only), so no change needed.
- **Apps run path** (`clients/mcp-client.ts:2999` `callToolForServer`, `routes/mcp-server-gateway.utils.ts:56-60`) — passes names to the upstream verbatim and already only works when slug == raw name (it can't call case-mangled names today either); suffixed tools are no worse off there, and adding per-call list-tools resolution would change a working path's behavior/latency.
- **Cross-server prefix collisions** (two catalogs whose names slug identically) — a different axis; fixing it would rename every tool of an affected server, violating "keep working identifiers" (`findByNameForAgent`'s `[expr]` at `models/tool.ts:494` marks the ambiguity boundary).
- **Proxy-sniffed tools** — names arrive already as client-chosen identifiers, no slugging (`createToolIfNotExists` path).
