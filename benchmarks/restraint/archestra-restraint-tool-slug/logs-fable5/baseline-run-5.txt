## Summary

**The problem and the fix.** Every MCP tool's platform identifier is produced by `ToolModel.slugifyName(…)` (`platform/backend/src/models/tool.ts:79`), which lowercases and strips disallowed characters. Distinct upstream names like `getUser`/`GetUser` or `get.user`/`getuser` collapsed to one identifier, so only one DB row was created and the tools could not be addressed individually. Now, discovery slugifies each server's tool list as a batch via a new `ToolModel.slugifyNames`: unique slugs stay byte-identical to today's output; within a colliding group, the tool whose raw name already equals its slug (i.e., its identifier worked verbatim) keeps the plain slug, and the rest get deterministic `_2`, `_3`… suffixes. Discovery also stores each tool's exact upstream name in `meta.rawToolName`, and dispatch uses it — so a suffixed identifier like `server__getuser_2` routes to upstream `get.user` even though the suffix is not recoverable by string surgery.

**Where names become identifiers (all updated to the batch helper):**
- `[expr]` — local (async) and remote (sync) install
- `services/mcp-reinstall.ts:405` — reinstall/sync (also used by the remote-reinstall route via `autoReinstallServer`)
- `[expr]` — `deploy_mcp_server` tool's local/remote discovery

**Files changed:**
- `models/tool.ts` — new `slugifyNames` + `rawToolNameFromMeta`; `syncToolsForCatalog` now matches existing rows by exact stored raw name first, persists `rawToolName` into meta, and lets each existing row be claimed by at most one incoming tool (previously, two colliding inputs could both rename the same row concurrently)
- `clients/mcp-client.ts` — dispatch prefers `meta.rawToolName` over prefix-stripping; `resolveActualToolName` matches exact names before the case-insensitive map (rows without stored raw names follow the exact legacy path)
- `routes/mcp-server.ts`, `services/mcp-reinstall.ts`, `archestra-mcp-server/mcp-servers.ts` — batch slugs + raw-name capture
- `routes/mcp-server-gateway.utils.ts`, `routes/mcp-server-proxy.ts` — Apps server-scoped `tools/list`/`tools/call` gate prefer the stored raw name, with the old `unslugifyName` behavior as fallback

**Deliberately unchanged, with sources:**
- `slugifyName` itself — untouched, so every non-colliding tool keeps its exact identifier (pinned by `models/tool.test.ts:43-127`).
- App launch tools — `services/apps/app-mcp-backing.ts:68-76` already suffixes the app id and each app catalog holds exactly that one tool; no batch, no collision.
- Archestra built-ins and delegation tools — curated constants and `[expr]` from agent names (`shared/agents.ts:36`), keyed by unique `delegateToAgentId` (`database/schemas/tool.ts` index); not MCP-server tool names.
- Proxy-sniffed tools — names arrive from client traffic already as identifiers; no conversion.
- Clone flow (`models/tool.ts` `cloneToolsAndPoliciesFromCatalog`) — re-slugifies already-unique per-catalog names (suffixes round-trip through `unslugifyName`), and clones copy `meta` wholesale, preserving stored raw names.
- Cross-catalog prefix collisions (two catalogs slugifying to the same prefix, deduped at `routes/mcp-gateway.utils.ts:1671`) — catalog naming, not tool naming.
- Frontend `parseFullToolName` consumers — display-only parsing of identifiers.

**Residual risk:** low. Existing rows have no `meta.rawToolName`, so they follow the byte-for-byte legacy code paths; the first post-patch discovery adds the raw name via the normal meta-update mechanism (identifier and tool ID unchanged, policies/assignments intact). The one accepted behavior change inside collision groups: pure case-twins (`getUser`/`GetUser`) had order-dependent, self-inconsistent binding before (row metadata from the first listed, dispatch to the last); they now bind deterministically to list order, and if a server reorders such twins across reinstalls the two identifiers swap while each row's policies stay with its actual tool. Meta JSON comparisons stay stable because the inserted key order (`_meta`, `annotations`, `rawToolName`) matches Postgres jsonb normalization.
