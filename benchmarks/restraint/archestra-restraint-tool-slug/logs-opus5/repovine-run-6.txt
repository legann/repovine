## Where tool names become identifiers

`ToolModel.slugifyName` (`platform/backend/src/models/tool.ts:82`) is the single transform. It lowercases, converts whitespace to `_`, and **deletes** every remaining character outside `[expr]` to satisfy the LLM-provider pattern. That deletion is lossy, so distinct raw names reduce to one slug — `get.user` and `get/user` both become `srv__getuser`, and a name made entirely of stripped characters (`[expr]`, CJK) becomes the bare `srv__`. Collided rows then collapse in `bulkCreateToolsIfNotExists`, which keys existing tools by `tool.name` (`[expr]`), so only one row survives and the tools stop being individually addressable.

## What changed

`slugifyName` itself is untouched. The fix goes where a server's tools are visible **as a set** — a per-pair transform cannot tell a lone `srv__` tool from several colliding on it.

| File | Change |
|---|---|
| `models/tool.ts` | New `slugifyNamesForServer(…)` beside the codec |
| `archestra-mcp-server/mcp-servers.ts` | Local + remote deploy discovery (2 sites) |
| `routes/mcp-server.ts` | Local + remote install discovery (2 sites) |
| `services/mcp-reinstall.ts` | Reinstall sync (1 site) |

The helper groups the batch by base slug: **count 1 → returned byte-for-byte**; only members of a colliding group get a suffix, an 8-hex SHA-256 of the raw tool name, so it is stable across discovery runs and independent of the order the server lists tools in. Already-unique slugs are reserved up front so a suffixed name can never claim one; identical raw names fall back to a counter.

I verified by extracting the real method bodies from source and exercising them: all-unique sets are preserved exactly, a lone empty-strip tool keeps its bare `srv__`, punctuation/empty-strip collisions and `__`-containing server names all resolve distinct, and output stays within `[expr]`.

## Residual risk

Disambiguated slugs don't round-trip through `unslugifyName` to a raw upstream name. Those tools were already unresolvable upstream, and the annotated contract scopes this out ("the wire is not extended to route it") — but it means collided tools become addressable and policy-governable without becoming *callable* upstream; full call-path support would need the frozen wire layer.

Separately, when an existing collapsed row is re-synced, `syncToolsForCatalog` matches on the raw name extracted from the stored slug (`getuser`) against the incoming `rawToolName` (`get.user`); that mismatch predates this change, but it now resolves as delete-plus-insert, so policies and agent assignments on the old collapsed row are lost as the single row splits into two.
