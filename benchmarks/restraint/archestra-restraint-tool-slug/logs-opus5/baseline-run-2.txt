## Where names become identifiers

`ToolModel.slugifyName(…)` — `platform/backend/src/models/tool.ts:81` — is the single chokepoint. Its output is stored as `tools.name`, which is exactly what the gateway lists and dispatches `tools/call` on (`routes/mcp-gateway.utils.ts:256`, `:350`). Every discovery path funnels through it: `[expr]`, `[expr]`, `services/mcp-reinstall.ts:406`, catalog clone at `models/tool.ts:864`, app launch tool at `services/apps/app-mcp-backing.ts:73`.

The defect: the sanitizer deletes every character outside `[expr]`, so a name written entirely in such characters (CJK, emoji, punctuation-only) sanitizes to nothing. All of them collapse onto `[expr]`, and `bulkCreateToolsIfNotExists` (`onConflictDoNothing`, tool.ts:792) keeps one row for the lot.

## Deliberately unchanged

1. **Case collapse** (`ListRepos` → `listrepos`) — pinned by `tool.test.ts:49-52`; `mcp-client.ts:2130-2132` documents case-insensitive resolution as intended. Both names are usable today.
2. **Whitespace collapse** (`list all repos` / `list_all_repos`) — `tool.test.ts:54-59` and `:85-91` pin both mappings.
3. **Dropped-character collapse** (`tool@name` → `toolname`) — `tool.test.ts:110-126` treats these as valid identifiers; each is usable on its own, so re-keying would change a working identifier. Only names sanitizing to *nothing* are unusable independent of siblings.
4. **Server-name portion** (a CJK-only catalog → `__tool`) — `stripServerPrefix` (`mcp-client.ts:2118-2126`) resolves those today and tools stay distinct within the server, so the identifiers work.
5. **App-call gate**, `routes/mcp-server-proxy.ts:165-171` — fail-closed exact match; normalizing there could attribute a call to a different tool's visibility/policy row.
6. **`callToolForServer`**, `mcp-client.ts:3009-3020` — forwards the caller's name verbatim through a per-call client (`withDirectServerClient`, `:2952`), with no `connectionKey` cache to hook into.
7. **`shared/utils.ts` `slugify()`** — agent/delegation and skill names (`[expr]`), not MCP-exposed tool names.
8. **Length cap** — the JSDoc claims `[expr]` but no truncation exists; adding it would create collisions and change working identifiers.
