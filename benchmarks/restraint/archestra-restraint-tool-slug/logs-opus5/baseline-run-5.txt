## What changed

**`platform/backend/src/models/tool.ts`** — `slugifyName` now slugifies the server and tool halves separately (identical output: every step preserves `__`, and a whitespace run can't span it). A tool name whose characters are all dropped by the transform — `"日本語"`, `[expr]`, `[expr]` — used to yield an empty segment, so every such tool on a server became the same bare `[expr]`; the `[expr]` unique index then kept only the first. Those now get `[expr]`, deterministic and stable across rediscovery. A genuinely empty tool name still yields `[expr]`, which `stripServerPrefix` depends on.

**`platform/backend/src/clients/mcp-client.ts`** — the remote-name resolution map now also keys each upstream tool by the segment `slugifyName` stores for it, added after the lowercase keys so exact matches still win. Without it a digest-named tool would be distinct but uncallable; it also fixes resolution for names lowercasing alone can't reproduce (`"List Repos"` stored as `list_repos`).

Change surface: new output **iff** `[expr]`. All other identifiers are byte-identical, including `[expr]` for an unsluggable *server* name.

## Deliberately left unchanged

- **Server half of the identifier.** `slugifyName(…)` → `__search` still addresses correctly: `stripServerPrefix` (`mcp-client.ts:2118-2126`) strips the `slugifyName(…)` = `"__"` prefix and recovers `search`. It's a working identifier, so constraint 1 forbids touching it.
- **Agent delegation tools** (`tool.ts:2462`, `2603`). Created with `[expr]` (`tool.ts:2463-2482`) and looked up by `delegateToAgentId` (`tool.ts:2445-2449`) — no MCP server exposes them.
- **Built-in `[expr]` tools.** Short names are hardcoded constants in `shared/archestra-mcp-server.ts` (`[expr]`), never an MCP server's tool name.
- **App launch tool** (`services/apps/app-mcp-backing.ts:72-76`). Tool half is the constant `[expr]` (`types/app.ts:20`), and the comment at `app-mcp-backing.ts:63-70` documents that the `[expr]` suffix already guarantees distinctness.
- **Synthetic resource tools** (`makeSyntheticResourceToolName`, `mcp-client.ts:3766`). Derived from `resource.uri` in the `listResources` fallback branch (`mcp-client.ts:2863-2884`), reached only when a server has no `tools/list`; output is always non-empty (`[expr]`), so the digest never applies. Two URIs can still sanitize to one name — a resource-URI path, not a tool name, so out of scope.
- **`syncToolsForCatalog` reinstall matching** (`tool.ts:2069-2135`). Matches stored rows by the segment after `__` against the incoming `rawToolName`; for a digest tool those differ, so reinstall recreates rather than updates the row. Identical to today (the stored segment is empty then), and the same pre-existing mismatch already hits any name whose slug differs from its lowercase form (`"List Repos"` → stored `list_repos` vs raw `list repos`).
- **MCP Apps pass-through** (`callToolForServer`, `mcp-client.ts:2999-3014`) forwards the app-supplied name verbatim. An app sees `unslugifyName(…)` from `mcp-server-gateway.utils.ts:60`, i.e. the digest, so it still can't reach upstream — unchanged from today, where it saw an empty string.
- **`urlSlugify`** (`shared/utils.ts:38`) produces gateway URL slugs, not tool identifiers.
