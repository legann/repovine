## Where tool names become identifiers

`ToolModel.slugifyName(…)` — `platform/backend/src/models/tool.ts:95` — is the **only** function that turns an MCP server's tool name into the platform identifier. Every row-creating path funnels through it:

| Caller | Path |
|---|---|
| `routes/mcp-server.ts:762`, `:924` | local / remote install discovery |
| `archestra-mcp-server/mcp-servers.ts:1451`, `:1506` | deploy-time discovery via the built-in MCP tool |
| `services/mcp-reinstall.ts:406` | reinstall / refresh → `syncToolsForCatalog` |
| `models/tool.ts:865` | catalog clone (re-mints via `unslugifyName`) |
| `services/apps/app-mcp-backing.ts:73` | app launch tool (fixed `APP_LAUNCH_TOOL_NAME`) |
| `clients/mcp-client.ts:2120` | `stripServerPrefix` — prefix only, empty tool name |

The collision: the `[expr]` filter drops characters, so `get.user` and `getuser` both mint `srv__getuser`, and any two non-Latin names both mint `srv__`. Tools are addressed by name alone (`ToolModel.findByNameForAgent`, `tool.ts:502`, `limit(…)`, no ordering), so the colliding tools are indistinguishable and all but one are unreachable.

## Changed

`platform/backend/src/models/tool.ts` only (+58/−4): `slugifyName` now slugifies the server and tool parts separately (provably identical output, since the `__` separator prevents whitespace runs from spanning them) and appends an 8-hex djb2 hash of the folded tool name **only when the charset filter actually dropped something**. Three module-private helpers at the file's helper section: `foldToolNamePart`, `dropRejectedToolNameChars`, `shortToolNameHash`. No tests touched, no schema change.

## Deliberately unchanged

| Path | Proof it's out of scope |
|---|---|
| Server-name half of the slug | `[expr]` pin stripped server slugs verbatim (`server_production`, `my-server`); `mcp-client.ts:2120` rebuilds the prefix with `slugifyName(…)` at call time |
| Case folding (`ListRepos`/`listrepos`) | `tool.test.ts:49` pins lowercasing; `McpClient.resolveActualToolName` (`mcp-client.ts:2134`) resolves upstream names case-insensitively by design |
| Whitespace folding | `[expr]` pin whitespace → underscore |
| Empty tool name → `server__` | `tool.test.ts:105`, and `stripServerPrefix` depends on that exact shape |
| `[expr]` | mints names from *agent* names (`tool.ts:2489`, `:2630`; `delegation.ts:111`), not from a name an MCP server exposes |
| `makeSyntheticResourceToolName` (`mcp-client.ts:3756`) | mints from a resource *URI* in the no-`tools/list` fallback (`:2863`); its output is already charset-clean, so it passes through unchanged |
| A2A skill ids (`a2a.ts:145`, `a2a-v2.ts:130`) | agent name → skill id, not a tool identifier |
| `syncToolsForCatalog` raw-name match (`tool.ts:2160`) | keys on the raw upstream name; for mangled names it misses identically before and after (`tool@name` vs `toolname` → vs `toolname_8c3ca544`) |

## Residual risk

- **Existing mangled rows re-mint.** A stored `srv__getuser` for upstream `get.user` becomes `srv__getuser_fb02d7d2` at the next discovery; its guardrail policies and agent assignments do not follow (sync's raw-name match already missed for these names, so they already churned). No *working* tool moves — the pinned tests plus a cross-product of clean names show zero drift.
- **Still not invocable upstream.** A mangled-name tool now has its own identity but the call path (`resolveActualToolName`) still can't map the slug back to `get.user`; that needs the raw name persisted, which is a schema change beyond "distinct identifier".
- **32-bit hash collision** between two mangled names in one catalog degrades to today's shared-slug behavior, no corruption.
- **Length:** the suffix adds ≤9 chars; this tree enforces no length cap anywhere, so a near-128-char name could cross the provider limit.
