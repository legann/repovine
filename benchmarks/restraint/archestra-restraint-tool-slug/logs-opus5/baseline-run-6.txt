## 1. Where tool names become identifiers

`ToolModel.slugifyName(…)` — `platform/backend/src/models/tool.ts:87` — is the single funnel. Every MCP-discovered tool row gets its `tools.name` from it:

| Call site | Path |
|---|---|
| `[expr]` | install-time discovery (local, remote) |
| `services/mcp-reinstall.ts:406` | reinstall/sync |
| `[expr]` | deploy-time discovery (local, remote) |
| `services/apps/app-mcp-backing.ts:73` | app launch tool |
| `models/tool.ts:846` | clone-catalog copy (re-slugifies `unslugifyName(…)`) |

The old body concatenated `[expr]`, lowercased, collapsed whitespace to `_`, then **deleted** every character outside `[expr]`. A tool name written entirely in deleted characters (CJK, Cyrillic, emoji, punctuation-only) left nothing behind, so every such tool of a server landed on the identical name `[expr]`. The tools table's composite unique constraint is NULLS-DISTINCT for MCP tools (`database/schemas/tool.ts:83-88`), so those rows co-exist as indistinguishable duplicates and every by-name lookup collapses them.

## 2. Change

**`platform/backend/src/models/tool.ts`** (only file touched):

- `slugifyName` now slugifies the server half and the tool half separately, then joins with `__`. This is byte-identical to the old whole-string form — lowercasing and character removal are per-character, and `__` contains no whitespace, so no whitespace run can span the boundary.
- New bottom-of-file helpers: `slugifySegment` (the old normalization, verbatim) and `slugifyToolSegment`, which falls back to `[expr]` **only** when the tool half slugifies to empty for a non-empty raw name. The digest keys off the tool name alone, so it is stable across re-discovery and across catalog renames.
- An empty `toolName` still returns `[expr]` unchanged — `McpClient.stripServerPrefix` (`clients/mcp-client.ts:2120`) calls `slugifyName(…)` to build the bare prefix, and `tool.test.ts:105` pins it.

## Summary

`ToolModel.slugifyName` gives a tool whose name consists entirely of characters LLM providers forbid a deterministic `[expr]` identifier instead of collapsing it onto the shared `[expr]`. Every tool name that already slugified to something keeps its exact identifier, including the empty-tool-name prefix form. One file changed: `platform/backend/src/models/tool.ts`.

Residual risk:

- **Legacy rows aren't migrated.** A `[expr]` row written before this change survives until the next reinstall, where `syncToolsForCatalog` orphans and deletes it; its assignment transfer matches by raw name and won't match the new digest names, so policies and assignments on that one shared row are lost. Those tools were unaddressable to begin with; a data migration is a separate call.
- **Digests aren't reversible.** A digest-named tool still can't be invoked upstream (`resolveActualToolName` can't map `[expr]` back to `搜索`), and MCP Apps calling by raw name (`mcp-server-proxy.ts:167`) won't match it — unchanged from today, where the name resolved to `""`. It is now individually listable, assignable, and policy-able.
- **Partial-strip collisions remain**: `検索_search` and `日本語_search` both still slugify to `_search`. Separating them would change identifiers that are usable today, which the constraint rules out.
- Digest collision probability is 48-bit — negligible at per-server tool counts.
