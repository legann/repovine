## Where names become identifiers

`ToolModel.slugifyName` (`platform/backend/src/models/tool.ts:80`) is the codec: it concatenates `[expr]`, lowercases, and **strips every character outside `[expr]`**. That strip is lossy, so distinct MCP names collapse onto one slug (`get.data`/`getdata`, or any two names that retain no characters at all, both yielding the bare `server__`). Combined with the `[expr]` unique constraint (`database/schemas/tool.ts:83`) and `onConflictDoNothing()` (`models/tool.ts:768`), the loser is silently dropped — never addressable.

It is called at five discovery→row sites, all of which now go through the new helper:

| Site | Path |
|---|---|
| Local install discovery | `routes/mcp-server.ts:762` |
| Remote install discovery | `routes/mcp-server.ts:928` |
| Local deploy discovery | `archestra-mcp-server/mcp-servers.ts:1451` |
| Remote deploy discovery | `archestra-mcp-server/mcp-servers.ts:1507` |
| Reinstall sync | `services/mcp-reinstall.ts:406` |

## Files changed

- **`services/mcp-tool-names.ts`** (new) — `slugifyToolNamesForServer(…)` slugifies a server's tools as a set. First claim wins verbatim; a colliding tool gets the first free `_2`, `_3`, … variant, skipping any slug a sibling claims outright.
- The five call sites above — mechanical swap from per-tool `slugifyName` to the batch helper.

`slugifyName`/`unslugifyName` are untouched, per the graph annotation flagging them as the stored-identity codec and its invariant that distinctness "is a property of the layer that holds them together, not of this transform."

One subtlety worth flagging: `syncToolsForCatalog` matches rows by raw name, and `mcp-reinstall.test.ts:1424` pins `rawToolName` exactly. Passing the raw MCP name alongside a disambiguated slug would make a sibling's raw name match the first tool's row and trigger a rename into a taken name — a unique-constraint 500 on reinstall. So the helper returns `rawToolName` = the stored raw part **only for tools that actually collided**; every non-colliding tool still passes its raw MCP name byte-for-byte, leaving that matcher's behavior unchanged.

The pinned reinstall assertion still holds (distinct names → helper is an identity function).

**Residual risk.** Which member of a colliding pair keeps the base slug follows the server's `tools/list` order; a server that reorders a colliding pair between installs could swap which row (and thus which policies) each tool binds to. Non-colliding tools are unaffected. Also, a disambiguated slug intentionally does not round-trip to a raw upstream name — consistent with the annotation's note that colliding tools are already unresolvable upstream and the wire is not extended to route them; they become individually addressable and policy-governable, and calls still resolve upstream by the server's live tool list.
