## Where tool names become identifiers

`ToolModel.slugifyName(…)` (`platform/backend/src/models/tool.ts:81`) is the single conversion point — it produces the `[expr]` string stored in `tools.name`, which is what the gateway advertises to the LLM and what tool calls are addressed by. Callers:

| Path | Site |
|---|---|
| Local install discovery | `backend/src/routes/mcp-server.ts:762` |
| Remote install discovery | `backend/src/routes/mcp-server.ts:924` |
| Deploy / remote discovery (MCP tools) | `backend/src/archestra-mcp-server/mcp-servers.ts:1451`, `:1506` |
| Reinstall sync | `backend/src/services/mcp-reinstall.ts:406` |
| Catalog clone (re-slug of unslugified name) | `backend/src/models/tool.ts:870` |
| App launch tool (constant ASCII tool half) | `backend/src/services/apps/app-mcp-backing.ts:73` |
| Prefix reconstruction for call routing | `backend/src/clients/mcp-client.ts:2120` |

**The bug:** slugification drops every character outside `[expr]`. A name written in another script keeps none of its identifying characters — `查询天气` and `发送邮件` both become `weather__`, `получить_данные` and `отправить_письмо` both become `weather___`. The gateway's `dedupeToolsByName` (`backend/src/routes/mcp-gateway.utils.ts:1668`) then exposes only one of them.

## Files changed

- **`platform/backend/src/models/tool.ts`** — `slugifyName` now slugifies the two halves separately; new `ToolModel.slugifyToolName` (`:100`) returns the plain slug when it keeps an alphanumeric **or** when the name lost no character, and otherwise a 12-hex-char SHA-256 digest of the lowercased name (`weather__tool_22cf3c76aa53`). Shared `slugifySegment` + constants at the file bottom (`:3092`). Also `syncToolsForCatalog` now falls back to matching an existing row by that canonical slug (`:2171`), so a reinstall updates the digest row instead of inserting a duplicate each time.
- **`platform/backend/src/clients/mcp-client.ts`** — `resolveActualToolName` indexes the upstream tool list by slug as a secondary key (`:2152`), so a digest identifier resolves back to the server's real name at call time. Exact case-insensitive matches still win.

## Summary

Tools whose names slugify away now get a deterministic per-name digest identifier instead of collapsing onto one shared string; every name that keeps an alphanumeric character, and every name that loses no character, slugifies byte-for-byte as before — verified by replaying the existing `slugifyName` expectations and a 936-pair old/new differential: 0 changed outputs among names with an identifying slug, collisions down from 408 to 96 (all of them the pre-existing ASCII cases above), all outputs matching `[expr]`, re-slugification idempotent, and `slugifyName(…)` still `[expr]`.

Residual risk:

- Digest names are opaque to the model; meaning comes from the description. Collision space is 48 bits per server.
- Rows already stored under a collapsed name aren't renamed. A reinstall sync creates the digest row and prunes the orphan (`tool.ts:2247-2331`), but assignment transfer is keyed by raw name and won't match an empty one, so assignments come from the install-time auto-assign rather than a transfer. On the fresh-install path there's no prune, so a stale `[expr]` row can linger until a reinstall.
- The Apps run path still can't reach a digest-named tool upstream — it now lists `[expr]` where it previously listed an empty name, so no regression, but no fix either; fixing it needs a `tools/list` resolution inside `callToolForServer`, adding a round trip to every app tool call.
- No tests added or modified, per the constraints. The suite couldn't be run here — this worktree has no `node_modules` and installs/builds/tests are blocked — so verification was static plus the offline differential described above.
