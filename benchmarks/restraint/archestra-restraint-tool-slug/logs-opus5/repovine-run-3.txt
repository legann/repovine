## Where tool names become identifiers

`ToolModel.slugifyName(…)` — `platform/backend/src/models/tool.ts:80`. It joins `server__tool`, lowercases, maps whitespace to `_`, then **deletes every character outside `[expr]`**. That deletion is the collision source: `"get data"` and `"get-data"` both yield `server__get_data`, and any name built only of stripped characters yields the bare `server__`.

Call sites: `[expr]`, `[expr]`, `services/mcp-reinstall.ts:406`, `services/apps/app-mcp-backing.ts:73`, `models/tool.ts:840`. Every batch path funnels into two set-level writers — `bulkCreateToolsIfNotExists` (`tool.ts:678`) and `syncToolsForCatalog` (`tool.ts:2008`).

Why colliding tools were unaddressable: the composite `unique(…)` (`database/schemas/tool.ts:83`) is NULLS-DISTINCT for catalog tools, so both rows persist under one name and collapse at the gateway's dedupe-by-name — the mechanism `app-mcp-backing.ts:64-70` names explicitly. In the Archestra built-in catalog the partial index `tools_archestra_catalog_name_uidx` (`schemas/tool.ts:93`) instead makes `onConflictDoNothing` drop the loser. Same symptom either way.

## Files changed

- **`platform/backend/src/models/tool.ts`** — new private `disambiguateToolNames`, applied at the head of both batch writers. First tool to reach a slug keeps it byte-for-byte; later collisions take the lowest free numeric suffix. All natural names are reserved up front so a generated suffix never steals an identifier another tool owns. A batch with no collisions returns the identical array.
- **`platform/backend/src/routes/mcp-server.ts`** — clone reconciliation compares against persisted names (`createdTools`) rather than pre-disambiguation names. Without this, `reconcileClonedCatalogTools` (`tool.ts:948-953`) deletes by exact stored name and would drop a provisional row for a disambiguated tool the server does expose.

## Residual risk

- Suffix assignment follows batch order, i.e. the server's `tools/list` order. If a server reorders colliding tools between discoveries, which one holds the bare slug can flip. Only affects tools that are unaddressable today.
- In `syncToolsForCatalog`, matching stays on raw name, so the first reinstall after this change may swap which row keeps the bare name within a colliding pair. Policies and assignments follow the row, not the name.
- Suffixed slugs don't round-trip through `unslugifyName` to an upstream raw name. Intentional — the wire is unchanged. Previously-colliding tools are now distinct rows, individually visible and policy-governable; invoking them still depends on the gateway's live-list match.
- Degenerate case: N tools all stripping to empty give `server__`, `server___2`, … — valid identifiers, awkward to read.
- Pre-existing and untouched: `syncToolsForCatalog` keys existing rows on the raw name extracted from the stored slug, so a raw name containing whitespace (`"Get Data"` → key `"get data"` vs stored-derived `"get_data"`) misses its own row. That's a raw-name *matching* defect, not identifier generation, and fixing it would alter the rename-preserves-ID contract.
