## Where tool names become identifiers

`ToolModel.slugifyName(…)` — `platform/backend/src/models/tool.ts:81` — is the single mint. Every discovery path funnels through it:

| Path | Call site |
|---|---|
| Local server deploy | `archestra-mcp-server/mcp-servers.ts:1451` |
| Remote server deploy | `archestra-mcp-server/mcp-servers.ts:1506` |
| Server install / tool refresh | `routes/mcp-server.ts:762`, `:924` |
| Catalog reinstall (sync) | `services/mcp-reinstall.ts:406` |
| App MCP backing | `services/apps/app-mcp-backing.ts:73` |
| Clone catalog | `models/tool.ts:865` |

It lowercased the joined `server__tool`, mapped whitespace to `_`, and dropped everything outside `[expr]`. A tool name made entirely of stripped characters — CJK, Cyrillic, emoji, pure punctuation — sanitized to nothing, so every such tool on a server landed on the same name `[expr]`.

## Files changed

- **`platform/backend/src/models/tool.ts`** — split the sanitizer into a shared `sanitizeNameChars` helper and a new `ToolModel.slugifyToolNamePart`. When a non-empty name sanitizes away, the tool half becomes `[expr]`. An empty name still yields the empty half, because `slugifyName(…)` is how `stripServerPrefix` builds a bare server prefix (`clients/mcp-client.ts:2120`). Also keyed `syncToolsForCatalog`'s raw-name map through the same function on both sides, so a reinstall matches these rows instead of orphan-deleting them.
- **`platform/backend/src/clients/mcp-client.ts`** — `resolveActualToolName` indexes each upstream tool under its slugified form as well, so a digest identifier resolves back to the real upstream name. Exact-casing keys are inserted first and never displaced.

A parity sweep over 112 server/tool combinations shows every identifier that changed previously ended in a bare `[expr]` with a non-empty source name; all others are byte-identical. No tests added or modified.

## Residual risk

- 64 bits of digest, no uniqueness guard beyond the DB unique index on `[expr]` — collision is theoretical, not impossible.
- `slugifyName` still enforces no 128-char cap (it never did). The digest adds 21 characters, so a server slug over ~107 chars could now cross the provider limit where the bare `[expr]` fit. Truncating would change existing identifiers, so I left it.
- These tools now surface in the UI as `[expr]` rather than a blank short name — distinct and addressable, but not human-readable. The description still carries the tool's own text.
- The sync-map change also repairs matching for raw names containing whitespace or punctuation, which were orphan-deleted and recreated on each reinstall. Their rows, policies, and assignments now survive a resync. No existing `syncToolsForCatalog` test covers that shape — all fixture names there are already slug-shaped.
- MCP Apps `tools/call` still cannot reach these tools upstream, unchanged from today.
