## Summary

**Where tool names become identifiers:** `ToolModel.slugifyName(…)` (`platform/backend/src/models/tool.ts:80-85`) is the sole codec — it lowercases the name and *deletes* any character outside `[expr]` (no replacement). Deleting rather than replacing means distinct raw names can collapse to the same string (e.g. `"Get.User"` and `"GetUser"` both → `"getuser"`). The `tools` table has no enforced uniqueness on `[expr]` for ordinary installed servers — the composite `unique()` in `database/schemas/tool.ts:83-88` includes `agentId`/`delegateToAgentId`, which are NULL for these rows, and standard Postgres NULLS-DISTINCT semantics mean it never fires (confirmed: no `[expr]` anywhere in `database/schemas/`; the file's own comment at line 89 says as much). The only enforced unique index is scoped to the built-in Archestra catalog only. So two colliding tools could both land in the DB under the same name, and every downstream lookup keyed by that name (`bulkCreateToolsIfNotExists`, `syncToolsForCatalog`, the MCP-apps proxy's tool lookup) could only resolve one of them.

**Fix:** added `[expr]` to `platform/shared/utils.ts` — first occurrence of a slug is returned untouched; each later collision gets `-2`, `-3`, ... , skipping any candidate that matches *another* tool's own slug (natural or already assigned), so disambiguating one pair can never rename an unrelated tool. Wired into the 5 places that turn one server's full discovered-tool list into DB rows, each still calling the byte-for-byte-unchanged `ToolModel.slugifyName` once per tool, now piped through `dedupeSlugs`:

| File | Function |
|---|---|
| `platform/backend/src/routes/mcp-server.ts` | local/K8s install path + remote install path (2 sites) |
| `platform/backend/src/archestra-mcp-server/mcp-servers.ts` | `discoverLocalMcpServerTools` + `discoverRemoteMcpServerTools` |
| `platform/backend/src/services/mcp-reinstall.ts` | `syncToolsForServer` |
| `platform/shared/utils.ts` | new `dedupeSlugs` helper |

`models/tool.ts` ends with **zero net diff** — I initially added a method there, but reverted it: `mcp-reinstall.test.ts` mocks `@/models`'s `ToolModel` down to `[expr]`, so any new `[expr]` method would throw `TypeError` across ~10 tests in that file. Moving the dedup into a plain function in the already-unmocked `@archestra/shared` package (verified against both existing `@archestra/shared` mocks in the suite — neither touches this export) sidesteps that while leaving the stored-identity codec untouched, per the repovine boundary advisory on that file.

**Deliberately left unchanged:**
- `models/tool.ts:840` clone flow — re-slugifies already-unique source names under a new prefix; can't reintroduce a collision since inputs are pairwise-distinct by construction.
