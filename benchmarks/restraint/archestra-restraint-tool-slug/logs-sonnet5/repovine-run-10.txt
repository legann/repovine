## What I changed

Added `platform/backend/src/services/mcp-tool-name-collisions.ts` — `slugifyDiscoveredToolNames(…)`. It calls the unmodified `ToolModel.slugifyName` per name, and only when a batch produces a duplicate, appends a deterministic `[expr]` suffix to every member of that colliding group. Non-colliding names pass through byte-identical to today. The hash is a pure function of the raw name (not position), so it's stable across re-discovery regardless of list ordering.

Wired it into the 5 call sites that turn a freshly-discovered tool list into identifiers:

| File | Site |
|---|---|
| `archestra-mcp-server/mcp-servers.ts` | `discoverLocalMcpServerTools`, `discoverRemoteMcpServerTools` |
| `routes/mcp-server.ts` | local-server async post-deploy discovery; remote/sync install discovery |
| `services/mcp-reinstall.ts` | `syncToolsForServer` (restart/reinstall reconciliation) |

`ToolModel.slugifyName`/`unslugifyName` themselves are untouched — repovine's own boundary annotation on `tool.ts` flags them as the frozen stored-identity codec, and every existing unit test in `tool.test.ts` pins their exact output. The fix lives entirely on the write path, one call-site edit each.

## Deliberately left unchanged

- **`cloneToolsAndPoliciesFromCatalog`** (`models/tool.ts:836`) — remaps an already-distinct set of names through a new prefix (`slugifyName(…)`); prefix substitution can't reintroduce a collision among names that were already distinct.
- **`app-mcp-backing.ts:72`** — always slugifies exactly one constant name (`APP_LAUNCH_TOOL_NAME`), never a batch; already has its own collision guard (app-id suffix in the prefix, per the comment there).
- **`mcp-client.ts:2120` (`stripServerPrefix`)** — calls `slugifyName(…)` only to measure the prefix length, never a tool name.
- **`bulkCreateProxyToolsIfNotExists`** (`models/tool.ts:2344`) — proxy-sniffed tools never call `slugifyName`; the observed name is stored as-is.

## Residual risk

- **Invocation fidelity for disambiguated tools is best-effort**, same as it already was. `mcp-client.ts`'s `resolveActualToolName` (line 2134) only reconciles case, not stripped whitespace/symbols; `mcp-server-gateway.utils.ts`'s Apps path (`callToolForServer`, line 2999) passes the name straight through with no reconciliation. Names needing disambiguation are exactly the names that already had this weakness, so this change doesn't make invocation worse — it makes the tool addressable/assignable/policy-able where it previously wasn't, but calling it still rides the same pre-existing best-effort path.
- **A shrinking collision group can rename the survivor.** If a colliding sibling later disappears from the upstream server on a resync, the survivor's identifier reverts from suffixed to bare (disambiguation is recomputed per batch, not persisted as sticky state). `syncToolsForCatalog`'s orphan-to-survivor transfer logic matches by re-deriving "raw name" from the last `__` segment of the persisted name, which could miss in that narrow case — an edge case of an already-acknowledged best-effort reconciliation (see its own comment about "previous buggy reinstalls").
- **No backfill for already-collided rows** in existing installations — this fixes identifier minting going forward, not a data migration.
