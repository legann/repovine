## Residual risk

**Invocation isn't collision-aware.** A disambiguated tool (`prefix__foo-2`) gets its own row, policies, and its own `tools/list` entry, but calling it strips the prefix and looks up `foo-2` against the live remote tool list, which has no literal tool named `foo-2` — the call would fail rather than reach the second tool. Making that round-trip fully correct requires resolving both colliding remote names in the same order used at creation time; I judged that too invasive to do blind (no test execution available in this worktree) against the actual likelihood of a server exposing two tools differing only in case or in characters the slugifier strips.

**Ordering assumption.** Disambiguation is positional — it assumes the MCP server returns `tools/list` in a stable order across calls (an assumption this codebase already makes elsewhere for tool identity). If a server reorders two colliding tools between install and a later reinstall, the `-2` suffix could attach to the other sibling.
