## The fix

Added `[expr]` in `platform/shared/utils.ts`, alongside the existing `slugify`/`parseFullToolName` helpers. Given a batch of already-computed slugs from one MCP server's tool list: a slug appearing once is returned untouched; for a colliding group, the first occurrence keeps the plain slug and each subsequent one gets a `_2`, `_3`, … suffix (skipping any suffix a sibling already claimed).

Every place that turns a live `tools/list` result into DB rows now does:
[code excerpt removed — 3 line(s)]
and indexes `[expr]` instead of slugifying inline per tool. `ToolModel.slugifyName` itself is byte-for-byte unchanged, so any tool whose name doesn't collide with a sibling in that discovery batch gets exactly the identifier it gets today.

**Files touched:**

| File | Change |
|---|---|
| `platform/shared/utils.ts` | new `disambiguateToolNameSlugs` |
| `platform/backend/src/routes/mcp-server.ts` | both install paths (local async discovery + remote sync) route through it |
| `platform/backend/src/services/mcp-reinstall.ts` | `syncToolsForServer` routes through it |
| `platform/backend/src/archestra-mcp-server/mcp-servers.ts` | `discoverLocalMcpServerTools` + `discoverRemoteMcpServerTools` route through it |

I deliberately did **not** add this as a `ToolModel` method. `services/mcp-reinstall.test.ts:12-31` replaces `ToolModel` wholesale with `[expr]` and asserts exact payloads built from that mock (e.g. `mcp-reinstall.test.ts:1424` expects `name: [value]`). A new `ToolModel.slugifyNames` would be `undefined` on that hand-built mock and throw. Keeping disambiguation as a standalone function that only consumes `slugifyName`'s already-mocked output — with every call site still calling `ToolModel.slugifyName` per tool exactly as before — leaves that test (and any other `ToolModel` spy/mock) untouched.

## Left unchanged, and why

- **`ToolModel.slugifyName`/`unslugifyName`** (`tool.ts:79-92`) — changing the per-name algorithm itself (e.g. substituting instead of deleting stripped characters) would also change identifiers for tools that don't collide today, violating "don't change identifiers that already work."
- **`ToolModel.cloneToolsAndPoliciesFromCatalog`** (`tool.ts:819`, comment at 879-882) — explicitly relies on "the source's tool names are unique within its catalog"; this fix is what now guarantees that invariant at creation time, so re-deriving one clone name at a time stays correct.
- **`app-mcp-backing.ts:72-76`** — creates exactly one tool per app; no batch to disambiguate. It already avoids cross-app collision by suffixing the prefix with the app id (comment at lines 68-71).
- **`mcp-client.ts` `stripServerPrefix`/`resolveActualToolName`** (~2118-2157) — recovers the true upstream name at call time via prefix-stripping plus a case-insensitive live lookup. It already can't restore characters `slugifyName` strips (a single, non-colliding tool named `"list.repos"` was already unreachable through its own stored slug before this change), and its own `nameMap` already collapses live tools that differ only by case. Both are pre-existing round-trip gaps, orthogonal to identifier generation.
- **`syncToolsForCatalog`'s raw-name matching** (`tool.ts:2007`+, comment ~2062-2063 "we lowercase raw names for matching") — matches incoming tools to existing rows by lowercased raw name across reinstalls, by design treating a pure case change as a rename of the same tool, not two tools. Redesigning that reconciliation is a separate, larger change with its own existing test coverage.

## Residual risk

- If two tools differing **only by case** are simultaneously live on one server, this fix makes them distinct on first discovery, but a later reinstall/resync of that same server could re-merge them via `syncToolsForCatalog`'s lowercase raw-name join (not collision-aware). Symbol/whitespace/Unicode collisions — the primary, test-evidenced case — aren't affected, since that join key preserves symbols.
- Pre-existing duplicate rows created under the old algorithm before this change aren't backfilled; only tools discovered/synced going forward are guaranteed unique. A real backfill is a data migration (precedent: `0285_dedup_archestra_builtin_tools_by_short_name.sql`), which is out of scope for a tool-name-handling implementation change.
- End-to-end remote invocation of a disambiguated tool still depends on `mcp-client.ts`'s existing name-recovery, which was already lossy for symbol-containing names regardless of collision.
- No tests were added or modified, per the task constraint; verification here is static (traced call sites, DB constraints, and existing test mocks) since `pnpm type-check`/`pnpm test` are blocked in this sandbox (no `node_modules`).
