## Summary of changed behavior

A monitor may now target at most 100 locations. `validateMonitor` gained an opt-in check (`enforceMaxLocations`, default `false`): when enabled and the normalized, deduplicated `locations` array exceeds `[expr]`, it returns `valid: false` with reason "Monitor targets too many locations" and details stating the count, the limit, and the fix. The three create/update write paths opt in, so the request is rejected as a 400 (REST routes) or a per-monitor failure entry (project push). Locations are counted after normalization, which resolves public+private locations and dedupes by id (`getMonitorLocations`, `common_fields.ts:268`), so the limit applies to the effective location set that would be persisted.

All paths below are under `x-pack/solutions/observability/plugins/synthetics`.
