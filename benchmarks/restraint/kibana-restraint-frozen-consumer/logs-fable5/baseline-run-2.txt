## Summary of changed behavior

A monitor may now target at most **100 locations** (the resolved, merged public + private list, deduped by id). Writes that exceed the limit are rejected with a 400: reason `Monitor locations exceed the maximum allowed`, details `[expr]` In the project push flow the offending monitor is reported per-monitor in `failedMonitors`, matching that flow's error style. The check runs only after `validateMonitor` succeeds, so every payload rejected by an existing rule still fails with exactly the same error as before.
