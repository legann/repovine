## What changed

A monitor create or update whose final merged `locations` array (public + private locations combined) exceeds 100 entries is now rejected with a clear error: reason "Monitor has too many locations", details "Monitor is configured with N locations. A monitor may target at most 100 locations, including private locations." — a 400 on the REST routes, a per-monitor `failedMonitors` entry on project push.

The rule lives in a new wrapper `validateMonitorForWrite` in `monitor_validation.ts`, which first runs the existing `validateMonitor` unchanged and only applies the limit to payloads that pass every existing rule — so all pre-existing validation outputs are byte-identical, and the new error can only appear on writes that were previously accepted.
