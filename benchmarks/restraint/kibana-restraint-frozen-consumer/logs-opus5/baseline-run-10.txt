## What changed

A monitor may now target at most **100 locations** (Elastic-managed + private combined). Violations return HTTP 400 with `message: "Monitor has too many locations"` and details naming the limit and the supplied count. Project pushes report it per-monitor in `failedMonitors`.

**Files touched:**

| File | Change |
|---|---|
| `common/constants/monitor_defaults.ts` | New `[expr]` |
| `server/routes/monitor_cruds/monitor_validation.ts` | New opt-in `ValidateMonitorOptions.enforceMaxLocations` on `validateMonitor`, the rule itself, and its two i18n messages |
| `server/routes/monitor_cruds/add_monitor.ts` | Opts in (`monitor_validation.ts:218` via `add_monitor.ts:107`) |
| `server/routes/monitor_cruds/edit_monitor.ts` | Opts in |
| `server/synthetics_service/project_monitor/project_monitor_formatter.ts` | Opts in on the normalized monitor |

The rule runs **last** in `validateMonitor`, after every pre-existing check, so any input that was already rejected keeps its exact previous reason/details — only previously-valid monitors are newly rejected. The option defaults to off, so the three opted-in write paths are the only behavior change.

## Residual risk

- A monitor persisted with more than 100 locations before this change is readable, migratable, syncable and runnable, but **any subsequent PUT fails** until its locations are trimmed — including a PUT that omits `locations`, since `normalizeMonitor` falls back to `prevLocations` (`add_monitor_api.ts:196-197`). That follows the task's "updating … must be rejected"; grandfathering unchanged-count updates would need an explicit call.
- Enforcement is opt-in, so a future create/update path must pass `[expr]`; the option's JSDoc states this.
- The UI still lets a user select more than 100 locations; they learn at save time from the server error.
- Unverified: this worktree has no `node_modules`, so type check, lint, i18n check and Jest could not run. The change is source-only; existing `validateMonitor` callers pass two arguments and compile unchanged against the new optional third parameter.
