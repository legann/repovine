## Residual risk

- **Unverified by execution.** This worktree has no `node_modules`, so type check, lint, i18n check, and Jest are unavailable — I verified statically instead. The third parameter is optional with a default, so all 21 existing two-arg call sites in `monitor_validation.test.ts` still compile and keep `[expr]`; both new i18n IDs are unique repo-wide; `values` keys match the message placeholders.
- **Editing a grandfathered monitor.** A monitor persisted with >100 locations now fails any update through `[expr]`, even a name-only edit, because `mergeSourceMonitor` carries the previous locations forward into the validated object. That follows the deliverable ("updating a monitor with more than 100 locations must be rejected") but means such monitors must shed locations before any other field can change. Reads, migrations, resets, and test-now are unaffected.
- **Forward-compatibility.** Because enforcement is opt-in, a future create/update path added without the flag would silently skip the rule. The `ValidateMonitorOptions` JSDoc states which callers must set it.
