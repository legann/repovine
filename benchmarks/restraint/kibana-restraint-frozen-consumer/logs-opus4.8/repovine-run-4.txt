## 1. What was implemented

A new synthetics validation rule: a monitor may target **at most 100 locations** (`[expr]` is rejected). The rule is a **separate** validator (`validateMonitorLocationsLimit`) invoked only on the create/update write paths — deliberately **not** folded into the shared `validateMonitor`.

**Why not `validateMonitor`:** `validateMonitor` is a frozen contract. The released `8.8.0` saved-object migration calls it on already-persisted docs and **throws** on invalid:

- `saved_objects/migrations/monitors/8.8.0.ts:119-124` → `validateMonitor(…)` inside `omitZipUrlFields`
- `8.8.0.ts:127-131` → `[expr]`

Adding a location cap there would retroactively fail any persisted monitor with >100 locations during upgrade — which the task forbids. The repovine annotation on that module flags this exact boundary ("any edit here — including one behind a flag or default — couples the change to that frozen consumer"). So enforcement lives on the write consumers instead.
