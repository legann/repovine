## Summary

Added a "max 100 locations per monitor" rule enforced on synthetics monitor **create** and **update** writes. A monitor whose resolved location list exceeds 100 is rejected with a clear 400 error; existing rules and already-persisted monitors are untouched.

### Changed behavior
- **Create** (`POST /api/synthetics/monitors`) and **update** (`[expr]`) now reject payloads whose normalized `locations` array (public + private, combined) has length > 100.
- Error surfaced through the handlers' existing `[expr]` branch: message `"Monitor has too many locations"`, details `[expr]`
- The count is checked on the **resolved** `ConfigKey.LOCATIONS` array (after `normalizeMonitor`), so it reflects what would actually be persisted — identical semantics on both create and update.
