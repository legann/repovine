## Summary of changed behavior

Synthetics monitors now reject **create/update writes** targeting more than **100 locations** (`MAX_MONITOR_LOCATIONS`), where the count is `monitorFields.locations.length` — the same merged, de-duplicated public+private set (`getMonitorLocations` → `uniqBy(…)`) that the existing "at least one location" rule already checks. The rejection returns a validation error: reason *"Monitor location limit exceeded"*, details *"A monitor can target at most 100 locations, but N were provided…"*.

The rule is a new, gated check inside `validateMonitor`, controlled by an **opt-in** `checkLocationsLimit` option (default `false`). It's enabled only on the three persistence write paths. Every existing rule is untouched, and every current 2-arg caller keeps identical behavior (limit inert).
