## Summary

Added a "≤ 100 locations per monitor" rule to synthetics monitor validation. It lives at the single server-side validation chokepoint (`validateMonitor`), so every create/update write inherits it, and it is opt-out only for the saved-object migration that re-validates already-persisted monitors.

### Changed behavior
A monitor whose `locations` array exceeds 100 entries is now rejected with `valid: false`, reason **"Monitor has too many locations"**, and a detail string naming the actual count and the limit. Any monitor with ≤ 100 locations behaves exactly as before (byte-identical result).
