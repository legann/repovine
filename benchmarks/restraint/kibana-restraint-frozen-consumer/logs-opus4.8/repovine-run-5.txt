## Summary

A monitor may now target at most **100 locations**. Create/update writes exceeding the cap are rejected with a clear validation error; already-persisted monitors are never re-checked.

The key constraint was a trap: the natural home for this rule, `validateMonitor`, is a **frozen contract**. Its repovine annotation (and the 8.8.0 migration's) shows it is reused unchanged inside the released `8.8.0` saved-object migration, which throws when it returns invalid (`omitZipUrlFields`). Adding the cap there would retroactively reject persisted >100-location monitors at load/migration time. So the rule lives in a new sibling helper invoked only from the write paths — `validateMonitor` is untouched.
